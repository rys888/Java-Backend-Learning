
后端面试最重要的是 **Undo Log、Redo Log 和 Binlog**。

| **日志类型**           | **所属层次**       | **主要作用**     |
| ------------------ | -------------- | ------------ |
| **Undo Log（回滚日志）** | InnoDB 存储引擎层   | 事务回滚、实现 MVCC |
| **Redo Log（重做日志）** | InnoDB 存储引擎层   | 保证事务持久性，崩溃恢复 |
| **Binlog（归档日志）**   | MySQL Server 层 | 数据恢复、主从复制    |

**① Undo Log：记录修改前的数据版本**

假设执行：

```sql
UPDATE user SET balance = 500 WHERE id = 1;
```

原来的 `balance = 1000`。

Undo Log 会保存用于恢复旧数据版本的信息。

作用：

- **事务回滚**：如果事务执行失败，可以撤销修改。
- **MVCC**：配合 Read View，让其他事务能够读取符合可见性规则的旧版本。


**② Redo Log：记录数据页的修改**

当执行 UPDATE 时，InnoDB 通常先修改 Buffer Pool 中的数据页，并按照 WAL 机制先持久化相关 Redo Log，再在之后将脏页刷入磁盘。

如果 MySQL 突然崩溃，可以通过 Redo Log 恢复已提交事务中尚未写入数据文件的修改。

**核心作用：保证事务的持久性（Durability）。**



**③ Binlog：记录数据库的数据变更**

Binlog 由 MySQL Server 层维护，记录数据库的数据变更事件。

主要作用：

- **主从复制**：主库通过 Binlog 将数据变更同步给从库。
- **数据恢复**：结合数据库备份进行指定时间点恢复。

### Q：

MySQL 常见的日志有 Undo Log、Redo Log、Binlog。

Undo Log 主要用于事务回滚和 MVCC；Redo Log 主要用于崩溃恢复，保证事务的持久性；Binlog 主要用于主从复制和数据恢复。

另外，Undo Log 和 Redo Log 属于 InnoDB 存储引擎层，而 Binlog 属于 MySQL Server 层。

**Undo Log 负责撤销，Redo Log 负责重做，Binlog 负责记录变更用于复制和恢复。**
