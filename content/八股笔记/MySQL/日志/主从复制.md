
[[#Q：]]

**MySQL 主从复制，就是将主数据库（主库）的数据变更同步到其他数据库（从库），使主库和从库的数据尽可能保持一致。**

### **① 举个例子**

假设有两台 MySQL 服务器：

- **主库（Master）**：负责 INSERT、UPDATE、DELETE 等写操作。
- **从库（Replica）**：同步主库的数据，通常负责 SELECT 查询。

当主库执行：

```sql
UPDATE user SET balance = 500 WHERE id = 1;
```

主从复制的过程：

```text
主库（Master）
    │
    │ ① 执行 UPDATE
    ▼
记录 Binlog
    │
    │ ② 从库获取 Binlog
    ▼
从库（Replica）
    │
    │ ③ 重放数据变更
    ▼
从库数据更新为 balance = 500
```

### **② 为什么需要主从复制？**

主要有三个作用：

1. **读写分离**：主库负责写，从库负责读，减轻主库的查询压力。
2. **提高可用性**：主库发生故障时，可以将符合条件的从库提升为新主库。
3. **数据备份**：可以在从库上执行备份，减少对主库的影响。

### **③ 主从复制有什么问题？**

**主从延迟。**

例如：

```text
主库 UPDATE balance = 500
           ↓
主库已经更新成功
           ↓
从库还没来得及同步
           ↓
用户查询从库，得到旧数据 1000
```

因为 MySQL 主从复制通常采用异步方式，所以主库和从库的数据不一定时刻完全一致。

### Q：

MySQL 主从复制是指将主库的数据变更同步到从库，使多个数据库之间的数据保持一致。

其核心原理是主库通过 Binlog 记录数据变更，从库获取并重放这些变更，实现数据同步。

主从复制主要用于读写分离、提高系统可用性以及辅助数据备份，但由于通常采用异步复制，所以可能存在主从延迟的问题。



**主库负责写入，Binlog 负责传递变更，从库负责同步数据，主要用于读写分离和提高可用性。**
