
**MySQL 发生死锁的根本原因是：多个事务互相持有对方需要的锁，并且都在等待对方释放锁，最终形成循环等待。**

### **一、MySQL 为什么会发生死锁？**

假设有一张用户表：

```sql
CREATE TABLE user (
    id INT PRIMARY KEY,
    balance INT
);
```

其中存在两条记录：

```text
id = 1
id = 2
```

现在两个事务同时执行。

**事务 A：**

```sql
BEGIN;

UPDATE user SET balance = 100 WHERE id = 1;
-- 锁住 id = 1

UPDATE user SET balance = 200 WHERE id = 2;
-- 等待事务 B 释放 id = 2 的锁
```

**事务 B：**

```sql
BEGIN;

UPDATE user SET balance = 300 WHERE id = 2;
-- 锁住 id = 2

UPDATE user SET balance = 400 WHERE id = 1;
-- 等待事务 A 释放 id = 1 的锁
```

假设执行顺序如下：

```text
事务 A                         事务 B
   │                              │
   ▼                              ▼
锁住 id = 1                  锁住 id = 2
   │                              │
   ▼                              ▼
尝试锁住 id = 2              尝试锁住 id = 1
   │                              │
   ▼                              ▼
等待事务 B                    等待事务 A
   │                              │
   └──────── 相互等待 ────────────┘
                 │
                 ▼
                死锁
```

**事务 A 等待事务 B，事务 B 又等待事务 A，谁都无法继续执行。**

这就是死锁。

---

### **二、MySQL 如何处理死锁？**

InnoDB 默认启用死锁检测机制。

当检测到事务之间形成循环等待时，InnoDB 通常会：

1. 检测到死锁。
2. 选择一个事务作为牺牲者，将其回滚。
3. 释放该事务持有的锁。
4. 让另一个事务继续执行。

例如：

```text
事务 A 等待事务 B
        ↑        │
        │        ↓
事务 B 等待事务 A
        │
        ▼
InnoDB 检测到死锁
        │
        ▼
回滚事务 B
        │
        ▼
释放 id = 2 的锁
        │
        ▼
事务 A 继续执行
```

被回滚的事务通常会收到：

```text
Deadlock found when trying to get lock;
try restarting transaction
```

因此，**MySQL 能够检测并解除死锁，但不能保证业务代码永远不会发生死锁。**

### **三、如何避免 MySQL 死锁？⭐⭐⭐⭐⭐**

常见的优化方式有：

**① 保持一致的加锁顺序（最重要）**

例如，所有事务都按照主键从小到大的顺序更新：

```sql
UPDATE user SET balance = 100 WHERE id = 1;
UPDATE user SET balance = 200 WHERE id = 2;
```

避免一个事务先锁 `id=1`，另一个事务先锁 `id=2`。

**② 尽量缩短事务执行时间**

事务持有锁的时间越长，其他事务发生锁竞争的概率通常越高。

因此，避免在事务中执行耗时的网络请求、复杂计算等操作。

**③ 合理使用索引**

因为 InnoDB 的行锁锁定的是索引记录。

如果 SQL 没有使用合适的索引，可能扫描并锁定大量记录，扩大锁竞争范围。

**④ 对死锁异常进行有限重试**

即使经过优化，也无法保证完全消除死锁。

实际开发中可以对死锁导致的事务失败进行有限次数重试，并确保重试操作满足业务幂等要求。

### **四、面试怎么回答？⭐⭐⭐⭐⭐**

MySQL 发生死锁的主要原因是多个事务在并发执行过程中，互相持有对方需要的锁，并且形成循环等待。

例如事务 A 先锁住记录 1，再尝试修改记录 2；而事务 B 先锁住记录 2，再尝试修改记录 1。此时两个事务互相等待，就会产生死锁。

InnoDB 默认具有死锁检测机制，检测到死锁后会选择一个事务进行回滚，释放它持有的锁，让其他事务继续执行。

在实际开发中，可以通过**统一加锁顺序、缩短事务执行时间、合理使用索引以及死锁失败重试**等方式降低死锁发生的概率。

**一句话记忆：死锁的本质是循环等待，解决思路是减少锁竞争、统一加锁顺序，并在发生死锁时回滚重试。**
