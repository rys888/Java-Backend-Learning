InnoDB 的锁是 MySQL 面试中的高频考点，主要可以从 **锁的粒度、锁的模式、锁定范围** 三个角度理解。

其中最重要的是：**共享锁、排他锁、意向锁、记录锁、间隙锁和临键锁。**

## **一、InnoDB 有哪些锁？**

### **1. 按锁的粒度分类**

|**锁类型**|**含义**|
|---|---|
|行级锁|锁住索引记录，允许较高的并发|
|表级锁|锁住整张表或在表级声明加锁意图|

InnoDB 支持行级锁，也存在表级锁机制。

**需要注意：InnoDB 的行锁实际上是加在索引记录上的。**

例如：

```sql
SELECT * FROM user WHERE id = 10 FOR UPDATE;
```

如果 `id` 是主键，并且记录存在，通常会对对应的索引记录加排他记录锁。

---

### **2. 按锁的模式分类**

主要有四种：

|**锁类型**|**英文**|**作用**|
|---|---|---|
|共享锁|S Lock|允许多个事务读取同一数据|
|排他锁|X Lock|防止其他事务对同一数据进行冲突的加锁读或修改|
|意向共享锁|IS Lock|表示事务准备对表中的某些行加共享锁|
|意向排他锁|IX Lock|表示事务准备对表中的某些行加排他锁|

**① 共享锁（S 锁）**

```sql
SELECT * FROM user WHERE id = 10 FOR SHARE;
```

多个事务可以同时持有同一记录的共享锁，但其他事务不能同时获得该记录的排他锁。

**② 排他锁（X 锁）**

```sql
SELECT * FROM user WHERE id = 10 FOR UPDATE;
```

排他锁与其他事务针对同一记录的共享锁、排他锁互斥。

**③ 意向锁（IS、IX）**

意向锁是表级锁，用来表示事务准备对表中的某些行加什么类型的锁。

例如：

```sql
UPDATE user SET age = 20 WHERE id = 10;
```

InnoDB 通常会：

1. 在表上获取 IX 意向排他锁。
2. 对需要修改的索引记录获取 X 锁。

**意向锁主要用于协调表级锁与行级锁，不是用来直接锁住某一行数据的。**

---

## **二、按锁定范围分类（面试重点）**

InnoDB 中最重要的三种行级锁定方式是：

**Record Lock、Gap Lock、Next-Key Lock。**

假设某个索引中存在以下数据：

```text
10    20    30    40
```

### **1. 记录锁（Record Lock）**

**记录锁只锁住某一条索引记录。**

例如：

```sql
SELECT * FROM user WHERE id = 20 FOR UPDATE;
```

如果 `id` 是主键，并且记录存在：

```text
10    20    30    40
      🔒
```

只锁住 `id = 20` 对应的索引记录。

其他事务不能对该记录执行冲突的加锁操作。

### **2. 间隙锁（Gap Lock）**

**间隙锁锁住索引记录之间的间隙，主要用于阻止其他事务向该间隙插入数据。**

例如：

```text
10        20        30        40
     🔒
   (10,20)
```

如果事务持有 `(10,20)` 的间隙锁，那么其他事务尝试插入 `id = 15` 时，就可能被阻塞。

需要注意：

- 间隙锁主要限制插入。
- 间隙锁本身不锁住已有记录。
- InnoDB 的间隙锁之间可以兼容，不是简单的互斥关系。

间隙锁常用于 RR 隔离级别下的范围加锁，防止其他事务在锁定范围内插入新记录。

### **3. 临键锁（Next-Key Lock）**

**临键锁 = 记录锁 + 前面的间隙锁。**

例如：

```text
10        20        30        40
     └─────🔒
      (10,20]
```

它既锁住：

- `(10,20)` 之间的间隙。
- `id = 20` 这条索引记录。

因此，Next-Key Lock 可以防止其他事务修改被锁住的记录，也能阻止其他事务向相应间隙插入数据。

在 InnoDB 的 RR 隔离级别下，范围加锁查询通常会使用 Next-Key Lock。

例如：

```sql
SELECT *
FROM user
WHERE id > 10 AND id < 30
FOR UPDATE;
```

实际锁住哪些索引记录和间隙，还取决于索引、执行计划和边界条件，不能简单认为只锁住 SQL 中写出的区间。

---

## **三、还有哪些锁？**

除了上面几种，还有：

|**锁类型**|**作用**|
|---|---|
|插入意向锁（Insert Intention Lock）|插入记录前，在目标间隙上申请的一种特殊间隙锁|
|AUTO-INC 锁|用于协调自增值分配|
|元数据锁（MDL）|保护表结构元数据，协调 DDL 和 DML|

其中，**插入意向锁**比较容易被追问。

例如两个事务：

```sql
-- 事务 A
INSERT INTO user(id) VALUES (15);

-- 事务 B
INSERT INTO user(id) VALUES (18);
```

假设二者都准备向 `(10,20)` 这个间隙插入数据。

由于插入的位置不同，如果没有其他冲突锁阻碍，它们通常可以并发插入。

因此，**插入意向锁不是说同一个间隙只能有一个事务插入。**

## **四、面试官可能追问：RR 和 RC 下的锁有什么区别？**

这是非常重要的一点。

|**对比**|**RC（读已提交）**|**RR（可重复读）**|
|---|---|---|
|普通 SELECT|通常为不加锁的快照读|通常为不加锁的快照读|
|UPDATE / DELETE|对相关记录加锁|对相关记录加锁|
|Gap Lock|通常禁用，保留外键检查、重复键检查等例外|范围加锁时可能使用|
|Next-Key Lock|通常不用于普通搜索和索引扫描|范围加锁时常见|
|防止幻读|不提供与 RR 相同的防护|MVCC 快照读与加锁读机制共同发挥作用|

特别注意：

**RR 并不是所有 SQL 都加 Next-Key Lock。**

例如：

```sql
SELECT *
FROM user
WHERE id = 10
FOR UPDATE;
```

如果 `id` 是唯一索引，并且记录存在，通常只需要记录锁，不需要额外加间隙锁。

## **五、面试怎么回答？**

InnoDB 的锁可以从多个维度分类。

首先，按照锁的粒度，可以分为行级锁和表级锁。

按照锁的模式，可以分为共享锁和排他锁。共享锁允许多个事务同时持有，而排他锁与其他事务对同一记录的共享锁和排他锁互斥。此外还有表级的意向共享锁和意向排他锁，用于协调表锁和行锁。

按照锁定范围，主要有三种：记录锁、间隙锁和临键锁。

记录锁用于锁住某条索引记录；间隙锁用于锁住索引记录之间的间隙，防止其他事务插入数据；临键锁则是记录锁和间隙锁的组合，既能锁住记录，也能限制间隙插入。

在 InnoDB 的 RR 隔离级别下，范围加锁查询通常会使用临键锁，防止其他事务向锁定范围插入新记录。

此外，InnoDB 还存在插入意向锁和 AUTO-INC 锁等机制。

**需要注意，InnoDB 的行锁是基于索引实现的，实际加锁范围与 SQL 使用的索引和执行计划密切相关。**
