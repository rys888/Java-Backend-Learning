
[[#Q]]

**InnoDB 的行锁，本质上锁的是索引记录，而不是直接锁住物理意义上的一整行数据。**

举个例子：

假设有一张用户表：

```sql
CREATE TABLE user (
    id INT PRIMARY KEY,
    name VARCHAR(50),
    age INT,
    INDEX idx_age(age)
);
```

### **① 通过主键查询**

```sql
SELECT * FROM user WHERE id = 10 FOR UPDATE;
```

因为 `id` 是主键，InnoDB 会通过**聚簇索引**找到 `id = 10` 的记录，并对相应索引记录加锁。

### **② 通过普通索引查询**

```sql
SELECT * FROM user WHERE age = 20 FOR UPDATE;
```

因为 `age` 存在二级索引，InnoDB 可以通过 `idx_age` 找到符合条件的记录。

此时通常会锁定：

- 二级索引中匹配的索引记录。
- 对应的聚簇索引记录。

具体锁定范围还与事务隔离级别、查询条件有关。

### **③ 如果没有使用索引呢？**

```sql
SELECT * FROM user WHERE name = 'Eason' FOR UPDATE;
```

假设 `name` 没有索引，优化器选择全表扫描。

InnoDB 就需要扫描聚簇索引，并对扫描过程中涉及的记录加锁。

**在默认 RR 隔离级别下，可能锁住大量记录及相关间隙，效果接近锁住整张表。**

但要注意，这并不意味着 InnoDB 自动把行锁升级成了表锁。

---

### Q

InnoDB 的行锁本质上是加在索引记录上的，而不是直接加在物理数据行上。

如果通过主键查询，就会锁定聚簇索引中的相关记录；如果通过二级索引查询，通常还需要锁定对应的聚簇索引记录。

如果查询没有使用合适的索引，可能需要扫描并锁定大量索引记录，导致锁定范围扩大，严重影响并发性能。

因此，**SQL 是否使用索引以及使用什么索引，不仅影响查询性能，还会影响 InnoDB 的加锁范围。**

**InnoDB 行锁锁的是索引记录，索引决定查找路径，也会影响加锁范围。**
