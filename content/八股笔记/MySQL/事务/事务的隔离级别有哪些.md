
MySQL 事务有 **4 种隔离级别**，分别是：

1. **READ UNCOMMITTED（读未提交）**
2. **READ COMMITTED（读已提交）**
3. **REPEATABLE READ（可重复读）**
4. **SERIALIZABLE（串行化）**

其中，**InnoDB 默认使用 REPEATABLE READ（可重复读）**。

## **一、先理解三个并发问题**

假设事务 A 和事务 B 同时操作数据库。

|**并发问题**|**含义**|
|---|---|
|**脏读**|事务 A 读取到了事务 B 尚未提交的数据|
|**不可重复读**|事务 A 两次读取同一条记录，结果不同|
|**幻读**|事务 A 两次按照相同条件查询，发现符合条件的记录数量或集合发生变化|

### **1. 脏读**

```text
事务 A                      事务 B
   │                           │
   │                      修改余额 1000 → 500
   │                           │
读取余额 = 500                  │
   │                           │
   │                        ROLLBACK
   │                           │
   ▼                           ▼
读到了最终被回滚的数据
```

事务 A 读取到了事务 B 尚未提交的数据，这就是脏读。

### **2. 不可重复读**

```text
事务 A                      事务 B
   │                           │
读取余额 = 1000                 │
   │                           │
   │                      修改余额为 500
   │                           │
   │                        COMMIT
   │                           │
再次读取余额 = 500              │
   │                           │
   ▼                           ▼
同一事务两次读取结果不同
```

**不可重复读主要关注同一条记录的数据发生变化。**

### **3. 幻读**

```text
事务 A                      事务 B
   │                           │
查询 age > 20                  │
返回 10 条记录                  │
   │                           │
   │                      INSERT 一条 age=25
   │                           │
   │                         COMMIT
   │                           │
再次查询 age > 20               │
返回 11 条记录                  │
   │                           │
   ▼                           ▼
符合条件的记录集合发生变化
```

**幻读主要关注符合查询条件的记录集合发生变化，典型情况是其他事务插入或删除记录。**

## **二、MySQL 的四种事务隔离级别 ⭐⭐⭐⭐⭐**

### **1. READ UNCOMMITTED（读未提交）**

**一个事务可以读取其他事务尚未提交的数据。**

例如：

```sql
-- 事务 B
BEGIN;
UPDATE account SET balance = 500 WHERE id = 1;
-- 尚未提交
```

此时事务 A：

```sql
SELECT balance FROM account WHERE id = 1;
```

可能读取到 `500`。

即使事务 B 最后回滚，事务 A 也已经读取到了错误的中间数据。

因此，读未提交可能出现：

- 脏读
- 不可重复读
- 幻读

这是隔离程度最低的级别。

### **2. READ COMMITTED（读已提交）**

**一个事务只能读取其他事务已经提交的数据。**

例如：

```text
事务 A                      事务 B
   │                           │
读取余额 = 1000                 │
   │                      修改余额为 500
   │                           │
再次读取 = 1000                 │
   │                           │
   │                         COMMIT
   │                           │
再次读取 = 500                  │
```

事务 B 没有提交时，事务 A 不会读取到它的修改。

但是事务 B 一旦提交，事务 A 后续查询就可能看到新数据。

因此：

- 解决脏读。
- 仍可能发生不可重复读。
- 仍可能发生幻读。

**实现原理：**

在 InnoDB 中，READ COMMITTED 的普通一致性读通常会在**每条 SELECT 语句开始时创建新的 Read View**。

因此，同一个事务中的两次 SELECT 可能看到不同的数据版本。

### **3. REPEATABLE READ（可重复读）⭐⭐⭐⭐⭐**

**在同一个事务中，多次普通一致性读能够看到一致的数据快照。**

这是 **MySQL InnoDB 的默认事务隔离级别**。

例如：

```text
事务 A                      事务 B
   │                           │
读取余额 = 1000                 │
   │                           │
   │                      修改余额为 500
   │                           │
   │                         COMMIT
   │                           │
再次读取余额 = 1000             │
   │                           │
   ▼                           ▼
两次读取结果一致
```

即使事务 B 已经提交，事务 A 的普通快照读仍然可以读取之前的数据版本。

**实现原理：MVCC + 锁机制。**

其中：

**① MVCC**

InnoDB 在 REPEATABLE READ 隔离级别下，通常在事务第一次执行普通一致性读时创建 Read View，并在后续一致性读中复用。

因此，同一个事务中的普通 SELECT 可以读取一致的数据快照。

**② 锁机制**

对于 `SELECT ... FOR UPDATE`、`UPDATE`、`DELETE` 等当前读操作，InnoDB 会使用锁机制。

在特定范围查询场景下，可以通过 Next-Key Lock（临键锁）等机制防止其他事务向锁定范围插入数据。

**注意：InnoDB 的可重复读能够在常见场景下避免幻读，但不能简单理解为所有情况下都绝对不会出现幻读。**

例如，在同一个事务中混合使用快照读和当前读，仍然可能观察到不同的记录集合。

### **4. SERIALIZABLE（串行化）**

**隔离级别最高，通过更严格的锁机制，使并发事务的执行效果符合串行执行的要求。**

例如：

```text
事务 A                      事务 B
   │                           │
读取某条记录                    │
   │                           │
   │                      尝试修改该记录
   │                           │
   │                         等待
   │                           │
事务 A 提交                     │
   │                           │
   │                      继续执行修改
```

在 InnoDB 中，串行化隔离级别会对普通查询施加更严格的并发控制，例如在显式事务中将普通 SELECT 转换为共享锁定读。

它能够避免脏读、不可重复读和幻读。

但是，由于锁竞争增加，可能导致：

- 并发性能下降。
- 事务等待时间增加。
- 死锁风险增加。

因此，实际开发中通常不会随意使用 SERIALIZABLE。

## **三、四种隔离级别对比 ⭐⭐⭐⭐⭐**

|**隔离级别**|**脏读**|**不可重复读**|**幻读**|**隔离程度**|
|---|---|---|---|---|
|READ UNCOMMITTED|❌ 可能|❌ 可能|❌ 可能|最低|
|READ COMMITTED|✅ 避免|❌ 可能|❌ 可能|较低|
|REPEATABLE READ|✅ 避免|✅ 避免|⚠️ 常见场景可避免|较高|
|SERIALIZABLE|✅ 避免|✅ 避免|✅ 避免|最高|

**补充：** 按 SQL 标准的最低保证，REPEATABLE READ 不要求完全消除幻读；InnoDB 通过 MVCC 和锁机制提供了额外的防护。


## Q：MySQL 的事务隔离级别有哪些？分别解决什么问题？


MySQL 事务有四种隔离级别，分别是读未提交、读已提交、可重复读和串行化。

**读未提交**是最低的隔离级别，可以读取其他事务尚未提交的数据，因此可能出现脏读、不可重复读和幻读。

**读已提交**只能读取其他事务已经提交的数据，解决了脏读问题，但仍可能出现不可重复读和幻读。

**可重复读**是 InnoDB 默认的隔离级别，通过 MVCC 实现普通查询的一致性读，避免不可重复读，同时结合锁机制，在常见场景下避免幻读。

**串行化**是最高的隔离级别，通过更严格的并发控制保证事务的串行化效果，但会降低并发性能。

其中，读已提交和可重复读的一个核心区别是 Read View 的创建时机：读已提交通常每次普通一致性读都创建新的 Read View，而可重复读通常在第一次一致性读时创建 Read View，并在后续一致性读中复用。



**RU 可以读未提交数据，RC 只读已提交数据，RR 保证普通快照读可重复，Serializable 保证串行化效果。**

面试中，建议你重点掌握 **RC 和 RR 的区别，以及 MVCC、Read View、快照读和当前读之间的关系**。这些是事务隔离级别最常见的深入追问。
