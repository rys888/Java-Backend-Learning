
[[#Q：什么是索引下推和覆盖索引？它们有什么区别？]]


**索引下推（Index Condition Pushdown，ICP）和覆盖索引（Covering Index）都是 MySQL 中减少回表开销的优化手段，但两者的原理不同。**

- **索引下推：** 在二级索引（非聚簇索引）中提前过滤不符合条件的记录，减少不必要的回表。
- **覆盖索引：** 查询需要的所有字段都能从索引中获取，直接返回结果，避免回表。

我们结合联合索引来理解。

## **一、什么是索引下推**

**索引下推（ICP）是指 MySQL 在使用索引查询时，将部分可以通过索引字段判断的 WHERE 条件下推到存储引擎层，提前过滤不符合条件的记录，从而减少回表次数。**

假设有一张用户表：

```sql
CREATE TABLE user (
    id BIGINT PRIMARY KEY,
    name VARCHAR(50),
    age INT,
    city VARCHAR(50),
    INDEX idx_age_city(age, city)
);
```

存在以下数据：

|**id**|**name**|**age**|**city**|
|---|---|---|---|
|1|Eason|20|Beijing|
|2|Tom|20|Shanghai|
|3|Jack|20|Hangzhou|
|4|Alice|21|Beijing|

现在执行：

```sql
SELECT * FROM user
WHERE age > 19 AND city = 'Beijing';
```

由于联合索引为 `(age, city)`，索引首先按照 `age` 排序，`age` 相同时再按照 `city` 排序。

这里 `age > 19` 是范围条件，`city = 'Beijing'` 通常无法进一步缩小索引扫描范围。

### **1. 没有索引下推**

```text
通过 idx_age_city 找到 age > 19 的索引记录
                  ↓
             获取主键 id
                  ↓
           回表查询完整数据
                  ↓
          判断 city = Beijing
                  ↓
           返回符合条件的记录
```

假设 `age > 19` 匹配了 1000 条索引记录，就可能需要回表 1000 次，再判断 `city` 是否符合条件。

### **2. 使用索引下推**

```text
通过 idx_age_city 找到 age > 19 的索引记录
                  ↓
        直接判断 city = Beijing
                  ↓
          ┌───────┴───────┐
          │               │
        不符合           符合
          │               │
          ▼               ▼
       直接跳过        获取主键 id
                          ↓
                       回表查询
                          ↓
                       返回数据
```

因为联合索引叶子节点已经包含：

```text
age + city + id
```

所以存储引擎可以直接利用索引中的 `city` 判断记录是否符合条件。

假设 1000 条记录中只有 50 条满足 `city = 'Beijing'`，那么就可能只需要回表 50 次。

**因此，索引下推的核心作用是：提前过滤数据，减少不必要的回表。**

需要注意，索引下推是否实际发生，由 MySQL 优化器决定；这里假设查询使用该二级索引且启用了 ICP。

## **二、什么是覆盖索引？⭐⭐⭐⭐⭐**

**覆盖索引是指查询所需要的字段全部包含在某个索引中，因此可以直接从索引中获取查询结果，不需要回表。**

还是刚才的联合索引：

```sql
INDEX idx_age_city(age, city)
```

InnoDB 二级索引叶子节点保存：

```text
age + city + id
```

现在执行：

```sql
SELECT id, age, city
FROM user
WHERE age = 20;
```

由于查询需要的 `id`、`age` 和 `city` 都可以从二级索引中获取，因此不需要再查询聚簇索引。

查询过程：

```text
通过 idx_age_city 查找 age = 20
                  ↓
           定位索引叶子节点
                  ↓
         读取 age、city 和 id
                  ↓
              直接返回
                  ↓
             不需要回表
```

但是，如果执行：

```sql
SELECT *
FROM user
WHERE age = 20;
```

由于 `name` 不在二级索引中，因此通常需要回表获取完整行数据。

**因此，覆盖索引的核心作用是：直接从索引获取所需数据，避免回表。**

注意，覆盖索引并不是一种独立的索引类型，而是指**某个索引能够覆盖当前 SQL 查询所需字段的情况**。

## **三、索引下推和覆盖索引的区别 ⭐⭐⭐⭐⭐**

|**对比**|**索引下推（ICP）**|**覆盖索引**|
|---|---|---|
|核心思想|提前过滤不符合条件的数据|直接从索引获取查询结果|
|优化目标|减少回表次数|避免回表|
|是否需要回表|符合条件的记录可能仍需回表|不需要回表|
|实现原理|将部分 WHERE 条件下推到存储引擎层|查询所需字段全部包含在索引中|
|典型场景|联合索引中部分字段不能用于缩小扫描范围|查询字段被二级索引覆盖|
|EXPLAIN| `Using index condition` | `Using index` |

其中最重要的区别是：

**索引下推是减少回表，覆盖索引是避免回表。**

### **用两个 SQL 对比**

假设存在联合索引：

```sql
INDEX idx_age_city(age, city)
```

**SQL 1：索引下推**

```sql
SELECT *
FROM user
WHERE age > 20 AND city = 'Beijing';
```

由于 `SELECT *` 需要读取 `name`，因此通常需要回表。

但可以利用索引中的 `city` 提前过滤不符合条件的记录，从而减少回表次数。

**SQL 2：覆盖索引**

```sql
SELECT id, age, city
FROM user
WHERE age > 20 AND city = 'Beijing';
```

查询需要的字段全部包含在索引中，因此可以直接从二级索引中读取数据，不需要回表。

即使第二条 SQL 同样需要判断 `city` 条件，也不代表它一定使用了 ICP。覆盖索引查询通常直接利用索引完成过滤和结果获取。

## Q：什么是索引下推和覆盖索引？它们有什么区别？

索引下推和覆盖索引都是 MySQL 中减少回表开销的优化手段。

**索引下推**是指将部分可以通过索引字段判断的 WHERE 条件下推到存储引擎层，在回表之前提前过滤不符合条件的记录，从而减少回表次数。

**覆盖索引**是指查询所需要的字段全部包含在索引中，因此可以直接从索引中获取查询结果，不需要回表。

两者最大的区别在于，索引下推是通过提前过滤减少回表次数，而覆盖索引是因为索引已经包含查询所需的全部字段，所以可以直接避免回表。




**索引下推：先通过索引过滤，再对符合条件的记录回表。**

**覆盖索引：查询所需字段全部在索引中，直接返回，不需要回表。**

简单地说：
- **索引下推：本来要回表 100 次，优化后可能只需要 10 次。**
- **覆盖索引：本来需要回表，现在 0 次。**
