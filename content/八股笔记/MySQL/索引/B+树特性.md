
[[#Q：B+ 树有什么特点？为什么 MySQL 使用 B+ 树？]]

**B+ 树是一种多路平衡搜索树，具有非叶子节点只存储索引键和子节点指针、数据记录集中在叶子节点、叶子节点有序且通过链表连接等特点。**

MySQL 的 InnoDB 之所以采用 B+ 树作为主要索引结构，就是因为它能够**减少磁盘 I/O，同时高效支持等值查询、范围查询和排序**。

## **一、B+ 树的五大特性 
### 1. 多路平衡搜索树，树的高度低

与二叉树不同，B+ 树的一个节点可以拥有多个子节点。

```text
                [20 | 40]
               /    |    \
              /     |     \
             ▼      ▼      ▼
         [1~19] [20~39] [40~60]
```

由于一个节点可以存储多个索引键和指针，因此 B+ 树的分支数较多，树的高度通常较低。

**优点：减少查找过程中需要访问的数据页数量，从而降低磁盘 I/O。**

### **2. 非叶子节点主要存储索引键和指针**

B+ 树的非叶子节点主要负责导航，不存储完整行数据。

例如：

```text
             非叶子节点
          ┌─────────────┐
          │ 10 | 20 | 30│
          └─────────────┘
             ↓   ↓   ↓
          指向子节点
```

这样，一个默认大小为 16 KB 的 InnoDB 数据页可以容纳较多索引项。

**优点：提高树的扇出，降低树高，减少磁盘 I/O。**

### **3. 所有数据记录都位于叶子节点**

B+ 树的非叶子节点主要负责索引导航，真正的索引记录存储在叶子节点中。

在 InnoDB 中：

- **聚簇索引**：叶子节点存储完整行数据。
- **非聚簇索引**：叶子节点存储索引列和主键值。

因此，查询时会沿着 B+ 树逐层向下，最终定位到叶子节点。

**优点：查找路径比较稳定，便于数据库管理和访问数据。**

### **4. 叶子节点之间通过双向链表连接

这是 B+ 树非常重要的特点。

```text
           B+ 树叶子节点

┌──────────┐    ┌──────────┐    ┌──────────┐
│ 1  2  3  │ ⇄  │ 4  5  6  │ ⇄  │ 7  8  9  │
└──────────┘    └──────────┘    └──────────┘
```

在 InnoDB 中：

- 叶子页之间通过**双向链表**连接。
- 同一数据页内部的记录通过**单向链表**连接。

例如：

```sql
SELECT * FROM user WHERE id BETWEEN 3 AND 8;
```

执行时：

1. 通过 B+ 树定位 `id = 3` 所在的叶子页。
2. 通过页目录和页内单向链表定位具体记录。
3. 顺序读取符合条件的数据。
4. 通过叶子页之间的双向链表继续扫描后续数据页。

**优点：范围查询不需要对每条记录都重新从根节点查找，提高范围扫描效率。**

### **5. 叶子节点中的索引键有序排列**

B+ 树中的索引键按照大小顺序组织。

例如：

```text
1 → 2 → 3 → 4 → 5 → 6 → 7 → 8
```

因此，B+ 树不仅支持等值查询，还可以利用索引顺序进行范围查询和排序。

例如：

```sql
-- 等值查询
SELECT * FROM user WHERE id = 10;

-- 范围查询
SELECT * FROM user WHERE id > 10;

-- 排序查询
SELECT * FROM user ORDER BY id;
```

**优点：能够利用索引的有序性，提高范围查询和排序效率。**

需要注意，排序能否利用索引，还取决于查询条件、索引设计和执行计划。

## **二、为什么 MySQL 不使用 B 树，而使用 B+ 树？**

|**对比**|**B 树**|**B+ 树**|
|---|---|---|
|非叶子节点|可以存储数据记录|主要存储索引键和指针|
|数据记录位置|非叶子节点和叶子节点|集中在叶子节点|
|树的高度|相同条件下可能较高|通常较低|
|范围查询|需要进行树的遍历|可以沿叶子节点链表扫描|
|查询路径|可能在非叶子节点结束|通常到叶子节点结束|

**B+ 树最大的优势在于：非叶子节点可以容纳更多索引键，使树的高度较低，同时通过叶子节点之间的链表提高范围查询效率。**

## Q：B+ 树有什么特点？为什么 MySQL 使用 B+ 树？

B+ 树是一种多路平衡搜索树，主要有四个特点。

第一，B+ 树的非叶子节点主要存储索引键和子节点指针，不存储完整行数据，因此一个节点可以容纳更多索引项，降低树的高度，减少磁盘 I/O。

第二，所有数据记录都存储在叶子节点中，因此查找路径比较稳定。

第三，叶子节点中的索引键有序排列，并且在 InnoDB 中，叶子页之间通过双向链表连接，方便进行范围查询和顺序扫描。

第四，B+ 树是一种平衡树，所有叶子节点都位于同一层，能够保证较稳定的查询性能。

因此，相比 B 树、二叉树和哈希表，B+ 树更适合数据库的磁盘存储特点，既能减少磁盘 I/O，又能高效支持等值查询、范围查询和排序。
