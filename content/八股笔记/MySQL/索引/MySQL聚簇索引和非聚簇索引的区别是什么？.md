
[[#Q：MySQL 中聚簇索引和非聚簇索引有什么区别？]]

MySQL 里，**聚簇索引和非聚簇索引的核心区别：B+ 树叶子节点存的东西不一样。**

- **聚簇索引**：叶子节点存的是完整的行数据。
- **非聚簇索引**：叶子节点不存完整行数据，只存索引键，以及用来定位数据行的信息。

InnoDB 里非聚簇索引一般也叫**二级索引（Secondary Index）**，叶子节点就是「索引列 + 主键值」这两样东西。下面都按 InnoDB 来说。

## 一、聚簇索引是什么？

**聚簇索引指的是索引结构和实际行数据存在一起的索引。** 在 InnoDB 里，聚簇索引一般由主键构建。

假设有这么一张用户表：

```sql
CREATE TABLE user (
    id BIGINT PRIMARY KEY,
    username VARCHAR(50),
    age INT,
    INDEX idx_age(age)
) ENGINE = InnoDB;
```

表里的数据：

|**id**|**username**|**age**|
|---|---|---|
|1|Eason|20|
|2|Tom|22|
|3|Jack|21|
|4|Alice|23|

`id` 是主键，InnoDB 就基于 `id` 建聚簇索引，结构大致是这样：

```text
                聚簇索引 B+ 树
                     │
                ┌────┴────┐
                │  2 | 3  │
                └────┬────┘
                     │
           ┌─────────┴─────────┐
           ▼                   ▼
      叶子节点 1           叶子节点 2
   ┌────────────────┐   ┌────────────────┐
   │ id=1           │   │ id=3           │
   │ username=Eason │   │ username=Jack  │
   │ age=20         │   │ age=21         │
   ├────────────────┤   ├────────────────┤
   │ id=2           │   │ id=4           │
   │ username=Tom   │   │ username=Alice │
   │ age=22         │   │ age=23         │
   └────────────────┘   └────────────────┘
```

这是简化图，实际的 B+ 树节点是按数据页为单位组织的。关键点在于：**聚簇索引的叶子节点不只保存主键，整行数据都在里面。**

查一下试试：

```sql
SELECT * FROM user WHERE id = 3;
```

过程就是 **拿 `id = 3` 走聚簇索引的 B+ 树 → 定位到叶子节点 → 完整行数据已经在手里 → 直接返回。** 不需要再通过别的索引找数据，这也是 InnoDB 主键查询效率比较高的主要原因。

## 二、非聚簇索引是什么？

非聚簇索引就是二级索引，叶子节点主要保存两样东西：**索引列的值 + 对应记录的主键值。**

上面的 `INDEX idx_age(age)` 就是一个非聚簇索引，结构大概是：

```text
                 非聚簇索引 B+ 树
                       │
                  ┌────┴────┐
                  │ 21 | 22 │
                  └────┬────┘
                       │
             ┌─────────┴─────────┐
             ▼                   ▼
         叶子节点 1           叶子节点 2
      ┌──────────────┐      ┌──────────────┐
      │ age=20, id=1 │      │ age=22, id=2 │
      │ age=21, id=3 │      │ age=23, id=4 │
      └──────────────┘      └──────────────┘
```

这里注意到，`username` 并没有存进去。所以查询如果需要 `username`，光靠这棵索引拿不到，还得再回聚簇索引找一趟。

## 三、什么是回表查询？

**回表就是：通过二级索引找到主键值，再拿这个主键值去聚簇索引里获取完整行数据。** 这是面试非常重要的一个点。

比如：

```sql
SELECT * FROM user WHERE age = 21;
```

`age` 上建了非聚簇索引，所以 MySQL 先走 `idx_age`。整个流程是：

1. 查 `idx_age`，找到 `age = 21`；
2. 从叶子节点里取出对应的主键 `id = 3`；
3. 拿着 `id = 3` 再查聚簇索引，取出完整行数据；
4. 返回查询结果。

这条链路概括起来就是 **二级索引 → 主键值 → 聚簇索引 → 完整行数据**，这个过程就叫**回表**。

回表为什么会降低性能？因为它要访问两棵 B+ 树，先查二级索引，再查聚簇索引。如果结果集有很多条记录，回表次数就上去了，所以 MySQL 优化器有时候会认为全表扫描比大量回表更划算。

不过要注意，回表不代表每次都会发生磁盘 I/O。相关的索引页和数据页很可能已经在 Buffer Pool 里了，直接从内存就拿到了。

⚠️ 顺带记一下 **Buffer Pool（缓冲池）**：它是 InnoDB 在内存中开辟的一块缓存区域，主要缓存磁盘中的**数据页和索引页**，用来减少磁盘 I/O。查询时 InnoDB 先看要的页在不在 Buffer Pool 里，在就直接从内存读，不在才从磁盘加载进来；修改时先改 Buffer Pool 里的页，这时页变成**脏页（Dirty Page）**，之后由后台线程刷入磁盘，同时靠 Redo Log 保障崩溃恢复。这个思路和操作系统的页面缓存很像。

## 四、非聚簇索引一定需要回表吗？

**不一定。**

如果查询需要的字段都能从二级索引里拿到，就不需要回表，这就是**覆盖索引（Covering Index）**。

```sql
SELECT id, age
FROM user
WHERE age = 21;
```

`idx_age` 的叶子节点里已经有 `age = 21` 和 `id = 3` 了，这两个字段正好就是要查的全部内容，所以 **直接返回结果，不需要回表。** 走一遍就是：查 `age = 21` → 找到 `idx_age` → 拿到 `age` 和 `id` → 返回，不用再去聚簇索引。

对比几种情况：

|**SQL**|**是否通常需要回表**|
|---|---|
| `SELECT * FROM user WHERE id = 3` |不需要|
| `SELECT * FROM user WHERE age = 21` |需要|
| `SELECT id, age FROM user WHERE age = 21` |不需要|
| `SELECT username FROM user WHERE age = 21` |需要|

（这里假设优化器选择了对应的索引，并且没有其他额外的覆盖索引。）

**覆盖索引的核心作用就是减少回表，提高查询效率。**

## 五、聚簇索引和非聚簇索引的区别 

|**对比**|**聚簇索引**|**非聚簇索引**|
|---|---|---|
|底层结构|B+ 树|B+ 树|
|叶子节点内容|完整行数据|索引列 + 主键值|
|数量|每张 InnoDB 表只有一个|可以有多个|
|是否需要回表|不需要|可能需要|
|查询方式|根据聚簇键直接定位完整记录|先定位索引记录，必要时回表|
|典型场景|主键查询|普通索引查询|
|存储特点|数据按照聚簇键组织|独立维护索引结构|

有一点容易搞混：**聚簇索引不完全等于主键索引。** InnoDB 选择聚簇索引的规则是：

1. 如果存在主键，优先使用主键作为聚簇索引；
2. 如果没有主键，选择第一个所有索引列都为 `NOT NULL` 的唯一索引；
3. 如果都不存在，InnoDB 会生成隐藏的行 ID，并以此建立聚簇索引。

所以 InnoDB 表即使没有显式定义主键，也一样会有聚簇索引。

## Q：MySQL 中聚簇索引和非聚簇索引有什么区别？

可以这样回答：

在 InnoDB 中，聚簇索引和非聚簇索引的主要区别在于 B+ 树叶子节点存储的内容不同。聚簇索引的叶子节点保存完整的行数据，InnoDB 通常使用主键建立聚簇索引，因此通过主键查询时，可以直接获取完整记录。而非聚簇索引也叫二级索引，它的叶子节点保存索引列和对应的主键值。当通过二级索引查询时，如果需要的字段不在二级索引中，就需要先获取主键，再通过聚簇索引查找完整记录，这个过程叫回表。如果查询需要的字段都包含在二级索引中，就可以使用覆盖索引，避免回表。此外，一张 InnoDB 表只有一个聚簇索引，但可以建立多个非聚簇索引。
