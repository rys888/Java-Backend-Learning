
## **一、什么是联合索引

**联合索引（Composite Index）是指将多个字段组合起来建立一个索引，底层仍然使用 B+ 树实现。**

与单列索引不同，联合索引会按照**索引字段的定义顺序依次排序**，因此具有最左前缀匹配的特点。

例如：

```sql
CREATE TABLE user (
    id BIGINT PRIMARY KEY,
    name VARCHAR(50),
    age INT,
    city VARCHAR(50),
    INDEX idx_name_age_city(name, age, city)
);
```

这里创建了一个联合索引：

```sql
(name, age, city)
```

需要注意：

**联合索引不是分别建立三棵 B+ 树，而是将三个字段组合起来，建立一棵 B+ 树。**

---

## **二、联合索引的底层实现原理 ⭐⭐⭐⭐⭐**

假设表中有以下数据：

|**id**|**name**|**age**|**city**|
|---|---|---|---|
|1|Alice|20|Beijing|
|2|Alice|22|Shanghai|
|3|Alice|22|Beijing|
|4|Bob|19|Hangzhou|
|5|Bob|25|Beijing|
|6|Eason|21|Shaoxing|

联合索引 `(name, age, city)` 的叶子节点会按照以下规则排序：

1. **首先按照 name 排序。**
2. **name 相同时，按照 age 排序。**
3. **name 和 age 都相同时，再按照 city 排序。**

因此，联合索引的叶子节点可以简化为：

```text
                 联合索引 B+ 树
                       │
                       ▼
              非叶子节点（索引导航）
                       │
                       ▼
                  叶子节点
                       │
     ┌────────────────────────────────┐
     │ (Alice, 20, Beijing)  → id=1   │
     │              ↓                 │
     │ (Alice, 22, Beijing)  → id=3   │
     │              ↓                 │
     │ (Alice, 22, Shanghai) → id=2   │
     │              ↓                 │
     │ (Bob, 19, Hangzhou)   → id=4   │
     │              ↓                 │
     │ (Bob, 25, Beijing)    → id=5   │
     │              ↓                 │
     │ (Eason, 21, Shaoxing) → id=6   │
     └────────────────────────────────┘
```

这里展示的是叶子记录的逻辑顺序。实际 InnoDB 中，记录存储在数据页中，叶子页之间通过双向链表连接，页内记录通过单向链表连接。

由于这是 InnoDB 的二级索引，叶子节点保存：

**联合索引字段（name、age、city）+ 主键值（id）。**

如果查询需要其他字段，就可能需要通过主键回表。

## **三、什么是最左前缀匹配原则？⭐⭐⭐⭐⭐**

这是联合索引最重要的知识点。

**最左前缀匹配原则是指：联合索引按照最左侧字段开始排序，查询时通常需要从最左侧字段开始，才能高效利用索引进行定位。**

假设联合索引为：

```sql
INDEX idx_name_age_city(name, age, city)
```

### **1. 可以完整利用联合索引**

```sql
SELECT * FROM user
WHERE name = 'Alice'
AND age = 22
AND city = 'Beijing';
```

查询过程：

```text
先定位 name = Alice
         ↓
在 Alice 的记录中定位 age = 22
         ↓
在相同 name、age 的记录中定位 city = Beijing
         ↓
获取对应主键
         ↓
必要时回表
```

三个字段都可以用于缩小索引扫描范围。

### **2. 可以利用联合索引的前两个字段**

```sql
SELECT * FROM user
WHERE name = 'Alice'
AND age = 22;
```

由于联合索引先按照 `name` 排序，再按照 `age` 排序，因此可以快速定位符合条件的记录。

### **3. 只使用第一个字段，也可以利用索引**

```sql
SELECT * FROM user
WHERE name = 'Alice';
```

因为所有 `name = 'Alice'` 的索引记录都连续排列，所以可以通过 B+ 树快速定位，再顺序扫描。

### **4. 跳过最左侧字段，通常无法高效定位**

```sql
SELECT * FROM user
WHERE age = 22
AND city = 'Beijing';
```

为什么？

因为联合索引首先按照 `name` 排序，而不是按照 `age` 排序。

例如：

```text
(Alice, 20, Beijing)
(Alice, 22, Beijing)
(Bob,   19, Hangzhou)
(Bob,   25, Beijing)
(Eason, 21, Shaoxing)
```

可以发现，`age` 在整个索引中并不是全局有序的。

因此，无法直接通过 `age = 22` 定位一个连续的索引范围。

不过需要注意：**不满足最左前缀原则，不代表 MySQL 一定完全不使用索引。** 优化器仍可能选择全索引扫描、索引跳跃扫描（Index Skip Scan）等方式。

## **四、联合索引遇到范围查询会怎么样？**

假设联合索引为：

```sql
(name, age, city)
```

执行：

```sql
SELECT * FROM user
WHERE name = 'Alice'
AND age > 20
AND city = 'Beijing';
```

查询过程：

**①**  `name = 'Alice'`

可以利用索引快速定位。

**②** `age > 20` 

可以利用索引定位符合条件的年龄范围。

**③**  `city = 'Beijing'` 

由于 `age > 20` 是范围条件，不同 `age` 下的 `city` 记录并不是一个连续的整体，因此通常无法继续利用 `city` 缩小 B+ 树的扫描范围。

但是，`city` 仍然可以通过索引条件下推（ICP）等方式参与过滤。

所以不能简单地认为范围查询之后的字段完全无法使用索引。

例如：

```text
(name, age, city)
       │
       ▼
name = Alice       → 等值定位
       │
       ▼
age > 20           → 范围扫描
       │
       ▼
city = Beijing     → 可以参与过滤，
                     但通常不能继续缩小扫描范围
```

另外，**并不是所有范围条件都会让后续字段无法用于索引范围定位**。

例如：

```sql
WHERE name = 'Alice'
AND age >= 20
AND age <= 20
AND city = 'Beijing'
```

这里 `age` 实际上被限制为一个确定值，优化器可能继续利用后续字段。

## **五、联合索引和覆盖索引的关系**

联合索引还可以减少回表查询。

例如：

```sql
SELECT name, age, city
FROM user
WHERE name = 'Alice'
AND age = 22;
```

由于联合索引已经包含：

```text
name
age
city
id（主键）
```

因此，查询所需字段都在二级索引中，可以直接返回结果，不需要回表。

这就是**覆盖索引**。

但如果执行：

```sql
SELECT *
FROM user
WHERE name = 'Alice'
AND age = 22;
```

假设表中还有其他未包含在联合索引中的字段，就需要回表获取完整数据。

## **六、面试怎么回答？

如果面试官问：

**“MySQL 联合索引的底层实现原理是什么？”**

可以这样回答：

联合索引是指将多个字段组合起来建立一个索引，在 InnoDB 中，底层仍然使用 B+ 树实现。

联合索引并不是为每个字段分别建立一棵 B+ 树，而是将多个字段按照定义顺序组合成索引键，建立一棵 B+ 树。

例如联合索引 `(a, b, c)`，会先按照 a 排序，a 相同时按照 b 排序，a 和 b 都相同时再按照 c 排序。

因此，联合索引具有最左前缀匹配原则，查询时通常需要从最左侧字段开始，才能高效利用索引进行定位。

如果遇到范围查询，后续字段通常无法继续用于缩小索引扫描范围，但仍可能通过索引条件下推参与过滤。

此外，InnoDB 联合索引属于二级索引，叶子节点保存联合索引字段和主键值，如果查询字段全部被索引覆盖，就可以避免回表，提高查询效率。

### **一句话总结**

**联合索引的底层是一棵 B+ 树，索引键按照字段定义顺序依次排序，因此具有最左前缀匹配原则；合理设计联合索引，还可以利用覆盖索引减少回表。**

这里最重要的是理解：

 `(a, b, c)` **的排序规则是先 a、再 b、最后 c，而不是三个字段各自独立排序。**
