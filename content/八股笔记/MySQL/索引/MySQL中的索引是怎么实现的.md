
[[#Q：MySQL 中的索引是怎么实现的？]]

MySQL 中的索引主要通过 **B+ 树数据结构实现**。索引的作用是帮助数据库快速定位数据，避免每次查询都进行全表扫描，从而提高查询效率。

需要注意，MySQL 的索引具体由存储引擎实现。我们最常用的 **InnoDB 存储引擎主要采用 B+ 树索引**。

## **一、MySQL 索引的底层结构

假设有一张用户表：

```sql
CREATE TABLE user (
    id BIGINT PRIMARY KEY,
    name VARCHAR(50),
    age INT,
    INDEX idx_age(age)
);
```

其中：

- `id`：主键索引（聚簇索引）。
- `age`：普通索引（二级索引）。

InnoDB 会分别为这两个索引建立 B+ 树。

### **1. B+ 树是如何组织数据的？**

假设主键为：

```text
1、2、3、4、5、6、7、8、9
```

对应的 B+ 树可以简化为：

```text
                   根节点
                ┌─────────┐
                │  4 | 7  │
                └─────────┘
                 /   |   \
                /    |    \
               ▼     ▼     ▼
          ┌──────┐ ┌──────┐ ┌──────┐
          │1 2 3 │ │4 5 6 │ │7 8 9 │
          └──────┘ └──────┘ └──────┘
             ↔         ↔
```

B+ 树具有三个重要特点：

1. **非叶子节点主要存储索引键和子节点指针**，用于定位数据。
2. **叶子节点存储实际索引记录**，聚簇索引的叶子节点还包含完整行数据。
3. **叶子节点按照索引键有序排列**，相邻叶子页通过链表连接，方便范围查询。

实际 InnoDB 的 B+ 树以数据页为单位组织，默认页大小为 16 KB。

## **二、索引是如何加快查询的？**

例如执行：

```sql
SELECT * FROM user WHERE id = 5;
```

如果没有合适的索引，数据库可能需要逐行扫描：

```text
id=1 → id=2 → id=3 → id=4 → id=5
```

如果使用 B+ 树索引：

```text
查询 id = 5
     ↓
从根节点开始
     ↓
比较索引键，确定子节点
     ↓
定位包含 id=5 的叶子节点
     ↓
获取完整行数据
```

因为 B+ 树是一种多路平衡搜索树，每个节点可以包含多个索引键，所以树的高度通常很低。

**即使存储大量数据，也通常只需要访问少量 B+ 树节点就能定位记录。**

而且，访问过的索引页可能缓存在 Buffer Pool 中，进一步减少磁盘 I/O。

## **三、聚簇索引和非聚簇索引是如何实现的？**

这是理解 InnoDB 索引的关键。

### **1. 聚簇索引**

InnoDB 通常使用主键构建聚簇索引。

```text
主键 B+ 树
    ↓
根据 id 查找
    ↓
叶子节点存储完整行数据
```

例如：

```sql
SELECT * FROM user WHERE id = 5;
```

可以通过聚簇索引直接获取完整记录。

### **2. 非聚簇索引**

非聚簇索引的叶子节点保存索引列和主键值。

```text
age 二级索引 B+ 树
         ↓
找到 age = 20
         ↓
获得主键 id = 5
         ↓
通过主键查找聚簇索引
         ↓
获取完整行数据
```

例如：

```sql
SELECT * FROM user WHERE age = 20;
```

如果优化器选择使用 `idx_age`，并且需要读取二级索引中没有的字段，就会发生**回表查询**。

但如果执行：

```sql
SELECT id, age FROM user WHERE age = 20;
```

由于二级索引中已经包含 `id` 和 `age`，就可以使用**覆盖索引**，避免回表。

## **四、为什么 MySQL 选择 B+ 树，而不是其他数据结构？**

|**数据结构**|**特点**|**为什么不作为 InnoDB 的主要索引结构**|
|---|---|---|
|数组|查找可以很快|插入、删除维护成本高|
|链表|插入删除方便|查找通常需要 O(n)|
|哈希表|等值查询平均 O(1)|不适合范围查询和排序|
|二叉搜索树|可以进行有序查找|树高可能较大|
|红黑树|能保持平衡|分支数少，数据量大时树较高|
|B 树|多路平衡搜索树|非叶子节点也存储数据记录，范围扫描不如 B+ 树的叶子层组织方式方便|
|**B+ 树**|多路平衡、叶子节点有序|**适合数据库索引**|

B+ 树主要有三个优势。

**① 树的高度低，减少磁盘 I/O。**

由于非叶子节点主要存储索引键和指针，一个数据页可以容纳大量索引项，使得 B+ 树的分支数较大、树高较低。

**② 支持范围查询。**

例如：

```sql
SELECT * FROM user
WHERE id BETWEEN 100 AND 200;
```

B+ 树可以先定位 `id = 100` 附近的叶子记录，然后沿着有序的叶子节点扫描，而不需要重新查找每一条记录。

**③ 支持排序。**

例如：

```sql
SELECT * FROM user ORDER BY id;
```

由于聚簇索引按照主键有序组织，数据库可以利用索引顺序读取记录，在合适的执行计划下避免额外排序。

## Q：MySQL 中的索引是怎么实现的？

MySQL 的索引由存储引擎实现，其中 InnoDB 主要采用 B+ 树作为索引的数据结构。

B+ 树是一种多路平衡搜索树，非叶子节点主要存储索引键和子节点指针，叶子节点存储实际索引记录，并且按照索引键有序排列。

在 InnoDB 中，索引主要分为聚簇索引和非聚簇索引。聚簇索引的叶子节点存储完整行数据，而非聚簇索引的叶子节点存储索引列和主键值，因此通过非聚簇索引查询完整记录时，可能需要回表。

之所以选择 B+ 树，是因为它的多路结构使树高较低，可以减少磁盘 I/O，同时叶子节点有序，能够高效支持等值查询、范围查询和排序。

此外，InnoDB 还会利用 Buffer Pool 缓存索引页和数据页，进一步提高查询效率。
