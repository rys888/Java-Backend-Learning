在 MySQL 中， `INT(1)`  **和**  `INT(10)` **在存储范围、占用空间以及计算性能上没有区别。**

括号中的数字表示的是**显示宽度（Display Width）**，而不是整数的存储长度。

## **一、INT(1) 和 INT(10) 的区别 ⭐⭐⭐⭐⭐**

|**对比**|**INT(1)**|**INT(10)**|
|---|---|---|
|数据类型|INT|INT|
|存储空间|4 字节|4 字节|
|有符号取值范围|-2³¹ ~ 2³¹-1|-2³¹ ~ 2³¹-1|
|无符号取值范围|0 ~ 2³²-1|0 ~ 2³²-1|
|是否限制数字位数|否|否|
|计算性能|相同|相同|

例如：

```sql
CREATE TABLE test (
    age INT(1),
    salary INT(10)
);
```

执行：

```sql
INSERT INTO test VALUES (123456, 123456);
```

**两个字段都能正常存储**  `123456` ****。**

因为 `INT(1)` 并不代表只能存储一位整数。

## **二、括号中的数字到底有什么作用？**

在旧版本 MySQL 中，`INT(M)` 中的 `M` 表示显示宽度。

它通常需要配合 `ZEROFILL` 才能明显体现效果。

例如：

```sql
CREATE TABLE test (
    id INT(5) ZEROFILL
);
```

插入：

```sql
INSERT INTO test VALUES (123);
```

查询结果可能显示为：

```text
00123
```

因为指定了显示宽度为 5，并使用 `ZEROFILL` 在前面补零。

但是：

**显示宽度不会改变整数的实际存储范围，也不会限制可以存储的整数位数。**

需要注意版本区别：

- **MySQL 8.0.17 起**，整数显示宽度被弃用。
- **MySQL 8.0.19 起**，`ZEROFILL` 也被弃用。
- **MySQL 8.4 等较新版本**已经不再支持普通整数类型的显示宽度语法，不能继续依赖 `INT(1)` 这种写法。

因此，现代 MySQL 开发中建议直接使用：

```sql
age INT
```

而不是：

```sql
age INT(10)
```

## **三、INT 和 BIGINT 有什么区别？**

真正决定整数存储空间和取值范围的是**数据类型本身**，而不是括号里的数字。

|**数据类型**|**存储空间**|**有符号取值范围**|
|---|---|---|
|TINYINT|1 字节|-128 ~ 127|
|SMALLINT|2 字节|-32768 ~ 32767|
|MEDIUMINT|3 字节|-8388608 ~ 8388607|
|INT|4 字节|-2147483648 ~ 2147483647|
|BIGINT|8 字节|-2⁶³ ~ 2⁶³-1|

例如：

```sql
age TINYINT UNSIGNED
```

适合存储年龄等较小的非负整数。

```sql
id BIGINT
```

适合存储可能持续增长的大范围整数 ID。

## Q：MySQL 中 INT(1) 和 INT(10) 有什么区别？

在 MySQL 中，INT(1) 和 INT(10) 本质上没有存储上的区别。

INT 类型固定占用 4 个字节，括号中的数字在旧版本 MySQL 中表示显示宽度，而不是存储长度，也不会限制整数的取值范围。

例如 INT(1) 同样可以存储 123456。

此外，MySQL 8.0.17 开始弃用整数显示宽度，因此在实际开发中通常直接使用 INT，不需要指定括号中的数字。

**一句话记忆：**** `INT(1)`  **和** `INT(10)` 都占 4 字节，括号中的数字不是存储位数，而是旧版本 MySQL 中的显示宽度。
