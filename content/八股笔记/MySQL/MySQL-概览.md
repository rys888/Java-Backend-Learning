- **索引**：B+树的结构、聚簇索引和非聚簇索引的区别、联合索引的最左匹配原则、索引失效的场景，这块是 MySQL 面试里出现频率最高的。
- **事务和 MVCC**：四种隔离级别的区别、MVCC 是怎么用 Read View 来实现可重复读的，这是理解并发问题的核心。
- **锁**：行锁、间隙锁、临键锁各自锁的范围，以及为什么没用上合适的索引会扩大加锁范围，这块很多人答不清楚。
- **日志**：redo log、undo log、binlog 三个日志各自的作用和区别，两阶段提交是怎么保证数据一致性的。

当执行 UPDATE 操作时，如果底层是 InnoDB 的话，就会通过索引去查找需要修改的记录，然后对相应的索引记录加一个行锁（排他锁），这个过程是有锁的，别的线程是无法对被锁住的记录进行 UPDATE 操作的，但是是可以进行普通 SELECT 的。然后这里又引出了 Read View 的知识，如果是 InnoDB 的话，默认支持 RR（可重复读）隔离级别，然后会根据当前事务第一次快照读时创建的 Read View 来 SELECT 某个数据，即使被**其他事务**所 UPDATE 并提交了，它也可以查询到没变化过的值，因为可以通过 Undo Log 找到符合 Read View 可见性规则的旧版本。但是如果是**当前事务自己 UPDATE 的数据，那么当前事务是可以查询到修改后的值的**。
