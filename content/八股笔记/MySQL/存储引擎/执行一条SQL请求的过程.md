
[[执行一条SQL请求的过程]]

MySQL 执行一条 SQL 语句，主要经过**连接器、解析器、预处理器、优化器和执行器**五个阶段。其中，预处理、优化和执行也可以统称为 SQL 的执行处理过程。

以以下 SQL 为例：

```sql
SELECT * FROM user WHERE id = 10;
```

### **1. 连接器**

客户端首先与 MySQL 建立连接，连接器负责**建立连接、管理连接以及校验用户身份**。

如果使用数据库连接池（如 HikariCP），则可以复用已有连接，不需要每次执行 SQL 都重新建立连接。

### **2. 解析器**

连接建立后，MySQL 通过解析器对 SQL 语句进行**词法分析和语法分析**。

- **词法分析**：识别 `SELECT`、`FROM`、`WHERE` 等关键字，以及表名、字段名等。
- **语法分析**：检查 SQL 是否符合语法规则，并构建语法树。

例如，如果将 `SELECT` 写成 `SELEC`，就会在解析阶段出现语法错误。

### **3. 预处理器**

预处理器主要负责**检查表和字段是否存在，并对 SQL 进行进一步处理**。

例如：

```sql
SELECT * FROM user WHERE id = 10;
```

预处理器会检查 `user` 表和 `id` 字段是否存在，并将 `SELECT *` 中的 `*` 展开为表中的所有列。

### **4. 优化器**

优化器根据**索引、统计信息和查询成本**，选择预估执行成本较低的执行计划。

例如：

```sql
SELECT * FROM user WHERE id = 10;
```

假设 `id` 是主键，优化器通常会选择通过主键索引查找记录，而不是进行全表扫描。

优化器主要决定：

- 是否使用索引，以及使用哪个索引。
- 多表查询时的连接顺序。
- 选择预估成本较低的执行方式。

### **5. 执行器**

执行器根据优化器生成的执行计划，**调用存储引擎提供的接口读取数据，并将查询结果返回客户端**。

例如，执行器通过 InnoDB 存储引擎查找 `id = 10` 的记录。

InnoDB 会通过 B+ 树索引定位数据，并利用 Buffer Pool 缓存数据页，减少磁盘 I/O。

最终将查询结果返回客户端。

---

## **整体执行流程**

```text
客户端发送 SQL 请求
        ↓
① 连接器
   建立连接、管理连接、身份认证
        ↓
② 解析器
   词法分析、语法分析、构建语法树
        ↓
③ 预处理器
   检查表和字段、展开 SELECT *
        ↓
④ 优化器
   根据查询成本选择执行计划
        ↓
⑤ 执行器
   调用存储引擎接口执行 SQL
        ↓
⑥ InnoDB 存储引擎
   通过索引和 Buffer Pool 读取数据
        ↓
返回查询结果
```

⚠️：小林 Coding 中在解析 SQL 前还有一个查询缓存阶段，但是 MySQL 8.0 已经移除了查询缓存模块，因此不需要将查询缓存作为执行流程中的一个阶段。

### Q：执行一条 SQL 请求的过程是什么

MySQL 执行一条 SQL 语句主要经过五个阶段。

首先是**连接器**，负责建立和管理连接、校验用户身份。

然后是**解析器**，对 SQL 进行词法分析和语法分析，并构建语法树。

接下来是**预处理器**，检查表和字段是否存在，并对 `SELECT *` 等语句进行处理。

随后是**优化器**，根据索引、统计信息和查询成本，选择预估成本较低的执行计划。

最后是**执行器**，根据执行计划调用存储引擎接口读取数据，并将结果返回客户端。

如果使用 InnoDB 存储引擎，底层还会涉及 B+ 树索引查找和 Buffer Pool 数据页缓存等机制。
