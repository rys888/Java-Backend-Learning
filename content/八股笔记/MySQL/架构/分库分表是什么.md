
**分库分表，就是当 MySQL 单个数据库或单张表的数据量太大、访问压力太高时，把数据拆分到多个数据库或多张表中。**

### **一、分表：把一张大表拆成多张小表**

假设有一张订单表：

```text
orders（1000 万条数据）
```

随着订单越来越多，查询和维护的成本可能越来越高。

这时候可以把订单表拆成：

```text
MySQL 数据库 A
│
├── orders_0（250 万条）
├── orders_1（250 万条）
├── orders_2（250 万条）
└── orders_3（250 万条）
```

例如，根据用户 ID 取模：

```java
int tableIndex = userId % 4;
```

如果：

- `userId = 1001` → `orders_1`
- `userId = 1002` → `orders_2`
- `userId = 1003` → `orders_3`

这样就可以根据用户 ID 定位到对应的订单表。

**核心作用：减少单张表的数据规模。**

但要注意，分表并不一定能解决数据库服务器的性能瓶颈，因为这些表可能仍然位于同一台服务器上。

---

### **二、分库：把数据拆到多个数据库中**

假设原来只有一台 MySQL 服务器：

```text
MySQL 服务器 A
│
└── orders（1000 万条）
```

随着业务量增加，服务器的 CPU、磁盘 I/O 等资源可能成为瓶颈。

这时候可以拆成：

```text
MySQL 服务器 A           MySQL 服务器 B
│                        │
└── orders_0             └── orders_1
    500 万条                 500 万条
```

例如：

```java
int dbIndex = userId % 2;
```

- `userId = 1001` → 数据库 B
- `userId = 1002` → 数据库 A

这样可以把数据和访问压力分散到不同的数据库服务器上。

**核心作用：分散单个数据库实例的存储和访问压力。**

---

### **三、分库和分表有什么区别？**

|**对比**|**分库**|**分表**|
|---|---|---|
|拆分对象|数据库|数据表|
|主要目的|分散数据库实例压力|减少单表数据规模|
|是否可以跨服务器|可以|可以，但不一定|
|举例|db _0、db_ 1|orders_ 0、orders_ 1|

实际上，分库和分表经常结合使用，称为**分库分表**。

例如：

```text
                 订单数据
                    │
             根据 userId 路由
                    │
          ┌─────────┴─────────┐
          ▼                   ▼
       数据库 A             数据库 B
          │                   │
     ┌────┴────┐         ┌────┴────┐
     ▼         ▼         ▼         ▼
  orders_0  orders_1   orders_2  orders_3
```

---
### Q：分库分表是什么

分库分表是指将原本集中存储的数据拆分到多个数据库或多张数据表中。

分表主要是为了解决单表数据量过大的问题，减少单表的数据规模。

分库主要是为了解决单个数据库实例的存储和访问压力问题，将数据分散到不同数据库实例上。

实际开发中可以通过用户 ID 取模等方式决定数据存储的位置。

**分表解决单表太大，分库解决单库压力太大，分库分表就是把数据拆开存储和处理。**
