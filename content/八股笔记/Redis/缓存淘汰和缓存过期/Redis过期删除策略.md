
[[#Q：]]

Redis 的过期删除策略主要就两种：**惰性删除和定期删除**。

这两个是配合着用的，一个省 CPU、一个省内存，合起来在 **CPU 性能和内存占用之间取平衡**。

## 一、惰性删除

**惰性删除：不主动去删过期 Key，等客户端来访问这个 Key 的时候，才顺手检查一下它过没过期。**

比如这条命令：

```redis
SET name "Eason" EX 10
```

表示 `name` 这个 Key 在 10 秒后过期。那么从 10:00:00 开始：

```text
10:00:00 → SET name "Eason" EX 10

10:00:10 → name 已经过期

10:00:20 → GET name
                │
                ▼
           检查是否过期
                │
                ▼
             已经过期
                │
                ▼
           删除并返回 nil
```

⚠️ 注意中间这一段：**10:00:10 到 10:00:20 之间，这个 Key 其实已经过期了，但它仍然占着内存**。因为没人访问，也就没人去触发那个检查。

### 优缺点

**优点**：不需要持续扫所有 Key，只在被访问的时候检查一次，省 CPU。

**缺点**：如果一个 Key 过期之后一直没人碰，它就可能长期占着内存。所以单靠惰性删除会造成内存浪费，必须再配一个主动清理的机制。

## 二、定期删除

**定期删除：Redis 周期性地抽样检查那些设置了过期时间的 Key，把其中已经过期的删掉。**

```text
Redis 中有 10000 个 Key
        │
        ▼
其中 5000 个设置了 TTL
        │
        ▼
Redis 周期性抽样检查
        │
        ▼
发现部分 Key 已经过期
        │
        ▼
删除这些过期 Key
```

为什么不直接检查所有 Key？因为 Redis 里可能存着几百万个 Key，每次都全量遍历一遍，CPU 直接就打满了。所以 Redis 用的是**抽样检查 + 时间预算控制**：每次只抽一部分来看，如果抽样发现过期 Key 的比例比较高，说明过期的数据还很多，就再接着清一轮，但整个过程有 CPU 时间上限，不会无限制地占着 CPU。

**优点**：能主动清掉那些长期没人访问的过期 Key，减少内存浪费，而且不用每次遍历全部 Key。

**缺点**：要消耗一部分 CPU；另外它是抽样，**不保证 Key 一到过期时间就立刻从内存里消失**。

## 三、为什么 Redis 不用定时删除？

第三种常见策略是**定时删除**：为每个设置了 TTL 的 Key 安排一个定时任务，到期立刻删除。比如：

- `name` → 10 秒后删除
- `age` → 20 秒后删除
- `city` → 30 秒后删除

这么做确实能及时释放内存，但如果 Redis 里有几百万个带 TTL 的 Key，就要同时维护几百万个定时任务，CPU 和调度开销都太高。所以 Redis 没有采用给每个 Key 单独挂一个定时器的方式。

## 四、三种删除策略对比

| 删除策略 | 删除时机 | 优点 | 缺点 |
|---|---|---|---|
| 定时删除 | Key 到期时 | 及时释放内存 | CPU 和调度开销大 |
| **惰性删除** | 访问 Key 时 | 节省 CPU | 可能浪费内存 |
| **定期删除** | 周期性抽样检查 | 平衡 CPU 和内存 | 不能保证立即删除 |

**Redis 实际采用的是：惰性删除 + 定期删除。**

## Q：

Redis 的过期删除策略主要有两种，惰性删除和定期删除。

**惰性删除**是指客户端访问某个 Key 时，Redis 才检查该 Key 是否过期，如果已经过期，就删除并返回不存在。

**定期删除**是指 Redis 周期性地从设置了过期时间的 Key 中抽样检查，并删除已经过期的 Key，同时通过时间预算控制 CPU 开销。

Redis 没有采用为每个 Key 单独设置定时器的方式，因为这样会带来较大的 CPU 和调度开销。

两者结合，就在 CPU 性能和内存占用之间取得了平衡。

## 六、和内存淘汰策略有什么区别？

| 对比 | 过期删除策略 | 内存淘汰策略 |
|---|---|---|
| 触发原因 | Key 已经过期 | Redis 内存达到 `maxmemory` 限制 |
| 删除对象 | 已过期的 Key | 根据淘汰策略选择的 Key |
| 主要目的 | 清理失效数据 | 释放内存空间 |
| 常见机制 | 惰性删除、定期删除 | LRU、LFU、Random、TTL |

举个例子，假设现在有三个 Key：

- Key A：TTL 已经过期
- Key B：TTL 还有 100 秒
- Key C：没有设置 TTL

**过期删除**管的是 Key A，因为它已经失效了。而如果此时内存达到了限制，**内存淘汰**按策略挑淘汰对象，Key B 甚至没设 TTL 的 Key C 都可能被淘汰掉。

**过期删除解决的是 Key 失效的问题，内存淘汰解决的是内存不够的问题。**
