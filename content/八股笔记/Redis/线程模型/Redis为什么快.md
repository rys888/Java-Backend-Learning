### **① 基于内存操作**

Redis 的数据主要存储在**内存（RAM）** 中，而 MySQL InnoDB 的数据主要持久化在磁盘上，通过 Buffer Pool 缓存热点数据。

例如：

```text
Redis 查询：
客户端 → 内存 → 返回结果

MySQL 查询：
客户端 → B+树索引 → Buffer Pool
                         │
                         └── 缓存未命中 → 磁盘读取
```

内存访问速度远快于磁盘，因此 Redis 可以快速完成数据读取和修改。

不过，MySQL 如果命中 Buffer Pool，也不需要读取磁盘。

**核心：Redis 主要在内存中完成数据操作，减少了磁盘 I/O 开销。**

---

### **② 单线程模型**

这里需要特别注意：

**Redis 并不是完全单线程，而是核心命令执行主要采用单线程模型。**

假设两个客户端同时发送命令：

```redis
客户端A：SET name "Eason"

客户端B：GET name
```

Redis 的核心命令执行线程会依次处理：

```text
客户端A ── SET ──┐
                 │
                 ▼
            Redis 主线程
                 │
客户端B ── GET ──┘
                 │
                 ▼
           依次执行命令
```

这样有什么好处？

如果多个线程同时修改同一份数据，就可能产生线程竞争，需要使用锁来保证线程安全。

而 Redis 的核心命令执行主要由单线程完成，因此：

- 避免了多个命令执行线程之间的锁竞争。
- 减少了线程上下文切换的开销。
- 简化了并发控制。

**但单线程不代表 Redis 只能同时服务一个客户端。**

另外，Redis 6.0 开始支持多线程处理部分网络 I/O，后台持久化、异步释放内存等任务也可以由其他线程或子进程完成。

**核心：单线程执行命令，减少锁竞争和线程切换开销。**

---

### **③ I/O 多路复用机制 

**既然 Redis 的核心命令执行是单线程，为什么还能同时处理成千上万个客户端连接？**

答案就是 **I/O 多路复用**。

假设有三个客户端：

```text
客户端A ─────┐
             │
客户端B ─────┼────→ Redis
             │
客户端C ─────┘
```

如果 Redis 为每个客户端创建一个线程，那么连接数量越多，线程数量也可能越多。

但 Redis 可以通过 I/O 多路复用机制，让一个线程监听多个客户端连接。

例如：

```text
客户端A ─────┐
             │
客户端B ─────┼──→ I/O 多路复用器
             │          │
客户端C ─────┘          ▼
                    Redis 主线程
                         │
                    执行就绪命令
```

假设：

- 客户端 A：暂时没有发送数据。
- 客户端 B：发送了 `GET name`。
- 客户端 C：暂时没有发送数据。

I/O 多路复用器会告诉 Redis：

**客户端 B 的连接已经有数据可以读取了！**

Redis 就处理 B 的请求，而不需要一直等待 A 或 C。

在 Linux 中，Redis 可以使用 `epoll` 等 I/O 多路复用机制。

**核心：一个线程可以高效管理大量客户端连接，只处理已经就绪的 I/O 事件，避免在没有数据的连接上阻塞等待。**

注意：I/O 多路复用并不是让 Redis 同时执行多条命令，而是让它能够高效管理大量网络连接。

### Q：

Redis 速度快主要有三个原因。

第一，Redis 是基于内存的数据库，大部分数据操作都在内存中完成，避免了频繁的磁盘 I/O。

第二，Redis 的核心命令执行采用单线程模型，避免了多线程之间的锁竞争和上下文切换开销。但 Redis 并不是完全单线程，例如 Redis 6.0 引入了多线程网络 I/O。

第三，Redis 使用 I/O 多路复用机制，可以通过一个线程高效监听多个客户端连接，只处理已经就绪的 I/O 事件，从而支持大量并发连接。


**不过还要补充一点：Redis 的高性能也离不开 HashTable、跳表等高效数据结构。**

另外，单线程并不意味着任何情况下都更快。Redis 的优势是大多数命令执行时间短，适合通过单线程快速处理；如果执行耗时较长的命令，反而可能阻塞其他请求。
