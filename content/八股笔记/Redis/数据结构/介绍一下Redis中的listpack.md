
**Listpack（紧凑列表）是 Redis 为了节省内存设计的一种底层数据结构。**

它的核心思想是：**将多个元素紧凑地存储在一块连续内存中，减少额外的内存开销。**

### **一、Listpack 长什么样？**

假设 Redis 需要存储三个元素：

```text
Tom、Jack、Eason
```

Listpack 的结构可以简化为：

```text
┌──────────────┬──────────────┬──────────────┬──────────────┬─────┐
│   Header     │    Entry 1   │    Entry 2   │    Entry 3   │ End │
├──────────────┼──────────────┼──────────────┼──────────────┼─────┤
│ 总字节数等信息 │     Tom      │     Jack     │    Eason     │结束标记│
└──────────────┴──────────────┴──────────────┴──────────────┴─────┘
```

它主要由三部分组成：

1. **Header（头部）**：记录整个 Listpack 的字节数和元素数量等信息。
2. **Entry（元素）**：存储实际的数据。
3. **End（结束标记）**：表示 Listpack 结束。

每个 Entry 内部还包含数据编码、实际数据和当前 Entry 的长度信息。

### **二、为什么 Redis 要使用 Listpack？**

假设我们要存储三个字符串：

```text
Tom → Jack → Eason
```

如果使用普通链表，每个节点除了保存数据，还需要保存指针：

```text
┌─────────────┐
│ Tom         │
│ prev / next │
└─────────────┘
       ↓
┌─────────────┐
│ Jack        │
│ prev / next │
└─────────────┘
       ↓
┌─────────────┐
│ Eason       │
│ prev / next │
└─────────────┘
```

这些指针和独立的内存分配都会产生额外开销。

而 Listpack 将元素紧凑存储：

```text
┌─────┬──────┬───────┐
│ Tom │ Jack │ Eason │
└─────┴──────┴───────┘
```

**因此，Listpack 的主要优势是节省内存，同时具有较好的缓存局部性。**

不过，它也存在缺点：

- 查找指定元素通常需要遍历，时间复杂度为 O(N)。
- 在中间插入或删除元素，可能需要移动后续数据。
- 数据量较大时，操作效率可能下降。

### **三、Redis 哪些数据类型使用 Listpack？**

以 Redis 7.x 为例：

|**Redis 数据类型**|**Listpack 的作用**|
|---|---|
|Hash|存储元素较少、字段和值较短的哈希|
|ZSet|存储元素较少、成员较短的有序集合|
|List|作为 Quicklist 节点内部的数据容器|

例如，一个小型 Hash：

```text
user:1
  name → Eason
  age  → 20
```

可以通过 Listpack 紧凑存储：

```text
┌──────┬───────┬─────┬────┐
│ name │ Eason │ age │ 20 │
└──────┴───────┴─────┴────┘
```

当 Hash 的数据规模或元素长度超过配置阈值时，Redis 会将其转换为 HashTable。

### **五、面试怎么回答？⭐⭐⭐⭐⭐**

Listpack 是 Redis 的一种紧凑列表结构，主要用于优化内存使用。

它将多个元素连续存储在一块内存中，减少指针和内存分配带来的额外开销。

在 Redis 7.x 中，Hash 和 ZSet 在满足一定条件时可以使用 Listpack，List 的 Quicklist 节点内部也使用 Listpack。

Listpack 相比早期的 Ziplist，解决了由于记录前一个节点长度而导致的连锁更新问题。

但由于采用连续内存存储，中间插入和删除可能需要移动数据，因此更适合存储规模较小的数据。

**一句话记忆：Listpack = 连续内存 + 紧凑存储，优点是省内存，缺点是大规模数据的插入、删除和查找效率不高。**
