
**跳表（Skiplist）的本质，就是在普通有序链表的基础上，增加多级索引，让查找数据时可以跳过大量节点。**

### **① 普通链表有什么问题？**

假设有一个按照分数排序的链表：

```text
10 → 20 → 30 → 40 → 50 → 60 → 70 → 80
```

如果想找到 `70`，就需要从 `10` 开始，一个一个往后找。

**时间复杂度：O(N)。**

### **② 跳表是怎么实现的？**

跳表会在原来的链表上建立多层索引：

```text
第3层：10 ───────────────────────→ 80
        │                          │
第2层：10 ─────→ 30 ─────→ 50 ────→ 80
        │        │        │         │
第1层：10 → 20 → 30 → 40 → 50 → 60 → 70 → 80
```

每个节点可以拥有多个层级的前进指针。

**层数越高，节点越少，每次可以跳过的元素通常越多。**

### **③ 跳表怎么查找数据？**

假设我们要查找 `70`。

从最高层开始：

**第一步：** 第 3 层

```text
10 ─────────────────→ 80
```

发现 `80 > 70`，不能继续向右，于是向下一层查找。

**第二步：** 第 2 层

```text
10 → 30 → 50 → 80
```

从 `10` 依次跳到 `30`、`50`。

发现下一个节点 `80 > 70`，于是向下一层。

**第三步：** 第 1 层

```text
50 → 60 → 70
```

最终找到 `70`。

这样就不需要逐个遍历所有节点。

**平均时间复杂度：O(log N)。**

---

### **④ 跳表怎么插入数据？**

假设要插入 `45`：

原来的链表：

```text
10 → 20 → 30 → 40 → 50 → 60
```

首先通过跳表快速找到插入位置：

```text
40 → 45 → 50
```

然后 Redis 会通过随机算法决定新节点拥有多少层索引。

例如随机得到 2 层：

```text
第2层：10 ─────→ 30 ─────→ 45 ─────→ 60
第1层：10 → 20 → 30 → 40 → 45 → 50 → 60
```

**这里有一个重要知识点：跳表通过随机算法决定节点层数，而不是每插入一个节点就重新建立全部索引。**

因此，跳表的插入和删除平均时间复杂度也是 O(log N)。

---

### **⑤ Redis 为什么使用跳表实现 ZSet？**

因为 ZSet 需要根据 Score 排序。

例如：

```text
Tom：100
Jack：150
Eason：200
```

跳表可以按照 Score 维护顺序：

```text
Tom(100) → Jack(150) → Eason(200)
```

这样 Redis 就能够高效实现：

- **按分数查找**：快速定位某个分数附近的节点。
- **范围查询**：例如查询 100～200 分的用户。
- **排行榜**：获取排名前 10 的用户。
- **动态更新**：用户分数变化后，调整其排序位置。

需要注意，Redis 的 ZSet 还会配合哈希表，实现根据 Member 快速查询 Score。

### Q：

跳表是在有序链表的基础上增加多级索引的一种数据结构。

普通链表查找需要从头遍历，时间复杂度是 O(N)，而跳表通过多级索引，可以从高层开始查找，逐层向下定位目标节点，将平均查找时间复杂度降低到 O(log N)。

在插入节点时，跳表通过随机算法决定节点的层数，不需要像平衡树一样进行旋转操作。

Redis 使用跳表实现 ZSet 的有序存储，支持高效的范围查询、排名和动态更新。

**一句话记忆：跳表 = 有序链表 + 多级索引，通过空间换时间，实现平均 O(log N) 的查找效率。**
