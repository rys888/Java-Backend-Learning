**ZSet（Sorted Set，有序集合）是 Redis 的一种数据类型，特点是元素不能重复，但每个元素都有一个 Score（分数），Redis 会根据 Score 自动排序。**

它的底层主要使用 **Listpack 或跳表（Skiplist）+ 哈希表（HashTable）** 实现。

## **一、ZSet 长什么样子？**

假设我们要实现一个游戏排行榜：

```redis
ZADD ranking 100 "Tom" 200 "Eason" 150 "Jack"
```

Redis 中的数据可以理解为：

```text
Key：ranking

┌──────────┬─────────┐
│  Member  │  Score  │
├──────────┼─────────┤
│  Tom     │   100   │
│  Jack    │   150   │
│  Eason   │   200   │
└──────────┴─────────┘
```

这里有两个重要概念：

- **Member（成员）**：例如 Tom、Jack、Eason，不能重复。
- **Score（分数）**：例如 100、150、200，可以重复。

ZSet 默认按照 Score 从小到大排序。

例如：

```redis
ZRANGE ranking 0 -1
```

返回：

```text
Tom
Jack
Eason
```

如果要查看分数最高的玩家：

```redis
ZREVRANGE ranking 0 0
```

返回：

```text
Eason
```

## **二、ZSet 底层是怎么实现的

在 Redis 7.x 中，ZSet 主要有两种底层实现。

### **① Listpack（紧凑列表）**

当 ZSet 元素数量较少、成员长度较短时，可以使用 Listpack。

例如：

```text
┌─────┬─────┬───────┬─────┬───────┬─────┐
│ Tom │ 100 │ Jack  │ 150 │ Eason │ 200 │
└─────┴─────┴───────┴─────┴───────┴─────┘
```

可以简单理解为将成员和分数紧凑地存储在一块连续内存中。

**优点：节省内存。**

但是随着元素数量增加，查找和插入的成本也会增加。

因此，数据规模较大时，Redis 通常会使用另一种实现。

### **② 跳表 + 哈希表**

这是 ZSet 最重要的底层实现。

**为什么需要同时使用两种数据结构？**

因为 ZSet 既需要：

1. 根据 Member 快速查询 Score。
2. 根据 Score 高效排序和范围查询。

所以 Redis 使用：

**哈希表：负责快速查找成员的分数。**

```text
HashTable

Tom   → 100
Jack  → 150
Eason → 200
```

通过哈希表，根据 Member 查找 Score 的平均时间复杂度是 O(1)。

**跳表：负责按照 Score 排序。**

假设有以下分数：

```text
10 → 20 → 30 → 40 → 50 → 60 → 70 → 80
```

普通链表只能逐个查找。

跳表则增加了多级索引：

```text
第3层：10 ───────────────────────→ 80
         │                          │
第2层：10 ─────→ 30 ─────→ 50 ────→ 80
         │        │        │         │
第1层：10 → 20 → 30 → 40 → 50 → 60 → 70 → 80
```

例如查找 70：

- 从最高层开始查找。
- 利用高层索引跳过部分节点。
- 逐层向下，最终找到 70。

这样就不用每次从头遍历所有元素。

**跳表查找、插入、删除的平均时间复杂度都是 O(log N)。**

而且跳表还支持按照 Score 进行范围查询，非常适合排行榜。

## **三、为什么 ZSet 不直接使用 HashTable？**

因为 **HashTable 虽然查找速度快，但无法直接按照 Score 排序。**

例如：

```text
Tom   → 100
Jack  → 150
Eason → 200
```

如果只有 HashTable，想查询分数最高的前 10 名，就需要额外处理排序。

而跳表本身就按照 Score 有序排列，因此可以高效获取排行榜。

所以两者各有分工：

|**底层结构**|**主要作用**|
|---|---|
|**HashTable**|根据 Member 快速查找 Score|
|**Skiplist**|根据 Score 排序、范围查询|
|**Listpack**|数据量较小时节省内存|

注意：**小型 ZSet 使用 Listpack 时，并不会同时使用跳表和哈希表。**

### Q：

ZSet 是 Redis 的有序集合，每个元素都有一个 Score，元素不能重复，但是 Score 可以重复，Redis 会按照 Score 对元素排序。

在 Redis 7.x 中，ZSet 底层主要使用 Listpack 或跳表加哈希表实现。

当数据量较小时，使用 Listpack 节省内存；当数据量较大时，使用跳表加哈希表。

其中哈希表用于根据 Member 快速查询 Score，跳表用于按照 Score 排序和范围查询，查找、插入和删除的平均时间复杂度为 O(log N)。

因此，ZSet 特别适合实现排行榜等需要排序的业务场景。

**ZSet = Member + Score；小数据用 Listpack，大数据用跳表 + 哈希表，哈希表负责查找，跳表负责排序。**
