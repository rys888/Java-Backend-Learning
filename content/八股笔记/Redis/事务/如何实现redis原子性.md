
[[#Q：]]

Redis 实现原子性主要有三种方式：**单条命令、Lua 脚本、事务（MULTI/EXEC）**。

先说原子性是什么。**原子性就是一个操作不可被其他操作打断**，一次操作要么完整做完，中间不会插进来别的操作。

### ① 单条 Redis 命令天然具有原子性

Redis 的核心命令执行采用单线程模型，一条命令在执行过程中不会被其他客户端的命令插进来。比如：

```redis
INCR stock
```

即使 100 个客户端同时执行 `INCR stock`，Redis 也会依次处理，不会因为并发导致计数丢失。

但如果要执行多条命令：

```redis
GET stock
SET stock 100
```

**这两条命令组合起来并不具有原子性**，因为其他客户端的命令可能刚好在这两条命令之间执行。

### ② Lua 脚本保证多条命令的原子性 

假设要实现秒杀库存扣减，业务要求是：判断库存是否大于 0，如果大于 0 就减 1。如果拆成两条 Redis 命令来做：

```text
客户端A：GET stock → 1
客户端B：GET stock → 1

客户端A：DECR stock → 0
客户端B：DECR stock → -1
```

就可能出现超卖。

**解决方案是把两步操作写进 Lua 脚本。**

```lua
local stock = tonumber(redis.call('GET', KEYS[1]))

if stock == nil or stock <= 0 then
    return 0
end

redis.call('DECR', KEYS[1])
return 1
```

Redis 执行 Lua 脚本时，不会在脚本执行过程中插入其他客户端的命令，所以：

```text
客户端A → Lua脚本 → 库存 1 → 0（成功）

客户端B → Lua脚本 → 库存 0（失败）
```

**Lua 脚本可以保证多条 Redis 操作连续执行，不被其他命令打断。** 这也是 Java 后端秒杀、限量预约这类业务经常用 Lua 的原因。

### ③ Redis 事务（MULTI / EXEC）

Redis 也提供事务机制：

```redis
MULTI

DECR stock
INCR sold

EXEC
```

执行过程是这样：`MULTI` 开启事务，后面的 `DECR stock`、`INCR sold` 不会立即执行，而是先加入队列，最后 `EXEC` 再依次执行队列里的命令。**Redis 保证 EXEC 执行事务队列时，不会插入其他客户端的命令。**

⚠️ 但这里要注意，**Redis 事务和 MySQL 事务不一样，它不支持 MySQL 那样的自动回滚**。比如第一条命令执行成功，第二条命令运行时发生错误，Redis 不会自动撤销第一条命令。Lua 脚本同样不提供自动回滚：脚本执行到一半报错，之前成功执行的写操作也不会自动撤销。

### Q：

Redis 实现原子性主要有三种方式。单条命令天然具有原子性，因为核心命令采用单线程执行，不会被其他命令打断；Lua 脚本可以把多条 Redis 命令组合起来执行，保证执行过程中不会被其他客户端的命令插入，常用于秒杀库存扣减这类场景；MULTI 和 EXEC 实现的 Redis 事务能保证事务中的命令连续执行，但不支持自动回滚。因此，在需要多步判断和修改的业务场景下，通常会优先考虑 Lua 脚本。

**单条命令本身具有原子性，多条命令可以通过 Lua 脚本或 Redis 事务保证执行过程不被其他命令打断，但不等于支持失败自动回滚。**
