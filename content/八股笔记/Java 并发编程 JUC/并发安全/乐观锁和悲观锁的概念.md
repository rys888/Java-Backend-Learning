
**悲观锁和乐观锁是两种并发控制思想。**

悲观锁认为并发冲突发生概率较高，因此在操作共享资源之前先加锁，其他线程需要等待，例如 Java 中的 synchronized、ReentrantLock。

乐观锁认为冲突概率较低，因此通常不会提前阻塞其他线程，而是在更新数据时检查数据是否被其他线程修改过。如果没有修改则更新成功，如果发生冲突则失败、重试或者进行其他处理。Java 中 CAS 是典型的乐观并发思想，数据库中也可以通过 version 版本号实现乐观锁。

悲观锁适合竞争比较激烈的场景；乐观锁在竞争较少时可以减少阻塞，但竞争激烈时可能因为不断重试而浪费 CPU。


CAS：
只有当变量当前值等于预期值时，才执行更新，否则重新尝试或返回失败。
因此，可以在不使用传统互斥锁的情况下，实现某些线程安全操作。

CAS 是一种原子操作，包含 3 个操作数：内存位置 v、预期原值 A 和新值 B。执行时，只有当 v 的值等于 A 时，才将 v 更新为 B，否则不更新。整个过程原子
