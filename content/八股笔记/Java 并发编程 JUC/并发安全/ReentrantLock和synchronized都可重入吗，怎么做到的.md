
`synchronized` 和 `ReentrantLock` 都是可重入锁。

可重入指的是同一个线程已经持有某把锁时，可以再次获取这把锁，而不会发生自我阻塞。

`synchronized` 的可重入性由 JVM 的锁机制实现。JVM 会维护锁的持有线程和重入计数，同一个线程重复进入同步区域时，允许再次获取锁，并增加相应的计数；退出同步区域时减少计数，全部退出后才释放锁。

`ReentrantLock` 则基于 AQS 实现，通过 `state` 记录锁的重入次数，同时记录当前持有锁的线程。第一次获取锁时通过 CAS 等机制竞争，之后如果发现当前线程就是锁的持有者，就直接增加 `state`。每次调用 `unlock()` 会减少 `state`，直到变为 0 才真正释放锁。

两者的核心原理都是**识别当前线程是否已经持有锁，并维护重入次数**，区别在于一个由 JVM 实现，另一个基于 AQS 实现。

`synchronized` 靠 JVM 的锁所有权和重入计数， `ReentrantLock` 靠 AQS 的 Owner 和 state；同一线程可以重复加锁，但必须全部解锁后，其他线程才能获得锁。
