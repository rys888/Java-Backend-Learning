这个问题和刚学的 `wait()` / `notify()` 正好连起来。

Java 中线程间通信，常见可以记成 **5 类**：

1. **共享变量**
2. **wait / notify / notifyAll**
3. **Condition**
4. **阻塞队列 BlockingQueue**
5. **并发工具类 / Future 等**

其中面试最经典的是 `wait()`  **+** `notify()` **。

---

## **1. 共享变量：最基础**

两个线程本来就在同一个 JVM 进程里，可以访问共享对象：

```java
class Task {
    volatile boolean running = true;
}
```

线程 A：

```java
while (task.running) {
    // 工作
}
```

线程 B：

```java
task.running = false;
```

过程：

```text
线程A                    共享变量                  线程B
  │                     running=true               │
  │                          │                      │
  └──────读取───────────────→│←────修改为false──────┘
                             │
线程A发现 false ←─────────────┘
      ↓
    停止
```

这里 `volatile` 保证可见性。

你上一轮学的：

```java
thread.interrupt();
```

本质上也是线程之间进行协作/通知的一种机制。

---

## **2. wait + notify ⭐⭐⭐⭐⭐**

这是最经典的线程通信。

例如消费者：

```java
synchronized (lock) {

    while (!condition) {
        lock.wait();
    }

    // 条件满足，继续执行
}
```

生产者：

```java
synchronized (lock) {

    condition = true;

    lock.notifyAll();
}
```

过程就是你刚理解的：

```text
消费者
  ↓
拿到 lock
  ↓
发现条件不满足
  ↓
wait()
  ↓
释放锁
  ↓
WAITING 💤


生产者
  ↓
拿到 lock
  ↓
修改条件
  ↓
notifyAll()
  ↓
通知消费者


消费者
  ↓
被唤醒
  ↓
重新竞争 lock
  ↓
拿到锁
  ↓
重新检查条件
  ↓
继续执行
```

所以：

`wait()` = 我条件不满足，先等。`notify()` = 条件可能变化了，叫醒一个。`notifyAll()` = 把等待这个 monitor 的线程都叫醒。

---

## **3. Condition**

`Condition` 可以理解成：

**Lock 体系中的 wait / notify。**

`synchronized` 搭配：

```text
wait()
notify()
notifyAll()
```

而：

```java
ReentrantLock
```

通常搭配：

```text
await()
signal()
signalAll()
```

例如：

```java
Lock lock = new ReentrantLock();
Condition condition = lock.newCondition();
```

等待：

```java
lock.lock();

try {
    condition.await();
} finally {
    lock.unlock();
}
```

通知：

```java
lock.lock();

try {
    condition.signal();
} finally {
    lock.unlock();
}
```

对应关系很好记：

|**synchronized**|**ReentrantLock + Condition**|
|---|---|
| `wait()` | `await()` |
| `notify()` | `signal()` |
| `notifyAll()` | `signalAll()` |

而且 `Condition` 可以创建多个等待条件，比单纯的 `wait/notify` 更灵活。

---

## **4. BlockingQueue ⭐⭐⭐⭐⭐**

实际开发里，如果是：

**一个线程生产数据，另一个线程消费数据**

通常没必要自己手搓 `wait/notify`。

可以直接：

```java
BlockingQueue<String> queue =
        new ArrayBlockingQueue<>(10);
```

生产者：

```java
queue.put("Java");
```

消费者：

```java
String data = queue.take();
```

它自动帮你处理：

```text
生产者
  ↓
put()
  ↓
BlockingQueue
  ↓
消费者
  ↓
take()
```

如果队列空：

```text
消费者 take()
     ↓
没有数据
     ↓
自动等待
```

如果队列满：

```text
生产者 put()
     ↓
没有空间
     ↓
自动等待
```

所以它特别适合：

**生产者—消费者模型。**

你后面学习线程池的时候会发现：

```java
ThreadPoolExecutor
```

里面就有一个非常重要的：

```java
BlockingQueue<Runnable> workQueue
```

用于在线程之间传递/缓存待执行任务。

## **5. 并发工具类**

Java 还提供了一堆专门协调线程的工具。

比如：

### **CountDownLatch**

一个线程：

“等其他几个线程都完成，我再继续。”

```text
主线程
  │
  │ await()
  ↓
等待
  │
  ├──── 线程A完成 → countDown()
  ├──── 线程B完成 → countDown()
  └──── 线程C完成 → countDown()
                  ↓
                计数=0
                  ↓
              主线程继续
```

---

### **Semaphore**

控制：

**最多允许多少个线程同时访问某个资源。**

比如：

```text
数据库连接只有 10 个

100个线程
   ↓
Semaphore(10)
   ↓
最多10个同时进去
```

---

### **CyclicBarrier**

多个线程：

**大家都执行到某个位置以后，再一起继续。**

类似：

```text
线程A ─────→ │
线程B ─────→ │集合点│ → 大家继续
线程C ─────→ │
```

这些严格来说更多是**线程协调工具**。

---

## **6. Future / CompletableFuture**

如果一个线程需要获取另一个异步任务的执行结果：

```java
Future<Integer> future =
    pool.submit(() -> 100);
```

然后：

```java
Integer result = future.get();
```

也属于线程之间进行结果传递/协作的一种方式。

你之前学过的：

```java
CompletableFuture
```

则更适合复杂的异步任务编排。

# **面试最重要的知识图**

你不用把所有东西都叫“通信方式”死背，理解成线程之间的**数据共享 + 通知 + 协调**：

```text
              Java线程间通信/协作
                      │
       ┌──────────────┼──────────────┐
       ↓              ↓              ↓
    共享数据         等待/通知        数据传递
       │              │              │
   volatile       wait/notify    BlockingQueue
   Atomic类       Condition         Future
       │
       ↓
   状态可见


另外还有线程协调工具：

CountDownLatch
Semaphore
CyclicBarrier
```

### Q：Java 线程之间有哪些通信方式？

Java 线程之间最基础的是通过共享内存进行通信，需要使用 volatile、锁等机制保证可见性和线程安全；还可以通过 `wait/notify/notifyAll` 实现等待通知机制。


使用 `ReentrantLock` 时可以配合 `Condition` 的 `await/signal`。实际生产者消费者场景通常可以使用 `BlockingQueue` 在线程之间安全传递数据。此外还有 `CountDownLatch`、`Semaphore`、`CyclicBarrier` 等并发工具进行线程协调，以及 Future、CompletableFuture 等进行异步结果传递。
