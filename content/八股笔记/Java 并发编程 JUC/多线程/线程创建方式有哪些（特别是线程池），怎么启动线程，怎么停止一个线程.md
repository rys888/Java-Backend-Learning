
[[#Q：Java 创建线程有哪些方式？怎么启动和停止线程？]]

这三个问题正好可以一起学：

**怎么创建线程 → 怎么启动 → 怎么优雅停止。**

其中面试最重要的是：**实际开发通常通过线程池管理线程，而不是业务代码里频繁** ** `new Thread()` ****。**

---

# **一、Java 创建/执行线程有哪些方式？**

八股里经常说“四种”：

```text
1. 继承 Thread
2. 实现 Runnable
3. Callable + FutureTask
4. 线程池 ⭐⭐⭐⭐⭐
```

严格来说，后面几种更多是“提交任务并由线程执行”的方式，但面试这么回答没问题。

## **1. 继承 Thread**

```java
class MyThread extends Thread {

    @Override
    public void run() {
        System.out.println("执行任务");
    }
}
```

使用：

```java
MyThread thread = new MyThread();

thread.start();
```

注意：

```text
start()  → 启动新线程 → 新线程执行 run()  ✅

run()    → 普通方法调用 → 不会创建新线程 ❌
```

流程：

```text
main线程
   ↓
thread.start()
   ↓
JVM启动新线程
   ↓
OS调度
   ↓
新线程执行 run()
```

---

# **二、实现 Runnable**

更常见：

```java
class MyTask implements Runnable {

    @Override
    public void run() {
        System.out.println("执行任务");
    }
}
```

然后：

```java
Thread thread = new Thread(new MyTask());

thread.start();
```

现在一般直接 Lambda：

```java
Thread thread = new Thread(() -> {
    System.out.println("执行任务");
});

thread.start();
```

相比继承 `Thread`，Runnable 把：

```text
任务
和
线程
```

分离了。

也就是：

```text
Runnable
   ↓
“要干什么”

Thread
   ↓
“谁来执行”
```

---

# **三、Callable + FutureTask**

前面的 `Runnable`：

```java
public void run()
```

最大的问题之一：

**没有返回值。**

如果我们希望：

```text
线程执行任务
    ↓
计算结果
    ↓
返回结果
```

可以使用 `Callable`：

```java
Callable<Integer> task = () -> {
    return 100;
};
```

但 `Thread` 不能直接：

```java
new Thread(task); // Callable不能直接这么传
```

可以通过 `FutureTask`：

```java
FutureTask<Integer> futureTask =
        new FutureTask<>(task);

Thread thread = new Thread(futureTask);

thread.start();
```

获取结果：

```java
Integer result = futureTask.get();
```

所以：

```text
Callable
   ↓
描述有返回值的任务
   ↓
FutureTask
   ↓
包装任务、保存结果
   ↓
Thread
   ↓
执行
```

`get()` 如果结果还没出来，通常会等待。

---

# **四、线程池 ⭐⭐⭐⭐⭐**

这个才是实际 Java 后端最需要重点掌握的。

假设每来一个任务都：

```java
new Thread(task).start();
```

10000 个任务：

```text
任务1 → new Thread
任务2 → new Thread
任务3 → new Thread
...
任务10000 → new Thread
```

线程创建、销毁都需要资源，而且线程太多还会产生大量调度、上下文切换和内存开销。

所以：

**提前维护一定数量的线程，任务来了复用这些线程。**

这就是线程池。

```text
             任务
              ↓
       ┌──────────────┐
       │   线程池      │
       │              │
       │ Thread 1     │
       │ Thread 2     │
       │ Thread 3     │
       │ Thread 4     │
       └──────────────┘
              ↓
           执行任务
              ↓
       执行完不销毁
              ↓
       继续等待新任务
```

核心好处：

**线程复用 + 控制线程数量 + 统一管理任务和线程资源。**

---

# **五、线程池怎么创建？**

简单学习时可能看到：

```java
ExecutorService pool =
        Executors.newFixedThreadPool(4);
```

然后：

```java
pool.execute(() -> {
    System.out.println("执行任务");
});
```

但是面试非常喜欢问：

**实际项目为什么不推荐直接通过 Executors 创建线程池？**

因为某些快捷工厂方法的默认配置可能导致任务队列或线程数量增长过大，从而带来资源耗尽风险。

因此实际项目通常更推荐根据业务明确配置：

```java
ThreadPoolExecutor
```

例如：

```java
ThreadPoolExecutor pool =
    new ThreadPoolExecutor(
        4,
        8,
        60,
        TimeUnit.SECONDS,
        new ArrayBlockingQueue<>(100)
    );
```

你马上就会学到线程池最经典的 **7 大参数**，这是线程池八股的核心。

# **六、线程池怎么“启动线程”？**

这是一个很重要的区别。

普通 Thread：

```java
thread.start();
```

线程池不是：

```java
pool.start(); // ❌
```

而是**提交任务**：

```java
pool.execute(task);
```

或者：

```java
pool.submit(task);
```

线程池内部负责：

创建/复用工作线程并执行任务。

所以：

```text
普通线程：

Thread
 ↓
start()
 ↓
run()


线程池：

任务
 ↓
execute / submit
 ↓
ThreadPoolExecutor
 ↓
工作线程
 ↓
执行任务
```

---

# **七、execute 和 submit 有什么区别？**

简单记：

### **execute**

```java
pool.execute(() -> {
    System.out.println("任务");
});
```

主要用于：

**不需要返回结果的任务。**

---

### **submit**

```java
Future<Integer> future = pool.submit(() -> {
    return 100;
});
```

可以获得：

```java
Integer result = future.get();
```

所以：

```text
execute
→ 没有 Future 返回结果

submit
→ 返回 Future
→ 可以获取结果/异常等
```

# **八、怎么停止一个线程？⭐⭐⭐⭐⭐**

这里非常容易答错。

以前有：

```java
thread.stop();
```

但是：

** `Thread.stop()` ** **已经被废弃，不应该使用。**

因为它可能在线程执行到任意位置时强制终止线程，容易破坏数据一致性。

例如：

```text
线程：
修改A
 ↓
修改B
 ↓
修改C
```

执行到：

```text
修改A完成
 ↓
stop()
```

直接没了。

于是：

```text
A = 新数据
B = 旧数据
C = 旧数据
```

数据可能处于不一致状态。

---

# **九、正确停止方式：interrupt ⭐⭐⭐⭐⭐**

Java 更推荐：

**协作式取消。**

也就是：

“我不是直接杀死你，而是告诉你应该停止了，由线程自己在合适的位置退出。”

使用：

```java
thread.interrupt();
```

它不是简单等于：

```text
立刻杀死线程 ❌
```

而是发出：

**中断请求。**

线程可以检查：

```java
Thread.currentThread().isInterrupted()
```

例如：

```java
while (!Thread.currentThread().isInterrupted()) {

    // 执行任务
}
```

外部：

```java
thread.interrupt();
```

流程：

```text
线程A：

while(...)
  ↓
工作
  ↓
检查中断状态
  ↓
工作
  ↓
检查中断状态


线程B：

thread.interrupt()
       ↓
设置/触发中断语义
       ↓

线程A检测到
       ↓
主动结束循环
       ↓
run()结束
       ↓
线程结束
```

这就是：

**协作式停止。**

# **十、sleep 时 interrupt 怎么办？**

例如：

```java
try {

    while (!Thread.currentThread().isInterrupted()) {

        Thread.sleep(1000);

        System.out.println("工作");
    }

} catch (InterruptedException e) {

    Thread.currentThread().interrupt();
}
```

如果线程正在：

```java
sleep()
```

这时候其他线程：

```java
thread.interrupt();
```

会让 `sleep()` 抛：

```java
InterruptedException
```

而且抛出该异常时，中断状态会被清除。

所以很多情况下 catch 后如果不打算直接结束方法，会重新：

```java
Thread.currentThread().interrupt();
```

把中断状态恢复，让上层逻辑知道：

**这个线程被要求中断过。**

---

# **十一、也可以使用 volatile 标志位**

例如：

```java
private volatile boolean running = true;
```

线程：

```java
while (running) {
    // 工作
}
```

停止：

```java
running = false;
```

因为：

```text
volatile
  ↓
保证可见性
  ↓
线程能观察到 running=false
```

于是退出。

但是如果线程阻塞在：

```java
sleep()
wait()
某些阻塞操作
```

单纯：

```java
running = false;
```

可能不能及时唤醒它。

所以很多场景更适合使用：

```java
interrupt()
```

---

# **十二、线程池怎么停止？⭐⭐⭐⭐⭐**

线程池不要一个个：

```text
thread1.interrupt()
thread2.interrupt()
thread3.interrupt()
```

通常通过线程池：

```java
pool.shutdown();
```

含义：

**不再接收新任务，但已经提交的任务继续执行，执行完后关闭。**

而：

```java
pool.shutdownNow();
```

则会：

尝试中断正在执行的任务，并返回队列中尚未开始的任务。

注意：

`shutdownNow()` 也是**尝试中断**，并不保证能暴力杀死所有线程。

任务代码仍然应该正确响应 `interrupt`。

# **十三、把整个知识体系串起来**

```text
Java线程执行任务
        │
 ┌──────┼─────────┐
 ↓      ↓         ↓
Thread Runnable  Callable
                  ↓
              FutureTask
        │
        ↓
   更推荐线程池
        ↓
ThreadPoolExecutor
        │
   ┌────┴────┐
   ↓         ↓
execute    submit
             ↓
           Future


启动：
Thread → start()
线程池 → execute()/submit()


停止：
Thread.stop() ❌

推荐：
interrupt() ✅
协作式停止

线程池：
shutdown()
shutdownNow()
```

### Q：Java 创建线程有哪些方式？怎么启动和停止线程？

Java 常见的线程任务执行方式包括继承 Thread、实现 Runnable、使用 Callable 配合 FutureTask，以及通过线程池执行任务。实际开发中通常更推荐使用线程池，因为它可以复用线程、控制线程数量并统一管理资源。

普通 Thread 通过 `start()` 启动，不能直接调用 `run()` 来达到启动新线程的效果；线程池则通过 `execute()` 或 `submit()` 提交任务。

停止线程不推荐使用已经废弃的 `Thread.stop()`，通常采用协作式中断，通过 `interrupt()` 发出中断请求，由线程检查中断状态或处理 `InterruptedException` 后安全退出。线程池可以通过 `shutdown()` 平滑关闭，或者通过 `shutdownNow()` 尝试中断正在执行的任务。
