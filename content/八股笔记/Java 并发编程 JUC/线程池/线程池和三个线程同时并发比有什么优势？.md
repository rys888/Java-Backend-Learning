
[[#Q：为什么使用线程池，而不是直接 new Thread？]]

如果你说的“三个线程同时并发”是这种：

```java
new Thread(task1).start();
new Thread(task2).start();
new Thread(task3).start();
```

那和“线程池里有 3 个线程”相比，**单看这一次只执行 3 个任务，性能差距可能并不大**。线程池真正的优势是在**任务不断到来**的时候体现出来。

最核心区别：

**手动创建线程：一个任务来了，我创建一个线程；任务结束，线程也结束。**  
**线程池：线程提前/按需创建后可以反复执行不同任务。**

比如现在有 1000 个任务。

直接创建线程：

```text
Task1 → 创建 Thread1 → 执行 → 销毁
Task2 → 创建 Thread2 → 执行 → 销毁
Task3 → 创建 Thread3 → 执行 → 销毁
...
Task1000 → 创建 Thread1000
```

会产生大量：

```text
创建线程
销毁线程
线程调度
上下文切换
内存占用
```

而假设线程池只有 3 个 Worker：

```text
              1000个任务
                  ↓
           BlockingQueue
                  ↓
        ┌─────────┼─────────┐
        ↓         ↓         ↓
    Thread1    Thread2    Thread3
       ↓          ↓          ↓
    Task1      Task2       Task3
       ↓          ↓          ↓
    Task4      Task5       Task6
       ↓          ↓          ↓
     ...        ...         ...
```

三个线程不断：

```text
取任务 → 执行 → 取下一个 → 执行……
```

所以线程池第一个优势就是：

**① 线程复用，减少频繁创建和销毁线程的开销。**

但还有一个更重要的优势：

**② 控制线程数量，避免资源耗尽。**

假如突然来了：

```text
10000 个任务
```

你如果：

```java
for (...) {
    new Thread(task).start();
}
```

可能一下创建大量线程。

线程并不是越多越快，因为每个线程都需要栈等资源，而且 CPU 核心数量有限：

```text
4核CPU

Thread1
Thread2
Thread3
Thread4
Thread5
...
Thread10000
```

大量线程反而可能造成：

```text
频繁上下文切换
+
内存占用增加
+
调度开销增加
+
严重时资源耗尽
```

线程池则可以限制：

```text
corePoolSize = 3
maximumPoolSize = 6
queue = 100
```

即使大量任务进来，也不会无限创建线程：

```text
任务
 ↓
核心线程
 ↓
队列缓冲
 ↓
最多扩到 maximumPoolSize
 ↓
再撑不住 → 拒绝策略
```

所以它实际上是在做**资源治理**。

第三个优势：

**③ 统一管理任务和线程。**

`ThreadPoolExecutor` 可以统一控制：

```text
核心线程数
最大线程数
任务队列
线程空闲回收
线程工厂
拒绝策略
shutdown
```

而你自己到处：

```java
new Thread(...)
new Thread(...)
new Thread(...)
```


## Q：为什么使用线程池，而不是直接 new Thread？

线程池主要有三个优势。第一是**降低资源消耗**，通过复用 Worker 线程，避免频繁创建和销毁线程；第二是**提高任务响应速度**，已有工作线程可以直接处理新任务；第三是**提高线程的可管理性和系统稳定性**，可以通过核心线程数、最大线程数、工作队列和拒绝策略等限制并发资源，避免大量任务到来时无限创建线程导致系统资源耗尽。

可以背一个经典总结：

**降低资源消耗、提高响应速度、提高可管理性。**
