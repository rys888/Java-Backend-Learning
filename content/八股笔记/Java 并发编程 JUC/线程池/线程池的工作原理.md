
[[#Q：线程池工作原理]]

**线程池 = 提前维护一批可复用线程，用这些线程不断执行提交的任务，而不是每来一个任务就创建一个新线程。**

核心类是：
```java
ThreadPoolExecutor
```

---

# **1. 为什么需要线程池？**

如果每个任务都：new Thread(task).start()，10000 个任务可能创建大量线程。

而线程的创建、销毁以及大量线程之间的调度都有成本，并且线程数量失控还可能耗尽内存等资源。

线程池变成：

```text
                任务不断到来
                    ↓
              ThreadPoolExecutor
                    ↓
        ┌───────────┼───────────┐
        ↓           ↓           ↓
     Thread-1    Thread-2    Thread-3
        ↓           ↓           ↓
     执行任务      执行任务      执行任务
        ↓
     不销毁
        ↓
     继续执行下一个任务
```

核心优势：

**线程复用 + 控制线程数量 + 管理任务 + 提供拒绝策略等。**

---

# **2. ThreadPoolExecutor 七大参数 ⭐⭐⭐⭐⭐**

这是重点！

```java
new ThreadPoolExecutor(
    corePoolSize,
    maximumPoolSize,
    keepAliveTime,
    unit,
    workQueue,
    threadFactory,
    handler
);
```

分别是：

| **参数**            | **含义**                |
| ----------------- | --------------------- |
| `corePoolSize`    | 核心线程数                 |
| `maximumPoolSize` | 最大线程数                 |
| `keepAliveTime`   | 非核心线程等空闲线程的存活时间（默认语义） |
| `unit`            | 时间单位                  |
| `workQueue`       | 任务队列                  |
| `threadFactory`   | 创建线程的工厂               |
| `handler`         | 拒绝策略                  |

假设：

```text
corePoolSize = 2
maximumPoolSize = 5
workQueue容量 = 3
```

注意这个例子，下面都用它。

# **3. 线程池收到任务后怎么处理？⭐⭐⭐⭐⭐**

`ThreadPoolExecutor.execute()` 的核心流程是：

```text
新任务到达
   ↓
当前工作线程数 < corePoolSize？
   ↓
是 → 创建核心工作线程执行任务
   ↓ 否
尝试加入 workQueue
   ↓
成功 → 排队等待
   ↓ 失败（队列满了）
当前线程数 < maximumPoolSize？
   ↓
是 → 创建新的非核心工作线程执行
   ↓ 否
执行拒绝策略
```

这就是线程池最重要的一张图。

**核心线程 → 队列 → 最大线程 → 拒绝策略**

# **4. 用 8 个任务走一遍**

配置：

```text
核心线程数 = 2
最大线程数 = 5
队列容量 = 3
```

假设所有任务执行得比较慢。

### **Task 1 来了**

当前线程数：

```text
0 < 2
```

创建线程：

```text
Thread-1 → Task1
```

### **Task 2 来了**

```text
1 < 2
```

继续创建：

```text
Thread-1 → Task1
Thread-2 → Task2
```

核心线程满了。

---

### **Task 3 来了**

核心线程已经：

```text
2 = corePoolSize
```

所以不马上创建 Thread-3。

而是：

```text
Task3
 ↓
workQueue
```

现在：

```text
线程：
T1 → Task1
T2 → Task2

队列：
Task3
```

Task 4、Task 5 继续：

```text
线程：
T1 → Task1
T2 → Task2

队列：
Task3 → Task4 → Task5
```

队列也满了。

---

### **Task 6 来了**

现在：

```text
核心线程满
+
队列满
```

但是：

```text
当前线程 = 2
最大线程 = 5
```

所以：

创建非核心工作线程。

```text
Thread-3 → Task6
```

Task 7：

```text
Thread-4 → Task7
```

Task 8：

```text
Thread-5 → Task8
```

现在：

```text
             ThreadPoolExecutor

正在执行：
T1 → Task1
T2 → Task2
T3 → Task6
T4 → Task7
T5 → Task8

队列：
Task3 → Task4 → Task5
```

已经达到：

```text
maximumPoolSize = 5
```

# **5. Task 9 再来怎么办？**

此时：

```text
核心线程满了
队列满了
最大线程也满了
```

于是：

**拒绝任务。**

```text
Task9
 ↓
RejectedExecutionHandler
 ↓
拒绝策略
```

因此完整顺序：

```text
Task到来
   ↓
核心线程有空间？
 ├─ 有 → 创建线程执行
 │
 └─ 没有
      ↓
   队列能放？
   ├─ 能 → 入队
   │
   └─ 不能
        ↓
    还能创建线程？
    ├─ 能 → 创建到maximumPoolSize
    │
    └─ 不能
         ↓
       拒绝
```

# **6. 为什么不是直接创建到 maximumPoolSize？**

```text
core = 10
max = 100
```

来了第 11 个任务。

线程池不会立刻创建 Thread-11，而是优先放 workQueue，原因可以理解成：

**线程本身也是昂贵资源，线程池优先维持核心线程处理正常负载；任务积压到队列无法容纳后，才继续增加线程应对更高压力。**

所以：

```text
corePoolSize
↓
正常处理能力

workQueue
↓
缓冲任务

maximumPoolSize
↓
高峰扩容上限

拒绝策略
↓
系统保护底线
```

# **7. workQueue 是什么？**

和**BlockingQueue** 很像，例如：

```java
new ArrayBlockingQueue<>(100);
```

可以理解：

```text
生产者：
业务线程不断 submit/execute
       ↓
BlockingQueue<Runnable>
       ↓
消费者：
线程池里的 Worker 不断取任务执行
```

本质上就是一个典型的：

**生产者—消费者模型。**

业务线程：

```text
提交任务
```

Worker：

```text
获取任务 → 执行 → 获取下一个任务
```

# **8. 线程为什么能够复用？⭐⭐⭐⭐⭐**

线程池里的工作线程大致是在做：

```java
while (task != null || (task = getTask()) != null) {
    task.run();
}
```

这是**简化模型**。也就是说：

```text
Worker Thread-1
     ↓
获取 Task1
     ↓
task.run()
     ↓
Task1执行结束
     ↓
线程没有结束！
     ↓
继续获取任务
     ↓
获取 Task2
     ↓
task.run()
     ↓
继续……
```

这才叫：

**线程复用。**

不是 Task 复用线程，而是：

**Worker 线程一直活着，不断从任务队列中取 Runnable 执行。**

---

# **9. Worker 是什么？**

`ThreadPoolExecutor` 内部有一个重要概念：**Worker**

```text
Worker
≈ 一个工作线程 + 这个线程当前/首次执行的任务等管理信息
```

整体：

```text
ThreadPoolExecutor
        │
        ├── Worker
        │     └── Thread-1
        │
        ├── Worker
        │     └── Thread-2
        │
        └── Worker
              └── Thread-3
```

Worker 内部的线程持续：

```text
取任务
 ↓
执行
 ↓
取任务
 ↓
执行
```

# **10. keepAliveTime 又是什么？**

假设高峰期：

```text
core = 2
max = 5
```

扩容到了：

```text
T1
T2
T3
T4
T5
```

后来业务低峰：

```text
没那么多任务了
```

没必要一直养 5 个线程。

默认情况下，超过核心线程数的空闲 Worker：

```text
T3
T4
T5
```

如果空闲超过：

```text
keepAliveTime
```

就可以退出。

最终：

```text
T1
T2
```

大致回到核心线程规模。所以：

```text
高峰：
core → maximum

低峰：
maximum → core
```

实现一定的弹性。

# **11. 四种拒绝策略 ⭐⭐⭐⭐⭐**

JDK 自带四种经典策略。

### **AbortPolicy**

默认策略：

**拒绝并抛** `RejectedExecutionException` ****。**

```text
满了
↓
直接报错
```

---

### **CallerRunsPolicy**

**让提交任务的线程自己执行。**

例如：

```text
Tomcat业务线程
 ↓
提交任务给线程池
 ↓
线程池满
 ↓
你自己执行这个任务
```

一个重要效果是：

提交线程被迫自己干活，提交新任务的速度自然下降。

所以它具有一定的**反压效果**。

---

### **DiscardPolicy**

**直接丢弃任务，不抛异常。**

---

### **DiscardOldestPolicy**

**丢弃队列中较老的待执行任务，然后再次尝试提交当前任务。**

所以记：

```text
Abort
→ 抛异常

CallerRuns
→ 谁提交谁执行

Discard
→ 直接丢

DiscardOldest
→ 丢较老的队列任务，再尝试提交
```

---

# **12. execute 和 submit 区别**

```text
execute
→ Runnable
→ 无 Future 返回

submit
→ Runnable / Callable
→ 返回 Future
→ 可以拿执行结果
```

# 15. 最重要的一张图

你现在把这个背下来：

```text
                    新任务
                      ↓
            工作线程数 < core？
                 /          \
               是            否
               ↓             ↓
          创建Worker       尝试入队
          直接执行           ↓
                       队列成功？
                       /      \
                     是        否
                     ↓         ↓
                   等待    线程数 < max？
                           /        \
                         是          否
                         ↓           ↓
                     创建Worker    拒绝策略
                       执行
```


**核心不满就建线程 → 核心满了先进队列 → 队列满了扩到最大线程 → 最大也满了执行拒绝策略。**

## Q：线程池工作原理

Java 线程池的核心实现是 `ThreadPoolExecutor`。当一个新任务提交时，首先判断当前工作线程数是否小于 `corePoolSize`，如果小于，则创建新的 Worker 执行任务；如果已经达到核心线程数，则尝试把任务加入 `workQueue`。

如果任务队列已经满了，并且当前线程数还小于 `maximumPoolSize`，则继续创建非核心工作线程执行任务；如果线程数也达到最大值，则执行 `RejectedExecutionHandler` 拒绝策略。

Worker 执行完一个任务后不会立即销毁，而是继续从任务队列中获取后续任务执行，从而实现线程复用。对于超过核心线程数的空闲线程，如果空闲时间超过 `keepAliveTime`，默认情况下会退出。

ThreadPoolExecutor 主要有七个参数：核心线程数、最大线程数、空闲存活时间、时间单位、工作队列、线程工厂以及拒绝策略。
