编译：
Java 源代码会先被 javac 编译为平台无关的字节码（.class）文件，这一步发生在程序运行之前

解释：
JVM 启动后由解释器逐条解释执行字节码
JVM 的**解释器（Interpreter）**：
> 读一条字节码指令，**现场翻译成机器码，立刻执行；不保存翻译结果**。
> 字节码是中间码，不是当前操作系统 CPU 认识的机器码，JVM 一边读 `.class` 字节码，一边实时翻译再跑，这就是 Java **解释特性的体现**。


编译型语言：在程序执行之前，整个源代码会被编译成目标平台的机器码，生产可执行文件，执行时直接运行编译后的代码，速度快，但是跨平台性较差（就比如 C++的 exe 在 macos 上面无法运行）


解释型语言：程序执行时，逐行解释源代码，不生成独立的可执行文件，但是执行满，跨平台好


```
          Java 源代码
           Hello.java
               │
               ▼
       javac 编译器（编译）
               │
               ▼
          Java 字节码
           Hello.class
               │
               ▼
           JVM 加载
               │
               ▼
          字节码验证
               │
               ▼
            JVM 执行
               │
      ┌────────┴────────┐
      ▼                 ▼
   解释器             JIT 编译器
      │                 │
逐条解释字节码      将热点代码编译为机器码
      │                 │
      └────────┬────────┘
               ▼
           CPU 执行
```

Java 的编译与执行流程主要分为两个阶段。

首先是编译阶段，Java 源代码通过 javac 编译器编译为 `.class` 字节码文件。字节码不是直接运行在 CPU 上的机器码，而是一种与具体平台相对独立的中间指令。

然后是执行阶段，JVM 加载并验证字节码，通过解释器或者 JIT 即时编译器执行。

解释器可以逐条解释执行字节码，而 JIT 编译器会将部分热点代码编译为本地机器码，从而提高后续执行效率。

因此，Java 既具有编译型语言的特点，也具有解释型语言的特点。

此外，由于 Java 编译生成的是平台无关的字节码，不同操作系统通过各自的 JVM 执行相同的字节码，所以 Java 能够实现一次编译、到处运行。
