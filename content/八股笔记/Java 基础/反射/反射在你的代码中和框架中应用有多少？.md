
1. **Spring IOC：通过反射创建对象和注入依赖。**
2. **Spring MVC：通过反射调用 Controller 方法。**
3. **MyBatis：通过反射完成数据库记录与 Java 对象的映射。**
4. **Jackson：通过反射实现 JSON 与 Java 对象之间的转换。**

理解这些场景之前，你需要先明白一个问题：

**为什么这些框架需要反射，而不是直接使用** ** `new` ** **创建对象、直接调用方法？**

## **一、为什么框架需要反射？**

假设你写了一个 `UserService`：

```java
public class UserService {
    public void save() {
        System.out.println("保存用户");
    }
}
```

如果不使用反射，我们可以直接：

```java
UserService userService = new UserService();
userService.save();
```

这里有一个特点：**程序在编译时就明确知道要创建** ** `UserService` ** **对象，并调用** ** `save()` ** **方法。**

但 Spring 是一个通用框架。

Spring 不可能提前知道你将来会定义哪些类，例如：

```java
UserService
OrderService
ProductService
ReservationService
```

也不知道这些类有哪些构造器、字段和方法。

因此，Spring 需要一种机制：

即使不知道具体的业务类，也能够在运行时获取类的信息，创建对象并调用方法。

这就是反射的重要作用。

---

## **二、Spring IOC：通过反射创建 Bean 和注入依赖**

这是反射最典型的应用场景之一。

假设有两个类：

```java
@Service
public class UserService {

    public void save() {
        System.out.println("保存用户");
    }
}
```

```java
@RestController
public class UserController {

    @Autowired
    private UserService userService;
}
```

你会发现，我们并没有手动编写：

```java
UserService userService = new UserService();
UserController controller = new UserController();
```

但 Spring 启动后，这两个对象就已经被创建并管理了。

**这是怎么实现的？**

### **1. 扫描 Bean**

Spring 启动时会扫描指定包下的类，识别 `@Component`、`@Service`、`@Controller` 等注解。

它会读取类的注解和元数据信息，判断哪些类需要交给 Spring 管理。

需要注意：Spring 的类路径扫描通常可以通过读取 `.class` 文件的元数据完成，并不是所有扫描过程都依赖 Java 反射。

### **2. 创建 Bean**

当 Spring 确定需要创建 `UserService` 时，可以通过反射获取构造器并实例化对象。

简化后的原理类似：

```java
Class<?> clazz = UserService.class;

Object bean = clazz.getDeclaredConstructor().newInstance();
```

实际上，Spring 的 Bean 实例化还可能涉及构造器选择、工厂方法等机制，并不只有这一种方式。

### **3. 注入依赖**

接下来，Spring 发现 `UserController` 中存在：

```java
@Autowired
private UserService userService;
```

于是会查找容器中的 `UserService` Bean，并将它注入 `UserController`。

对于字段注入，简化后的反射操作类似：

```java
Field field = UserController.class.getDeclaredField("userService");

field.setAccessible(true);

field.set(controller, userService);
```

其中：

- `getDeclaredField()`：获取指定字段。
- `setAccessible(true)`：尝试允许访问私有字段。
- `set()`：给对象的字段赋值。

**所以，Spring IOC 中反射的主要作用是：动态创建 Bean，以及访问构造器、字段和方法来完成依赖注入。**

## **三、Spring MVC：通过反射动态调用 Controller 方法**

这个场景其实和你之前学过的 `DispatcherServlet` 有直接关系。

假设你定义了一个接口：

```java
@RestController
@RequestMapping("/user")
public class UserController {

    @GetMapping("/{id}")
    public String getUser(@PathVariable Long id) {
        return "用户：" + id;
    }
}
```

当前端发送请求：

```http
GET /user/1001
```

Spring MVC 是怎么知道应该调用 `getUser()` 的？

### **1. 建立请求映射关系**

Spring MVC 启动时，会扫描 Controller 中的 `@RequestMapping`、`@GetMapping` 等注解。

然后建立请求与处理方法之间的映射关系。

例如：

```text
GET /user/{id}
       ↓
UserController.getUser(Long id)
```

### **2. DispatcherServlet 接收请求**

当请求到达时：

```text
GET /user/1001
       ↓
DispatcherServlet
       ↓
HandlerMapping
       ↓
找到 UserController.getUser()
       ↓
HandlerAdapter
       ↓
调用 Controller 方法
```

### **3. 通过反射调用方法**

Spring MVC 已经知道要调用哪个 Controller 方法。

它可以通过反射获取对应的 `Method` 对象，并执行方法。

简化后的原理类似：

```java
Method method = UserController.class
        .getDeclaredMethod("getUser", Long.class);

Object result = method.invoke(controller, 1001L);
```

其中：

```java
method.invoke(controller, 1001L);
```

表示在 `controller` 对象上调用 `getUser()` 方法，并传入参数 `1001L`。

实际 Spring MVC 还需要完成参数解析、类型转换、返回值处理等工作，而且可能涉及代理对象。

**所以，Spring MVC 中反射的主要作用是：根据请求映射信息，在运行时动态调用对应的 Controller 方法。**

## **四、MyBatis：通过反射完成对象映射**

这个场景非常值得掌握，因为它和数据库操作密切相关。

假设有一张用户表：

```text
user
-----------------
id    name    age
1     张三     20
```

对应 Java 实体类：

```java
public class User {

    private Long id;
    private String name;
    private Integer age;

    // Getter、Setter
}
```

Mapper 接口：

```java
public interface UserMapper {

    User selectById(Long id);
}
```

SQL：

```sql
SELECT id, name, age
FROM user
WHERE id = #{id};
```

当你执行：

```java
User user = userMapper.selectById(1L);
```

MyBatis 最终返回了一个 `User` 对象。

但问题是：

**数据库返回的是 ResultSet，为什么最后能够变成 User 对象？**

### **1. JDBC 获取查询结果**

MyBatis 底层通过 JDBC 执行 SQL，得到 `ResultSet`。

例如：

```text
ResultSet
    ↓
id = 1
name = 张三
age = 20
```

### **2. 创建 User 对象**

MyBatis 根据结果映射配置，确定需要创建的 Java 对象类型。

例如：

```java
Class<?> clazz = User.class;

Object user = clazz.getDeclaredConstructor().newInstance();
```

### **3. 将查询结果映射到对象属性**

接下来，MyBatis 需要将数据库字段的值设置到 Java 对象中。

简化后的原理类似：

```java
Method setName = User.class
        .getDeclaredMethod("setName", String.class);

setName.invoke(user, "张三");
```

相当于执行：

```java
user.setName("张三");
```

实际 MyBatis 会通过 `MetaObject`、`Reflector` 等组件封装属性访问逻辑，也支持构造器映射等方式。

最终得到：

```java
User {
    id = 1,
    name = "张三",
    age = 20
}
```

此外，在执行 SQL 时，MyBatis 还可以读取参数对象中的属性。

例如：

```java
User user = new User();
user.setId(1L);
```

SQL：

```sql
SELECT * FROM user WHERE id = #{id}
```

MyBatis 可以根据 `#{id}` 读取参数对象的 `id` 属性，再通过 JDBC 将它绑定到 SQL 参数中。

**所以，MyBatis 中反射的主要作用是：动态读取 Java 对象的属性，以及将数据库查询结果映射为 Java 对象。**

这里要注意区分：

- **动态代理**：让 Mapper 接口不需要手写实现类。
- **JDBC**：真正执行 SQL。
- **反射**：读取和设置对象属性，完成结果映射等操作。

这三者各自负责不同的工作。

## **五、Jackson：通过反射完成 JSON 序列化与反序列化**

假设前端发送一个 JSON：

```json
{
  "name": "张三",
  "age": 20
}
```

Spring MVC 中的 Controller：

```java
@PostMapping("/user")
public void save(@RequestBody User user) {
    System.out.println(user.getName());
}
```

你没有手动编写 JSON 解析代码，为什么 Spring MVC 能够自动把 JSON 转换成 `User` 对象？

因为 Spring MVC 通常会通过 `HttpMessageConverter` 调用 Jackson 完成反序列化。

### **1. 反序列化：JSON → Java 对象**

Jackson 需要：

1. 确定目标类型是 `User`。
2. 根据构造器或其他创建机制实例化对象。
3. 根据 JSON 字段名找到对应属性。
4. 通过 Setter、字段访问等方式设置属性。

例如：

```text
JSON
{"name":"张三","age":20}
          ↓
Jackson
          ↓
读取 User 类的属性信息
          ↓
创建 User 对象
          ↓
设置 name 和 age
          ↓
返回 User 对象
```

### **2. 序列化：Java 对象 → JSON**

反过来，当 Controller 返回：

```java
@GetMapping("/user")
public User getUser() {
    return new User(1L, "张三", 20);
}
```

Jackson 可以读取对象的属性值，将它们转换成 JSON。

简化后的反射操作类似：

```java
Method method = User.class.getDeclaredMethod("getName");

Object value = method.invoke(user);
```

得到 `"张三"` 后，将其写入 JSON。

实际 Jackson 还支持注解、字段访问、构造器绑定和其他优化机制。

**所以，Jackson 中反射的主要作用是：动态读取和设置对象属性，实现 Java 对象与 JSON 之间的转换。**

## **六、把四个场景放在一起理解**

|**框架**|**反射的主要作用**|**典型操作**|
|---|---|---|
|Spring IOC|动态创建 Bean、完成依赖注入|构造器实例化、字段赋值|
|Spring MVC|动态调用 Controller 方法| `Method.invoke()` |
|MyBatis|SQL 参数读取、查询结果映射|Getter、Setter、字段访问|
|Jackson|JSON 序列化与反序列化|读取属性、创建对象、设置属性|

你会发现，这四个框架使用反射的方式虽然不同，但背后的思想是一样的：

**框架在编写时不知道具体的业务类，但可以在运行时通过类的元信息完成对象创建、属性访问和方法调用。**

## **七、整理成面试回答**

你可以在原来那段话的基础上，扩充成下面这个版本：

反射在 Java 框架中应用非常广泛，主要用于动态创建对象、依赖注入、方法调用以及数据映射。

例如，在 **Spring IOC** 中，Spring 会根据组件扫描和 Bean 定义识别需要管理的对象，再通过反射等机制调用构造器创建 Bean，并根据 `@Autowired` 等注解完成依赖注入。

在 **Spring MVC** 中，框架会根据请求路径，通过 HandlerMapping 找到对应的 Controller 方法，然后由 HandlerAdapter 完成参数处理，并通过反射等机制动态调用该方法。

在 **MyBatis** 中，框架底层通过 JDBC 执行 SQL，获取查询结果后，可以利用反射读取实体类的属性信息，通过 Setter 或字段访问等方式将数据库记录映射为 Java 对象。同时，也可以读取参数对象中的属性，为 SQL 绑定参数。

此外，**Jackson** 等 JSON 处理框架也会利用反射读取 Java 对象的属性，完成 JSON 序列化；或者在反序列化时动态创建对象并设置属性。

因此，反射的核心价值在于，**框架不需要在编写时知道具体的业务类，就可以在运行时根据配置、注解和类的元信息动态操作对象，从而提高框架的灵活性和扩展性，降低代码耦合。**

**面试时最值得重点掌握的是 Spring IOC、Spring MVC 和 MyBatis 这三个场景。** 尤其要能说清楚：Spring IOC 为什么能自动创建 Bean、Spring MVC 为什么能调用指定的 Controller 方法，以及 MyBatis 为什么能把查询结果自动转换成实体对象。
