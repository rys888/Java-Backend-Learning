单例模式（Singleton Pattern）是一种创建型设计模式，核心思想是：保证一个类在程序中只有一个实例，并提供统一的访问入口。

Java 后端面试中，主要掌握 饿汉式、懒汉式、双重检查锁（DCL）和静态内部类，以及 Spring 单例 Bean 的区别。

## 一、单例模式有什么作用？

假设一个系统需要使用某个配置管理器，如果每次使用都创建一个对象：

```
ConfigManager manager1 = new ConfigManager();
ConfigManager manager2 = new ConfigManager();
```

就可能造成不必要的资源消耗。

单例模式希望实现：

```
ConfigManager manager1 = ConfigManager.getInstance();
ConfigManager manager2 = ConfigManager.getInstance();

// true：获取的是同一个对象
System.out.println(manager1 == manager2);
```

## 二、单例模式的几种实现 ⭐⭐⭐⭐⭐

### 1. 饿汉式：类初始化时创建实例

```
public class Singleton {

    private static final Singleton INSTANCE = new Singleton();

    private Singleton() {}

    public static Singleton getInstance() {
        return INSTANCE;
    }
}
```

特点：实现简单、线程安全，但即使没有使用实例，也会在类初始化时创建。

### 2. 懒汉式：第一次使用时创建实例

```
public class Singleton {

    private static Singleton instance;

    private Singleton() {}

    public static Singleton getInstance() {
        if (instance == null) {
            instance = new Singleton();
        }
        return instance;
    }
}
```

问题：线程不安全。

假设两个线程同时执行：

```
线程A：发现 instance == null
线程B：发现 instance == null
线程A：创建 Singleton
线程B：创建 Singleton
```

最终就可能创建两个实例。

### 3. 双重检查锁（DCL）：面试重点

```
public class Singleton {

    private static volatile Singleton instance;

    private Singleton() {}

    public static Singleton getInstance() {

        if (instance == null) {
            synchronized (Singleton.class) {

                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }

        return instance;
    }
}
```

这里有三个关键点：

- 第一次 `if`： 避免实例已经创建后，每次获取都需要加锁。
    
- `synchronized`： 保证同一时间只有一个线程进入创建实例的临界区。
    
- 第二次 `if`： 防止多个线程先后获得锁时重复创建实例。
    

为什么需要 `volatile`？

因为：

```
instance = new Singleton();
```

可以理解为三个步骤：

1. 分配内存。
    
2. 初始化对象。
    
3. 将对象引用赋给 `instance`。
    

如果没有 `volatile`，可能发生指令重排序，导致其他线程获取到尚未初始化完成的对象。

`volatile` 在这里主要保证可见性，并禁止相关指令重排序。

### 4. 静态内部类：比较推荐

```
public class Singleton {

    private Singleton() {}

    private static class Holder {
        private static final Singleton INSTANCE = new Singleton();
    }

    public static Singleton getInstance() {
        return Holder.INSTANCE;
    }
}
```

优势：

- 懒加载：调用 `getInstance()` 时才触发内部类初始化。
    
- 线程安全：依靠 JVM 的类初始化机制保证。
    
- 不需要显式加锁。
    

需要注意，上面这些常规实现并不能全部防止反射或反序列化破坏单例。枚举单例在这方面更稳妥。

## 三、Spring 的单例 Bean 和单例模式一样吗？

不完全一样，这是面试常见追问。

|对比|Java 单例模式|Spring 单例 Bean|
|---|---|---|
|实例范围|通常是每个类加载器一个实例|每个 Spring 容器、每个 Bean 定义一个实例|
|创建方式|自己通过代码控制|Spring IoC 容器管理|
|获取方式| `getInstance()` | `@Autowired`、`getBean()` |
|线程安全|取决于具体实现|Spring 不保证 Bean 内部业务逻辑线程安全|

例如：

```
@Service
public class UserService {
}
```

默认情况下，`UserService` 是 singleton 作用域。

如果两个 Controller 注入同一个 `UserService` Bean，通常获取的是同一个对象。

但是，Spring 单例 Bean 不等于线程安全。如果 Bean 中存在共享的可变成员变量，仍然需要考虑并发问题。

## Q：

> 单例模式是一种创建型设计模式，主要用于保证一个类只有一个实例，并提供统一的访问入口。
> 
> 常见实现有饿汉式、懒汉式、双重检查锁和静态内部类。
> 
> 饿汉式在类初始化时创建对象，天然线程安全，但不支持懒加载。
> 
> 普通懒汉式虽然支持延迟创建，但存在线程安全问题。
> 
> 双重检查锁通过两次空值判断和 synchronized 保证只创建一个实例，同时使用 volatile 防止指令重排序。
> 
> 静态内部类则利用 JVM 类初始化机制实现线程安全和懒加载。
> 
> 在 Spring 中，Bean 默认也是单例作用域，但它保证的是同一个容器内同一个 Bean 定义通常只有一个实例，并不意味着 Bean 本身线程安全。

一句话记忆：单例模式 = 私有构造方法 + 唯一实例 + 全局访问入口；面试重点是 DCL 为什么需要 `volatile`，以及 Spring 单例 Bean 是否线程安全。
