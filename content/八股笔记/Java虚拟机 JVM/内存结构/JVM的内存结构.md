
[[#Q：讲一下 JVM 内存结构]]


这里要和前面学的 **JMM（Java Memory Model）** 区分开。**JMM** 规定的是多线程怎么读写共享变量，解决可见性、原子性、有序性；**JVM 内存结构 / 运行时数据区**说的是 JVM 运行 Java 程序时，内存实际被逻辑划分成哪些区域。这里讲的是后者，也是面试里常说的“JVM 内存模型长什么样”。

最经典的一张图可以先记成：

```text
                 JVM 运行时数据区
                       │
       ┌───────────────┴───────────────┐
       │                               │
   线程共享区域                      线程私有区域
       │                               │
   ┌───┴────┐              ┌───────────┼───────────┐
   │        │              │           │           │
  堆 Heap  方法区        虚拟机栈     本地方法栈    程序计数器
           Method Area    JVM Stack   Native Stack    PC
```

这 **5 大区域** 是面试最重要的。

---

## **一、堆 Heap ⭐⭐⭐⭐⭐**

```text
                   Heap 堆
                     │
          ┌──────────┴──────────┐
          │                     │
       新生代                 老年代
     Young Gen               Old Gen
          │
     ┌────┴────┐
    Eden   Survivor
           S0 / S1
```

堆最重要的作用是**主要存放对象实例和数组，也是 GC 管理的主要区域**。比如 `User user = new User();` 这一行，简化理解就是：

```text
虚拟机栈                         堆
┌─────────────┐              ┌─────────────┐
│ user引用     │ ───────────→ │ User对象     │
└─────────────┘              └─────────────┘
```

这里非常重要：局部变量 `user` 在当前线程对应的**栈帧局部变量表**中，而 `new User()` 创建出来的对象通常在**堆**。所以初学可以先记成**栈放局部变量等执行数据，堆放对象**，但这是简化说法，别把它理解成绝对规则。

---

# **二、虚拟机栈 JVM Stack ⭐⭐⭐⭐⭐**

每个线程都有自己的 Java 虚拟机栈，每调用一个 Java 方法就创建一个**栈帧 Stack Frame**。比如下面这段：

```java
public void A() {
    B();
}

public void B() {
    C();
}
```

执行过程就是一层层往上压：

```text
调用 A
↓
┌───────┐
│ A栈帧 │
└───────┘

调用 B
↓
┌───────┐
│ B栈帧 │
├───────┤
│ A栈帧 │
└───────┘

调用 C
↓
┌───────┐
│ C栈帧 │
├───────┤
│ B栈帧 │
├───────┤
│ A栈帧 │
└───────┘
```

C 执行完出栈，回到 B 继续执行。

---

## **一个栈帧里面有什么？**

一个栈帧主要包含 **局部变量表**、**操作数栈**、**动态链接** 和 **方法返回地址**，前两个是重点。

**局部变量表**存方法里用到的局部变量，方法参数也算。例如：

```java
public int add(int a, int b) {
    int c = a + b;
    return c;
}
```

`a`、`b`、`c` 这些局部变量就在局部变量表中。需要注意，这里存的是基本类型的值本身；如果变量是个对象，那局部变量表里放的是**引用**，对象本体还是在堆里。

**操作数栈**是方法执行过程中做运算用的“临时工作台”。还是上面那段代码，`int c = a + b;` 大概是这样走的：

1. 把 a 压入操作数栈，此时栈里是 `[a]`
2. 把 b 压入操作数栈，此时栈里是 `[a, b]`
3. 执行加法，弹出栈顶两个数相加，再把结果压回去，此时栈里是 `[a+b]`
4. 把栈顶的结果存到局部变量 c

所以这两个东西的分工是：**局部变量表负责“放变量”，操作数栈负责“算的中间过程”**。再想一层，`i++` 这种自增之所以在多线程下不安全，拆到这一层看就是**读取 → 压栈 → 加一 → 写回**好几步，中间任何一步被打断，另一个线程都可能读到旧值。

**动态链接**是栈帧里保存的一个引用，指向运行时常量池中“当前这个方法”。方法内部要调用别的方法时，不是把地址写死，而是顺着这个引用去常量池里找真正要执行的方法，多态的方法调用和这个过程有关。

**方法返回地址**记录的是方法执行完之后回到调用者的哪一条指令继续执行，以及把返回值交给调用者的操作数栈。方法执行结束，这个栈帧就出栈销毁。

# **三、程序计数器 PC Register**

这个东西很小，每个线程都有自己的程序计数器，可以简单理解成**记录当前线程执行到哪条字节码指令附近**。

为什么每个线程都需要一个？因为 CPU 会不断在线程之间切换：线程 A 执行到第 30 条 → CPU 切走 → 执行线程 B → 又切回线程 A → 从之前的位置继续。所以线程需要保存自己的执行位置，可以理解成**程序计数器就是当前线程执行字节码的“书签”**。

顺带记一个面试点：**程序计数器是 JVM 规范里唯一没有规定 OutOfMemoryError 的区域**，因为它只存“下一条要执行的字节码地址”，占用的空间是固定的，不会随着程序一直运行而变大。

---

# **四、本地方法栈 Native Method Stack**

这个和虚拟机栈很像，区别就是**虚拟机栈服务 Java 方法，本地方法栈服务 native 方法**，比如某些底层功能需要调用本地代码。面试准备阶段记住这一句基本就够。再补一句：HotSpot 里这两块其实是合在一起管理的，所以很多时候不会分开讨论，但规范上是两个区域。

---

# **五、方法区 Method Area ⭐⭐⭐⭐⭐**

这里容易和堆搞混。方法区主要存放**类相关的信息**：

* **类的结构信息**：这个类有哪些字段、哪些方法、继承了什么、实现了哪些接口
* **运行时常量池**：Class 文件里那个常量池，类加载之后变成运行时常量池，方法里的字面量、符号引用都指向它
* **方法相关数据**：方法的字节码、访问标志这类信息
* **静态字段等类级数据**：`static` 修饰的东西

需要注意，**方法区是 JVM 规范定义的逻辑区域**，而永久代和元空间是 HotSpot 的具体实现，JDK 7 及以前方法区的实现是**永久代 PermGen**，JDK 8 之后主要实现变成了 **Metaspace 元空间**。所以面试里会经常听到“JDK 8 把永久代移除了，改成元空间”。

元空间主要使用**本地内存 Native Memory**，⚠️ 别把“元空间”直接等同于 JVM 堆。

这里有两个很容易答错的点。第一，**方法区是规范，永久代 / 元空间是实现**，规范只规定“要有这么一个逻辑区域”，HotSpot 具体拿什么实现是另一回事，所以不能直接说“方法区就是永久代”，它们只是某一个 JDK 版本里的对应关系。第二，**元空间用的是本地内存，不在堆里**，这也是为什么 JDK 8 之后 Metaspace 默认可以一直涨，最后耗尽的是机器的内存。

还有一个小变化需要记住：**JDK 7 开始，字符串常量池和静态变量已经从永久代搬到了堆里**。所以严格来说，JDK 8 之后元空间里主要放的是类的元数据，静态变量是跟着堆里的 Class 对象走的，这一点在下面第八节 `static int count` 那个例子里正好会用到。

# **七、哪些线程共享？哪些线程私有？⭐⭐⭐⭐⭐**

* 线程共享：**堆 Heap**、**方法区 Method Area**
* 线程私有：**虚拟机栈**、**本地方法栈**、**程序计数器**

一句话记：**堆、方法区共享；两栈一计数器私有。**

---

# **八、它和前面学的多线程正好能串起来**

```java
class Test {
    static int count = 0;

    public void add() {
        int x = 10;
        count++;
    }
}
```

Thread A 和 Thread B：

```text
                 共享区域

                  Heap
                   │
              共享对象等

                方法区
                   │
            类级相关数据等


Thread A                       Thread B
   │                              │
JVM Stack                     JVM Stack
   │                              │
add栈帧                        add栈帧
x = 10                         x = 10
```

这里顺手把第五节说的接上：`int x = 10` 是方法里的局部变量，所以它待在各线程自己的栈帧里，A、B 各一份，互不影响；而 `static int count` 虽然是“类级数据”，但 JDK 7 之后静态变量已经跟着 Class 对象放到堆里了，所以它属于**堆上的共享数据**，两个线程改的是同一个它。这就是为什么一个不用加锁，一个必须考虑并发。

所以每个线程都有自己的**虚拟机栈**，但多个线程又可能操作同一个共享对象或者共享状态，于是就出现了前面学的这些东西：多线程共享数据 → 并发访问 → 可能出现线程安全问题 → **synchronized / ReentrantLock / volatile / CAS / AtomicInteger**。

不过这里要注意：**JVM 运行时数据区负责描述“内存逻辑区域”，JMM 负责定义多线程访问共享内存时应该遵守什么规则**，两者不是一个东西。

# **九、每个区域最经典的异常**

这个后面学 JVM 调优会继续遇到，现在先建立印象：

|**区域**|**常见问题**|
|---|---|
|Heap| `OutOfMemoryError: Java heap space` |
|JVM Stack| `StackOverflowError` |
|Metaspace| `OutOfMemoryError: Metaspace` |
|PC|JVM 规范中唯一没有规定 OOM 情况的运行时数据区|
|Native Method Stack|可能出现 StackOverflowError / OOM|

比如无限递归：

```java
void test() {
    test();
}
```

每递归一层就多压一个 test 栈帧，一层层压下去，最终典型的结果就是 **StackOverflowError**。

这里别把两个错搞混：**栈是“压太多层放不下” → StackOverflowError；堆是“对象太多放不下” → OutOfMemoryError**。栈的大小是固定的（可以用 `-Xss` 调整），方法一层层压进去，压不下就是栈溢出；堆那边则是对象一直创建、GC 又回收不掉，才会 OOM。

## Q：讲一下 JVM 内存结构

JVM 运行时数据区主要可以分为五部分：**堆、方法区、Java 虚拟机栈、本地方法栈和程序计数器**。

其中**堆和方法区是线程共享的**。堆主要用于存放对象实例和数组，也是 GC 管理的主要区域；方法区主要存储类相关的信息、运行时常量池等，在 HotSpot JDK 8 之后主要通过元空间实现。

**虚拟机栈、本地方法栈和程序计数器是线程私有的**。虚拟机栈描述 Java 方法执行过程，每次方法调用都会对应一个栈帧；本地方法栈主要服务 native 方法；程序计数器用于记录当前线程执行的字节码指令位置。

另外 JVM 内存结构和 JMM 不是一个概念，JMM 主要规定多线程环境下共享变量的可见性、有序性等内存语义。


**JVM 五大区：堆、方法区、虚拟机栈、本地方法栈、程序计数器；堆和方法区共享，两栈一计数器私有。**
