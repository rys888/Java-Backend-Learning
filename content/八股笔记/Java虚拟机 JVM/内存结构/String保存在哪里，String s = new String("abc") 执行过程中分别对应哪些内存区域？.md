[[#Q：String s = new String("abc")创建几个对象？分别在哪里？]]

`String s = new String("abc");` 这行代码创建了几个对象？分别存储在哪里？这个问题非常经典，JVM 面试里问到的频率很高，而且刚好能把堆、方法区、虚拟机栈串起来。

## 一、String 到底存储在哪里

先要区分三个东西。**String 引用变量**：如果是方法内的局部变量，通常位于虚拟机栈的局部变量表。**String 对象**：通常位于 JVM 堆中。**字符串常量池（String Pool）**：存储字符串字面量对应的规范化 String 对象，JDK 7 及以后这个池本身也位于堆中。

第三点需要单独强调：**JDK 8 中字符串常量池位于堆中，而不是元空间。** 这也是很多八股文章容易讲错的地方。

## 二、`String s = new String("abc")` 的执行过程 ⭐⭐⭐⭐⭐

假设代码：

```java
public void test() {
    String s = new String("abc");
}
```

在 JDK 8 中，内存结构可以这样理解：

```text
                    JVM 内存结构
                         │
          ┌──────────────┴──────────────┐
          │                             │
     虚拟机栈                         堆 Heap
     （线程私有）                    （线程共享）
          │                             │
     test() 栈帧                        │
          │                  ┌──────────┴────────────┐
          │                  │                       │
    局部变量表           字符串常量池              普通堆对象
          │                  │                       │
          │             ┌─────────┐             ┌─────────┐
          │             │ "abc"   │             │ "abc"   │
          │             │ String  │             │ String  │
          │             └─────────┘             └─────────┘
          │                                          ↑
          │                                          │
          └────────── s 引用 ────────────────────────┘
```

这里最关键的是：**变量 `s` 指向的是 `new` 创建的 String 对象，而不是字符串常量池里的那个对象。**

一步一步看。

### 第一步：处理字符串字面量 `"abc"`

JVM 需要取得字符串常量池中与 `"abc"` 对应的 String 对象。如果常量池中还没有这个字符串对象，就会创建并将其纳入字符串常量池。

```text
堆 Heap
│
└── 字符串常量池
       │
       └── String("abc")
```

需要注意：类文件常量池中的字面量信息与运行时堆中的 String 对象不是一回事，前者是 class 文件里的一份描述，后者是运行期真正创建出来的对象。

### 第二步：执行 `new String("abc")`

`new` 会在堆中创建一个新的 String 对象。这个对象与常量池中的 `"abc"` 内容相同，但引用不同，是两个独立的对象。

```text
Heap
│
├── 字符串常量池
│      └── String("abc") ①
│
└── 普通堆对象
       └── String("abc") ②
```

### 第三步：将引用赋值给 `s`

```java
String s = new String("abc");
```

局部变量 `s` 保存的是第二个对象的引用：

```text
虚拟机栈                          Heap

test() 栈帧
┌──────────────┐
│ s：对象引用   │ ───────────────┐
└──────────────┘                │
                                ↓
                        String("abc") ②

字符串常量池：
String("abc") ①
```

所以：**`s` 位于虚拟机栈的局部变量表中，`new String()` 创建的对象位于堆中，字符串常量池中的 `"abc"` 对象也位于堆中。**

## 三、到底创建几个对象？

这是最经典的面试追问。**通常回答：最多涉及两个 String 对象。**（`abc` 可能已经被创建过了，不一定还要创建）

|对象|位置|创建条件|
|---|---|---|
|字符串常量池中的 `"abc"`|堆|常量池中尚不存在时创建|
|`new String("abc")`|堆|执行 `new` 时创建|

如果 `"abc"` 已经存在于字符串常量池中：

```java
String a = "abc";
String s = new String("abc");
```

执行第二行时，通常只需要创建一个新的 String 对象。因此面试回答要严谨：**`new String("abc")` 一定会创建一个新的 String 对象；如果字符串常量池中还没有 `"abc"`，还可能涉及常量池中 String 对象的创建。**

这里讨论的是 String 对象数量，不包括可能涉及的底层数组等其他对象。

## 四、与 `String s = "abc"` 有什么区别？⭐⭐⭐⭐⭐

直接看代码：

```java
String s1 = "abc";
String s2 = "abc";

String s3 = new String("abc");
```

内存结构：

```text
虚拟机栈                           Heap

s1 ────────────────┐
                   │
s2 ────────────────┤
                   ↓
             字符串常量池
              String("abc")
                  

s3 ────────────────────────→ 新 String("abc")
```

所以：

```java
System.out.println(s1 == s2);      // true
System.out.println(s1 == s3);      // false
System.out.println(s1.equals(s3)); // true
```

原因很清楚：`s1 == s2` 指向同一个常量池 String 对象；`s1 == s3` 一个指向常量池对象，一个指向新创建的对象；`s1.equals(s3)` 中 String 重写了 equals，比较的是字符串内容。这里正好和之前学的 `==` 与 `equals()` 对上：**`==` 比引用，`equals()` 比内容。**

## 五、再补充一个知识点：intern()

假设：

```java
String s1 = new String("abc");
String s2 = s1.intern();
String s3 = "abc";
```

`s1.intern()` 表示获取字符串常量池中与当前字符串内容相同的规范化 String 对象。因此：

```java
System.out.println(s1 == s2); // false
System.out.println(s2 == s3); // true
```

可以理解成：

```text
s1 → new 创建的 String("abc")

s2 ───┐
      ├──→ 常量池中的 String("abc")
s3 ───┘
```

需要注意：`intern()` 返回常量池中的规范化引用，并不意味着它一定会新建一个对象。常量池里已经有内容相同的对象时，直接返回已有的那个。

## 六、方法区在这里起什么作用？

一个常见的疑问：**String 字符串常量池在堆里，那方法区在这个过程中干什么？**

例如：

```java
public void test() {
    String s = new String("abc");
}
```

可以分成：

|JVM 内存区域|主要作用|
|---|---|
|方法区|存储类元数据、方法相关信息、运行时常量池等|
|堆|存储 String 对象，包括字符串常量池中的对象|
|虚拟机栈|存储本次 `test()` 方法调用的栈帧、局部变量等|
|程序计数器|记录当前线程执行字节码的位置|

特别注意区分：**运行时常量池 ≠ 字符串常量池。** 运行时常量池属于方法区的逻辑组成部分，而 JDK 7 及以后 HotSpot 的字符串常量池位于堆中。

## Q：String s = new String("abc")创建几个对象？分别在哪里？

在 JDK 8 中，String 对象存储在堆中，字符串常量池也位于堆中。

对于 `String s = new String("abc")`，首先需要获取字符串常量池中 `"abc"` 对应的 String 对象，如果不存在，就会创建对应的常量池对象。

然后执行 `new String()`，在堆中创建一个新的 String 对象，最后将这个新对象的引用赋值给局部变量 `s`，引用通常保存在当前方法栈帧的局部变量表中。

所以这行代码通常涉及一到两个 String 对象，具体取决于 `"abc"` 是否已经存在于字符串常量池中。

### 三个结论

**① `String s = "abc"`**：s 指向字符串常量池中的 String 对象。

**② `String s = new String("abc")`**：s 指向堆中新创建的 String 对象。

**③ JDK 8 的字符串常量池**：位于堆中，不在元空间。
