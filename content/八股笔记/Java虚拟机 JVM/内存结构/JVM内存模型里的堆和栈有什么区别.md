这里更准确应该叫 **JVM 内存结构里的堆和虚拟机栈**。这两个是 JVM 面试里最基础、也最容易被问到的区别。

先记最核心的一句话：

**堆主要存对象，线程共享；栈主要描述方法执行，线程私有。**

## **1. 堆 Heap**

比如：

```java
User user = new User();
```

可以粗略理解为：

```text
Thread 的虚拟机栈                 Heap 堆

┌──────────────┐              ┌──────────────┐
│ user：引用    │ ───────────→ │  User对象     │
└──────────────┘              │  name        │
                              │  age         │
                              └──────────────┘
```

`new User()` 创建的对象通常在**堆**里。

堆的几个核心特点：

- **线程共享**
- 主要存放**对象实例、数组**
- 是 **GC 垃圾回收的主要区域**
- 通常比单个线程的虚拟机栈大
- 对象不再可达后，可以被 GC 回收

例如：

```java
User user1 = new User();
User user2 = user1;
```

可以理解成：

```text
栈                           堆

user1 ───────┐
             ├────────→ User对象
user2 ───────┘
```

两个引用可以指向堆里的同一个对象。

## **2. 虚拟机栈 JVM Stack**

栈主要和：

**方法调用**

有关。

假设：

```java
public void A() {
    int x = 10;
    B();
}

public void B() {
    int y = 20;
}
```

执行 A：

```text
JVM Stack

┌──────────────┐
│ A 的栈帧      │
│ x = 10       │
└──────────────┘
```

A 调用 B：

```text
JVM Stack

┌──────────────┐
│ B 的栈帧      │ ← 当前执行
│ y = 20       │
├──────────────┤
│ A 的栈帧      │
│ x = 10       │
└──────────────┘
```

B 执行结束：

```text
B 栈帧出栈
    ↓

┌──────────────┐
│ A 的栈帧      │ ← 继续执行
│ x = 10       │
└──────────────┘
```

所以：

**方法调用 → 栈帧入栈；方法结束 → 栈帧出栈。**

一个栈帧主要包含：

```text
栈帧 Stack Frame
│
├── 局部变量表
├── 操作数栈
├── 动态链接
└── 方法返回相关信息
```

---

## **3. 最大的几个区别**

|**对比**|**堆 Heap**|**虚拟机栈 JVM Stack**|
|---|---|---|
|是否共享|**线程共享**|**线程私有**|
|主要存什么|对象、数组|栈帧|
|与什么相关|对象生命周期|方法调用|
|回收方式|主要由 GC 管理|方法结束，栈帧出栈|
|常见异常| `OutOfMemoryError` | `StackOverflowError` |

其中前四个最重要。

## **4. “栈存基本类型，堆存对象”对不对？**

这个说法**适合入门，但不够严谨**。

比如：

```java
public void test() {
    int age = 20;
    User user = new User();
}
```

可以粗略理解：

```text
当前方法的栈帧                Heap

局部变量表：
┌─────────────┐
│ age = 20    │
│ user = 引用 │ ───────────→ User对象
└─────────────┘
```

所以这里确实：

```text
age基本类型局部变量 → 栈帧局部变量表
user引用           → 栈帧局部变量表
User对象           → 堆
```

但是如果：

```java
class User {
    int age = 20;
}
```

这个 `age` 是 **User 对象的实例字段**。

那么：

```text
Heap

User对象
┌─────────────┐
│ age = 20    │
└─────────────┘
```

它跟着对象一起位于堆中。

所以不要死记：

❌ 基本类型一定在栈，对象一定在堆。

更准确应该说：

**局部变量通常存储在当前方法的栈帧局部变量表中；对象实例通常分配在堆中。**

## **5. 为什么栈是线程私有，而堆是线程共享？**

这个很好理解。

假设：

```text
Thread A                       Thread B

JVM Stack A                    JVM Stack B
┌──────────┐                  ┌──────────┐
│ A的方法   │                  │ B的方法   │
└──────────┘                  └──────────┘
      \                          /
       \                        /
        ↓                      ↓
            Heap（共享）
          ┌────────────┐
          │ User对象    │
          └────────────┘
```

每个线程都有自己的：

**方法调用链、局部变量、执行状态。**

所以每个线程有自己的虚拟机栈。

但是多个线程可能需要操作同一个：

```java
User user;
Order order;
List list;
```

所以堆是线程共享区域。

这也正好和你前面学的并发联系起来：

```text
多个线程
   ↓
访问共享堆中的同一个对象/共享状态
   ↓
可能产生线程安全问题
   ↓
synchronized / ReentrantLock / CAS...
```

当然，“对象在堆里”并不意味着它就一定被多个线程共享；它也可能只被一个线程访问。

## **6. StackOverflowError 和 OOM**

这两个也经常一起问。

### **栈溢出**

比如无限递归：

```java
public void test() {
    test();
}
```

不断：

```text
test栈帧
↓
test栈帧
↓
test栈帧
↓
test栈帧
↓
...
```

最终：

```text
StackOverflowError
```

因为当前线程的栈空间撑不住了。

### **堆 OOM**

比如不断创建并保留大量对象：

```text
Heap

Object
Object
Object
Object
Object
Object
...
↓
堆空间不足
↓
OutOfMemoryError: Java heap space
```

所以可以辅助记忆：

**无限递归容易爆栈，大量存活对象容易爆堆。**

## **面试怎么回答**

如果面试官问：

**“JVM 中堆和栈有什么区别？”**

你可以直接回答：

JVM 中的堆是线程共享的内存区域，主要用于存放对象实例和数组，也是垃圾回收器主要管理的区域。

Java 虚拟机栈则是线程私有的，每个线程都有自己的虚拟机栈。每次调用 Java 方法都会创建一个栈帧，栈帧中包含局部变量表、操作数栈、动态链接等信息，方法执行结束后对应栈帧出栈。

在异常方面，堆空间不足比较典型的是 `OutOfMemoryError: Java heap space`，而递归层数过深等导致栈空间不足，典型会出现 `StackOverflowError`。

最后记：

**堆：对象、共享、GC。**  
**栈：方法、私有、栈帧。**
