
在 JVM 八股中，面试官问 **“Java 有哪些引用类型？有什么区别？”**，通常指的是 Java 的四种引用类型：

1. **强引用（Strong Reference）**
2. **软引用（Soft Reference）**
3. **弱引用（Weak Reference）**
4. **虚引用（Phantom Reference）**

它们最大的区别是：

**引用类型不同，垃圾回收器（GC）对对象的回收策略也不同。**

## **一、先理解什么是引用**

例如：

```java
User user = new User();
```

可以理解为：

```text
虚拟机栈                  堆 Heap

user ─────────────────→ User对象
       强引用
```

这里的 `user` 就是一个引用变量，它指向堆中的 `User` 对象。

默认情况下，Java 普通对象引用属于**强引用**。

但是 Java 还提供了其他引用类型，用来让程序更灵活地管理对象的生命周期。

---

## **二、四种引用类型分别是什么？**

### **1. 强引用（Strong Reference）⭐⭐⭐⭐⭐**

这是我们平时使用最多的引用。

```java
User user = new User();
```

只要对象仍然能够通过强引用被访问到，GC 就不会回收它。

例如：

```java
User user = new User();

System.gc();
```

即使调用：

```java
System.gc();
```

只要 `user` 仍是有效的强引用，GC 就不能回收这个对象。

注意，`System.gc()` 只是请求 JVM 进行垃圾回收，不保证立即执行。

如果：

```java
user = null;
```

原来的对象失去了这个强引用。

当它没有其他可达引用时，就可能被 GC 回收。

**总结：**

强引用：只要对象强可达，GC 就不会回收。

---

### **2. 软引用（Soft Reference）⭐⭐⭐⭐**

软引用的特点是：

**内存充足时尽量保留对象，内存紧张时可以回收。**

Java 提供：

```java
SoftReference<T>
```

例如：

```java
User user = new User();

SoftReference<User> softRef =
        new SoftReference<>(user);

user = null;
```

此时：

```text
SoftReference
      │
      ↓
   User对象
```

假设对象没有其他强引用。

那么：

```text
内存充足
   ↓
对象通常保留

内存紧张
   ↓
GC可能回收对象
```

可以通过：

```java
User obj = softRef.get();
```

尝试获取对象。

如果对象已经被回收：

```java
softRef.get(); // null
```

**典型应用场景：**

软引用曾经常被用于实现内存敏感型缓存。

不过实际项目中，通常更推荐使用具有明确容量和淘汰策略的缓存，而不是完全依赖软引用控制缓存大小。

---

### **3. 弱引用（Weak Reference）⭐⭐⭐⭐⭐**

弱引用比软引用更弱。

它的特点是：

**当对象只剩弱引用时，一旦 GC 发现它，就可以将其回收，不需要等到内存不足。**

Java 提供：

```java
WeakReference<T>
```

例如：

```java
User user = new User();

WeakReference<User> weakRef =
        new WeakReference<>(user);

user = null;
```

现在对象只剩弱引用：

```text
WeakReference
      │
      ↓
   User对象
```

当 GC 运行时：

```text
GC发现对象只剩弱引用
        ↓
清除弱引用
        ↓
对象可以被回收
```

之后：

```java
weakRef.get(); // 可能为 null
```

这里需要注意：

**弱引用对象并不是创建后立刻消失，而是在 GC 发现对象弱可达时被清除。**

#### **你之前学过的 ThreadLocal 就用到了弱引用！**

还记得：

```text
Thread
  ↓
ThreadLocalMap
  ↓
Entry
├── key：WeakReference<ThreadLocal<?>>
└── value：强引用
```

ThreadLocalMap 的 Entry：

- key 弱引用 ThreadLocal 对象
- value 强引用实际存储的数据

假设：

```text
ThreadLocal对象失去其他强引用
        ↓
GC回收ThreadLocal对象
        ↓
Entry的key变成null
        ↓
value仍可能被强引用持有
        ↓
长期不清理可能造成内存滞留
```

所以之前我们强调：

```java
try {
    threadLocal.set(user);
    // 业务逻辑
} finally {
    threadLocal.remove();
}
```

**这就是弱引用在 Java 后端中的真实应用。**

---

### **4. 虚引用（Phantom Reference）⭐⭐⭐**

虚引用是四种引用中最特殊的。

它的特点是：

**虚引用无法通过**  `get()` **获取对象，主要用于配合 ReferenceQueue 跟踪对象的回收过程。**

Java 提供：

```java
PhantomReference<T>
```

例如：

```java
ReferenceQueue<User> queue =
        new ReferenceQueue<>();

User user = new User();

PhantomReference<User> phantomRef =
        new PhantomReference<>(user, queue);

user = null;
```

即使对象还没有被回收：

```java
phantomRef.get(); // 永远返回 null
```

它和前三种引用不同：

```text
强引用 → 可以获取对象

软引用 → 对象未回收时可以获取

弱引用 → 对象未回收时可以获取

虚引用 → get()始终返回null
```

虚引用通常需要配合：

```java
ReferenceQueue
```

当对象达到相应的可回收状态时，JVM 可以将关联的虚引用加入引用队列。

程序通过监测引用队列，可以执行相关的资源清理工作。

例如：

某些涉及堆外内存、直接内存或其他外部资源的清理机制。

注意：虚引用本身并不会自动释放这些外部资源。

---

## **三、四种引用类型对比 ⭐⭐⭐⭐⭐**

这是面试最重要的表格。

|**引用类型**|**GC 回收条件**|**能否通过引用获取对象**|**常见用途**|
|---|---|---|---|
|**强引用**|对象不再强可达后才可能回收|✅|普通对象引用|
|**软引用**|仅软可达时，内存压力下可回收|✅ 未清除前|内存敏感型缓存|
|**弱引用**|仅弱可达时，GC 发现即可清除|✅ 未清除前|ThreadLocalMap、WeakHashMap|
|**虚引用**|不阻止对象被回收|❌|回收跟踪、资源清理|

你可以把它们理解成四种不同程度的关系：

```text
                 引用强度

强引用 ──────→ 最强
   │
   ↓
软引用 ──────→ 内存紧张时可以回收
   │
   ↓
弱引用 ──────→ GC发现弱可达即可清除
   │
   ↓
虚引用 ──────→ 无法通过引用访问对象
```

口诀：

**强引用不回收，软引用内存紧张回收，弱引用 GC 就能清除，虚引用主要跟踪回收。**

这里的“不回收”指对象仍然强可达，并不是对象永远不会被回收。

---

## Q：Java 中有哪几种引用类型？它们有什么区别？


Java 主要有四种引用类型，分别是强引用、软引用、弱引用和虚引用，它们主要区别在于垃圾回收器对引用对象的回收策略不同。

**强引用**是最常见的引用方式，只要对象仍然强可达，GC 就不会回收。

**软引用**在内存充足时通常会被保留，在内存紧张时可以被回收，适合一些内存敏感的场景。

**弱引用**比软引用更弱，当对象只剩弱引用时，GC 发现后就可以清除引用并回收对象，不需要等到内存不足，例如 ThreadLocalMap 的 Entry 就使用弱引用保存 ThreadLocal 对象。

**虚引用**无法通过 `get()` 获取对象，主要配合 ReferenceQueue 跟踪对象回收状态，常用于资源清理相关的机制。

### **最后再记住一个面试高频追问**

面试官很可能接着问：

**“为什么 ThreadLocalMap 的 key 使用弱引用，而不是强引用？”**

你可以回答：

如果使用强引用，即使外部代码不再使用 ThreadLocal 对象，ThreadLocalMap 仍然会持有它，导致 ThreadLocal 对象无法被正常回收。

使用弱引用后，当 ThreadLocal 没有其他强引用时，GC 就可以回收它。但 Entry 的 value 仍然可能被强引用持有，所以需要在使用完 ThreadLocal 后主动调用 `remove()`，避免长期存活的线程持有无用数据。

**对于 Java 后端实习面试，四种引用的区别必须掌握，其中强引用、弱引用以及 ThreadLocal 的弱引用机制尤其重要。**
