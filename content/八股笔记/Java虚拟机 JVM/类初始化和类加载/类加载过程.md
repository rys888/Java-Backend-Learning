
[[#Q：讲一下 Java 的类加载过程。]]
[[#Q：什么时候会触发类初始化？]]



Java 的**类加载过程（Class Loading Process）是 JVM 面试中的高频八股题，和你刚刚学习的双亲委派机制**联系非常紧密。

首先记住一个结论：

**一个类从被加载到 JVM 中，到最终可以正常使用，主要经历：加载 → 连接（验证、准备、解析）→ 初始化。**

如果讨论类的完整生命周期，还包括**使用和卸载**。

## **一、类加载的整体流程 ⭐⭐⭐⭐⭐**

先看这张图：

```text
              类的生命周期
                    │
                    ▼
                ① 加载
                    │
                    ▼
                ② 连接
                    │
          ┌─────────┼─────────┐
          ▼         ▼         ▼
         验证      准备       解析
                    │
                    ▼
                ③ 初始化
                    │
                    ▼
                ④ 使用
                    │
                    ▼
                ⑤ 卸载
```

其中，**加载、验证、准备、初始化、卸载**有规定的开始顺序，而解析阶段在某些情况下可以延迟到初始化之后进行。

面试主要考察前面五个阶段：

**加载 → 验证 → 准备 → 解析 → 初始化。**

下面结合代码理解。

---

## **二、第一步：加载（Loading）**

假设有一个类：

```java
public class User {

    private int age = 18;

    public void hello() {
        System.out.println("Hello");
    }
}
```

当 JVM 需要使用 `User` 类时，就需要通过类加载器获取它的字节码。

可以简单理解为：

```text
User.java
    │
    │ javac 编译
    ▼
User.class
    │
    │ ClassLoader
    ▼
    JVM
```

加载阶段主要完成三件事：

1. 通过类的全限定名获取对应的二进制字节流。
2. 将字节流中的静态存储结构转换为方法区中的运行时数据结构。
3. 在内存中生成代表这个类的 `java.lang.Class` 对象，作为访问类元数据的入口。

例如：

```java
Class<?> clazz = User.class;
```

这里的 `clazz` 就引用了 `User` 对应的 Class 对象。

需要注意：

**Class 对象和 User 实例不是同一个东西。**

```text
JVM

方法区（逻辑区域）
    │
    └── User 类的元数据
          ├── 类名
          ├── 字段信息
          └── 方法信息

堆
    │
    ├── User 对应的 Class 对象
    │
    └── new User() 创建的实例对象
```

在 HotSpot JVM 中，Class 对象通常位于堆中，而类元数据主要存储在元空间中。

另外，**双亲委派主要发生在类加载器寻找和加载类的过程中**，它不是类加载生命周期中的独立阶段。

---

## **三、第二步：验证（Verification）**

类加载器把字节码加载进来后，JVM 需要检查：

**这个字节码文件是否合法？会不会破坏 JVM 的安全性？**

例如，一个 `.class` 文件可能是：

- 正常由 `javac` 编译生成的。
- 被人为修改过的。
- 通过网络获取的。
- 由其他语言编译生成的。

因此 JVM 需要验证字节码。

常见验证内容包括：

|**验证类型**|**主要作用**|
|---|---|
|文件格式验证|检查 Class 文件格式是否合法|
|元数据验证|检查类的元数据信息是否符合规范|
|字节码验证|检查字节码指令是否符合类型安全等要求|
|符号引用验证|检查符号引用解析是否合法|

例如：

```text
User.class
    ↓
JVM 验证
    ↓
字节码合法？
    │
    ├── 是 → 继续
    │
    └── 否 → 抛出相关错误
```

可能出现：

```java
java.lang.VerifyError
```

**一句话理解：验证就是检查字节码是否符合 JVM 规范。**

---

## **四、第三步：准备（Preparation）⭐⭐⭐⭐⭐**

这是面试最容易考的地方。

**准备阶段主要为类变量（static 字段）分配存储空间，并设置初始值。**

注意两个关键词：

**static 字段、初始值。**

假设：

```java
public class User {

    public static int count = 100;

    public int age = 18;
}
```

在准备阶段：

```text
User 类

static int count = 100
           ↓
准备阶段
           ↓
count = 0
```

为什么不是 100？

因为准备阶段通常只是给静态字段赋予**默认零值**。

真正执行：

```java
count = 100;
```

通常是在后面的**初始化阶段**。

所以：

```text
准备阶段
    ↓
count = 0

初始化阶段
    ↓
count = 100
```

而：

```java
public int age = 18;
```

属于实例字段，不是在类的准备阶段完成实例内存分配的。

它要等到：

```java
new User();
```

创建对象时才会进行相应初始化。

### **特殊情况：static final**

假设：

```java
public class User {

    public static final int MAX_COUNT = 100;
}
```

对于这种编译期常量，编译器可以生成 `ConstantValue` 属性。

JVM 可以在准备阶段就将它设置为：

```text
MAX_COUNT = 100
```

而不是先设置为 0，再等初始化阶段赋值。

但是并非所有 `static final` 字段都是编译期常量。

例如：

```java
public static final Integer VALUE = 100;
```

它不属于上述编译期基本类型常量的情况，赋值需要在类初始化阶段执行。

### **对比总结**

|**字段**|**准备阶段**|**初始化阶段**|
|---|---|---|
| `static int a = 10` | `a = 0` | `a = 10` |
| `static boolean b = true` | `b = false` | `b = true` |
| `static final int c = 20` | `c = 20` |不需要再执行该赋值|
| `int d = 30` |不处理实例字段|创建对象时初始化|

最后一行的“初始化”指对象初始化，不是类初始化。

---

## **五、第四步：解析（Resolution）**

解析阶段主要做一件事：

**将运行时常量池中的符号引用转换为直接引用。**

这句话听起来很抽象，我们结合代码理解。

假设：

```java
public class UserService {

    public void hello() {
        System.out.println("Hello");
    }
}
```

另一个类：

```java
public class Main {

    public static void main(String[] args) {

        UserService service = new UserService();

        service.hello();
    }
}
```

在 Class 文件中，某些对其他类、字段和方法的引用，最初是通过符号信息来表示的。

例如：

```text
UserService
UserService.hello()
```

JVM 在解析时，需要将这些符号引用关联到实际的类、字段或方法的运行时表示。

```text
符号引用
    │
    │ UserService.hello()
    ▼
解析
    │
    ▼
直接引用
    │
    ▼
JVM 能够定位对应的运行时目标
```

你可以简单理解为：

**符号引用相当于知道目标的名字，直接引用相当于已经建立了能够定位目标的联系。**

不过，直接引用不一定就是一个简单的内存地址，也可能是偏移量、句柄等具体实现形式。

而且解析不一定全部在初始化之前完成，JVM 可以根据需要进行延迟解析。

---

## **六、第五步：初始化（Initialization）⭐⭐⭐⭐⭐**

这是整个类加载过程中特别重要的一步。

**初始化阶段主要执行类初始化方法**  `<clinit>()` ****，完成静态字段的显式赋值和静态代码块中的逻辑。**

例如：

```java
public class User {

    public static int count = 100;

    static {
        System.out.println("User 类初始化");
        count = 200;
    }
}
```

编译器会将相关静态初始化逻辑按照源代码顺序组织到类初始化方法 `<clinit>()` 中。

可以简单理解为：

```java
// 示意代码，并非可以直接编写的 Java 方法
static void <clinit>() {

    count = 100;

    System.out.println("User 类初始化");

    count = 200;
}
```

因此：

```text
准备阶段
    ↓
count = 0
    ↓
初始化阶段
    ↓
count = 100
    ↓
执行 static 代码块
    ↓
count = 200
```

最终：

```java
System.out.println(User.count);
```

输出：

```text
User 类初始化
200
```


###  `<clinit>()` **和** `<init>()` 有什么区别？

这也是面试官可能追问的。

|**对比**| `<clinit>()` | `<init>()` |
|---|---|---|
|含义|类初始化方法|实例构造方法|
|主要内容|静态字段赋值、静态代码块|实例字段初始化、实例初始化块、构造器逻辑|
|执行时机|类首次需要初始化时|创建实例并调用对应构造器时|
|执行次数|一个类通常只初始化一次（针对同一个定义类）|每次创建对象通常都会执行相应构造过程|

例如：

```java
public class User {

    static {
        System.out.println("类初始化");
    }

    public User() {
        System.out.println("对象初始化");
    }
}
```

执行：

```java
new User();
new User();
```

输出：

```text
类初始化
对象初始化
对象初始化
```

为什么？

因为：

- `User` 类只需要初始化一次。
- 每次 `new User()` 都需要初始化新的对象。

这里的“一次”是指同一个类加载器定义的 Class 在正常情况下成功完成一次初始化，而不是说不同类加载器定义的同名类只能初始化一次。

## Q：什么时候会触发类初始化？

不是所有使用类的操作都会触发初始化。

常见的主动使用场景包括：

**① 创建类的实例**

```java
new User();
```

**② 读取或修改类的非编译期常量静态字段**

```java
System.out.println(User.count);
```

**③ 调用类的静态方法**

```java
User.hello();
```

**④ 通过反射进行某些主动使用操作**

例如：

```java
Class.forName("com.example.User");
```

默认情况下，`Class.forName(String)` 会触发类初始化。

此外，JVM 启动时包含 `main()` 方法的主类也会被初始化。

### **什么情况不会触发初始化？**

例如：

```java
public class User {

    static {
        System.out.println("初始化 User");
    }

    public static final int MAX = 100;
}
```

执行：

```java
System.out.println(User.MAX);
```

通常不会触发 `User` 类初始化。

因为 `MAX` 是编译期常量，它的值可能已经被编译器直接放进调用方的常量池。

因此：

```text
输出：
100
```

而不会输出：

```text
初始化 User
```

**注意：类加载和类初始化不是同一回事。类可能已经被加载，但还没有执行初始化。**

## **八、类加载和对象创建有什么区别？**

你之前刚刚学过对象创建的五个步骤，这里可以直接对比。

### **类加载过程**

```text
加载
 ↓
验证
 ↓
准备
 ↓
解析
 ↓
初始化
```

主要解决：

**JVM 如何认识一个类，并让这个类具备被使用的条件？**

### **对象创建过程**

```text
类加载检查
    ↓
分配对象内存
    ↓
初始化零值
    ↓
设置对象头
    ↓
执行构造方法
```

主要解决：

**JVM 如何根据一个类创建具体的实例对象？**

例如：

```java
User u1 = new User();
User u2 = new User();
```

可以理解为：

```text
User 类
   │
   │ 首次主动使用时
   ▼
完成必要的类加载和初始化
   │
   ├── new User() → 对象1
   │
   └── new User() → 对象2
```

**类通常只需要加载和初始化一次，但可以根据这个类创建很多个对象。**

## Q：讲一下 Java 的类加载过程。


Java 类加载过程主要包括加载、连接和初始化三个阶段，其中连接又分为验证、准备和解析。

**第一步是加载。** JVM 通过类加载器获取 Class 文件的字节码，将其转换成运行时数据结构，并生成对应的 Class 对象。

**第二步是验证。** 检查字节码是否合法，是否符合 JVM 规范，保证类加载的安全性。

**第三步是准备。** 为类的静态字段分配存储空间并设置默认值，例如 `static int a = 10`，准备阶段通常先设置为 0。

**第四步是解析。** 将运行时常量池中的符号引用转换为直接引用，使 JVM 能够定位相关的类、字段和方法。

**第五步是初始化。** 执行类初始化方法 `<clinit>()`，完成静态字段赋值和静态代码块的执行。

另外，类加载过程中通常会遵循双亲委派机制，即优先委托父类加载器加载，父加载器无法加载时再由当前加载器尝试加载。



### **三个重点**

**① 类加载五个阶段：**

**加载 → 验证 → 准备 → 解析 → 初始化**

**② 准备和初始化的区别：**

```java
static int a = 10;
```

```text
准备阶段：a = 0

初始化阶段：a = 10
```

**③ 类加载和对象创建的区别：**

**类加载是让 JVM 认识这个类，对象创建是根据这个类生成具体的实例。**

对于 Java 后端实习面试，建议你重点掌握**五个阶段、准备与初始化的区别、**** `<clinit>()`  **与**  `<init>()`  **的区别，以及双亲委派机制**。这些知识点经常会被连续追问。
