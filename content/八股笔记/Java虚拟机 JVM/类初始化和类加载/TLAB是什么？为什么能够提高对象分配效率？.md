[[#Q：什么是 TLAB？为什么能够提高对象分配效率？]]

**TLAB（Thread Local Allocation Buffer，线程本地分配缓冲区）** 是 JVM 在堆中为每个线程预先划分的一小块内存。核心思想只有一句：**让每个线程优先在自己的内存区域里分配对象，减少多个线程同时分配对象时产生的竞争。**

## **一、为什么需要 TLAB？**

假设三个线程同时创建对象，也就是都在执行 `new User()`。如果没有 TLAB，它们面对的是同一块空闲内存：

```text
                 JVM 堆
                    │
              空闲内存区域
                    │
         ┌──────────┼──────────┐
         │          │          │
      Thread A   Thread B   Thread C
         │          │          │
         └──────────┼──────────┘
                    ↓
             竞争内存分配位置
```

如果 JVM 用指针碰撞的方式分配内存，就需要移动一个指针，表示内存已经分配到哪里：

```text
堆内存：

┌──────────────┬────────────────┐
│ 已使用        │ 空闲           │
└──────────────┴────────────────┘
               ↑
             分配指针
```

线程 A 和线程 B 都要分配 32 字节，如果两个线程同时去改同一个分配指针，就会产生并发问题，所以 JVM 必须保证内存分配的线程安全。一种做法是用 **CAS** 更新这个共享的分配指针，但在高并发下多个线程抢同一个位置，CAS 会失败重试，重试本身就是额外的开销。TLAB 要解决的就是这一层开销。

## **二、TLAB 是怎么工作的？⭐⭐⭐⭐⭐**

JVM 会从堆中为线程划分一小块内存：

```text
                    JVM 堆
┌───────────────────────────────────────────┐
│                                           │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐ │
│  │ TLAB A   │  │ TLAB B   │  │ TLAB C   │ │
│  │          │  │          │  │          │ │
│  │ Thread A │  │ Thread B │  │ Thread C │ │
│  └──────────┘  └──────────┘  └──────────┘ │
│                                           │
│             其他堆内存                     │
└───────────────────────────────────────────┘
```

有了各自的 TLAB 之后，三个线程分别在 TLAB A 里分配 User、在 TLAB B 里分配 Order、在 TLAB C 里分配 Product，互相不干扰。**只要 TLAB 中还有足够的空间，线程就可以直接在自己的 TLAB 中分配对象，不需要与其他线程竞争共享的分配指针。** 这就是 TLAB 提高对象分配效率的主要原因。

## **三、TLAB 为什么能够提高效率？**

主要有两个原因。

### **1. 减少线程之间的竞争**

没有 TLAB 时，三个线程的分配请求都汇聚到同一个共享分配指针上，需要靠 CAS 竞争着更新；有 TLAB 之后，每个线程改的是自己的分配指针，互不相干。**竞争减少了，共享分配指针上的 CAS 操作自然也就少了。**

### **2. 对象分配速度快**

在 TLAB 内分配对象时，通常只有三步：

1. 判断剩余空间是否足够。
2. 移动当前线程的分配指针。
3. 返回分配到的内存地址。

```text
TLAB A

┌───────────────┬───────────────────┐
│ 已使用         │ 剩余空间           │
└───────────────┴───────────────────┘
                ↑
              分配指针
```

假设创建一个 32 字节的对象，整个过程就是 **检查剩余空间 → 空间足够 → 分配指针移动 32 字节 → 完成内存分配**，非常快。所以 **TLAB 的优势不是减少对象占用的内存，而是让常见的小对象分配路径更加高效。**

## **四、如果 TLAB 空间不够了怎么办？**

TLAB 并不是无限大的。当前线程的 TLAB 剩余空间不足时，JVM 会根据对象大小、TLAB 剩余空间和分配策略来处理，常见的情况有两种：

- **申请新的 TLAB**：当前 TLAB 不够用时，从堆中获取新的 TLAB。
- **直接在 TLAB 外分配**：例如对象较大，或者当前分配策略认为不适合使用 TLAB。

因此，并不是所有对象都一定在 TLAB 中分配。另外，**申请新的 TLAB 本身仍然需要协调共享的堆内存分配状态**，TLAB 只是减少竞争，并不是完全消除所有同步操作。

## **五、TLAB 是线程私有的，那对象也是线程私有的吗？**

这是一个特别容易答错的问题。

**不是。** 这里要区分两个概念：**TLAB 是线程私有的分配缓冲区，而 TLAB 中分配的对象仍然位于 JVM 堆中。**

```java
public class Demo {

    private static User sharedUser;

    public static void main(String[] args) {

        User user = new User();

        sharedUser = user;
    }
}
```

假设 `User` 对象是在主线程的 TLAB 中分配的，之后执行 `sharedUser = user;` 把它赋给了静态变量，其他线程依然可以通过 `sharedUser` 访问到这个对象：

```text
                 JVM 堆
                    │
             Thread A 的 TLAB
                    │
                 User 对象
                    ↑
                    │
          其他线程也可能访问
```

所以这里必须分清：**TLAB 的线程私有，指的是内存分配过程由对应线程独立管理，并不意味着其中创建的对象只能被这个线程访问。** 这也解释了为什么 TLAB 不属于虚拟机栈，它本来就是堆的一部分。

## **六、TLAB 和 CAS 有什么关系？**

学过 CAS 之后，可以把两者放在一起看：

|**对比**|**CAS**|**TLAB**|
|---|---|---|
|核心思想|通过原子操作保证并发更新安全|为线程划分独立的分配缓冲区|
|主要作用|保证共享分配状态更新的正确性|减少共享分配状态的竞争|
|是否存在竞争|可能存在，失败后重试|TLAB 内部分配通常无竞争|
|典型使用场景|共享分配指针更新|线程快速分配普通小对象|

二者并不是互相替代的关系，而是配合着用的：

```text
对象创建
   │
   ▼
尝试在当前线程 TLAB 中分配
   │
   ├── 空间足够
   │      ↓
   │   移动本地分配指针
   │      ↓
   │   分配成功
   │
   └── 空间不足
          ↓
      尝试申请新 TLAB
      或在 TLAB 外分配
          ↓
      可能涉及 CAS 等同步机制
```

## Q：什么是 TLAB？为什么能够提高对象分配效率？

TLAB 全称是 Thread Local Allocation Buffer，也就是线程本地分配缓冲区，是 JVM 在堆中为每个线程划分的一小块内存。在多线程环境下，如果多个线程同时创建对象，可能会竞争同一个堆内存分配指针，需要通过 CAS 等方式保证线程安全。引入 TLAB 后，每个线程可以优先在自己的 TLAB 中分配对象，只需要检查剩余空间并移动本地分配指针，通常不需要与其他线程竞争，因此减少了同步和 CAS 重试的开销，提高了对象分配效率。如果 TLAB 空间不足，JVM 可以申请新的 TLAB，或者在 TLAB 外进行分配。需要注意的是，TLAB 虽然是线程私有的，但它仍然属于 JVM 堆，里面创建的对象依然可以被其他线程访问。

### **三个结论**

**① TLAB 是什么？** 线程在堆中的专属对象分配缓冲区。

**② 为什么快？** 减少共享分配指针竞争，避免每次分配都进行 CAS。

**③ TLAB 在哪里？** 在 JVM 堆里，是线程私有的分配区域，但里面创建的对象仍然是堆对象。

**一句话记忆：TLAB 通过让线程优先在自己的堆内存缓冲区中分配对象，减少多线程竞争，从而提高对象分配效率。**
