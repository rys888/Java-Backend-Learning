
[[#Q：说说 Java 对象的创建过程。]]

主要想考察的是：当我们执行 `new` 关键字时，JVM 内部到底做了什么？

先记住一个结论：

**Java 对象的创建过程主要分为 5 步：类加载检查 → 分配内存 → 初始化零值 → 设置对象头 → 执行构造方法。**

下面结合代码一步一步理解。

## **一、先看一个简单的例子**

```java
public class User {
    private int age = 18;
    private String name = "Eason";

    public User() {
        System.out.println("创建 User 对象");
    }
}
```

执行：

```java
User user = new User();
```

我们可以把这个过程理解成：

```text
             new User()
                  │
                  ▼
          ① 类加载检查
                  │
                  ▼
          ② 分配对象内存
                  │
                  ▼
          ③ 初始化零值
                  │
                  ▼
          ④ 设置对象头
                  │
                  ▼
          ⑤ 执行构造方法
                  │
                  ▼
            对象创建完成
```

注意：这里讨论的是 HotSpot JVM 中普通对象的典型创建流程。

---

## **二、第一步：类加载检查**

当 JVM 遇到：

```java
new User();
```

对应的字节码通常包含：

```text
new
dup
invokespecial
```

其中 `new` 指令会引用一个类的符号引用。

JVM 首先需要确定：

**这个类是否已经完成必要的加载、链接和初始化？**

如果没有，就需要执行相应的类加载流程。

例如：

```java
User user = new User();
```

如果 `User` 类还没有被加载和初始化，JVM 就需要先处理这些工作。

你可以理解成：

```text
new User()
    ↓
JVM：User 类我认识吗？
    ↓
不认识
    ↓
加载 User 类
    ↓
验证、准备、解析等链接工作
    ↓
执行必要的类初始化
    ↓
继续创建对象
```

这里要区分两个概念：

- **类初始化**：执行类的静态初始化逻辑，例如静态字段赋值和 `static` 代码块。
- **对象初始化**：执行实例字段初始化、实例初始化代码块和构造方法。

它们不是同一回事。

---

## **三、第二步：为对象分配内存 ⭐⭐⭐⭐⭐**

类加载检查完成后，JVM 就知道这个对象需要占用多少内存。

接下来需要在堆中分配一块空间。

例如：

```java
User user = new User();
```

JVM 需要为 `User` 对象分配内存。

这里有两种常见的内存分配方式。

### **1. 指针碰撞（Bump the Pointer）**

假设堆中空闲内存是连续的：

```text
堆内存

┌──────────────────┬──────────────────┐
│    已使用内存      │     空闲内存      │
└──────────────────┴──────────────────┘
                   ↑
                分界指针
```

创建新对象时：

```text
创建一个 User 对象
        ↓
计算对象需要的内存大小
        ↓
将分界指针向空闲区域移动
        ↓
完成内存分配
```

这种方式叫作**指针碰撞**。

它适用于空闲内存比较规整的情况。

### **2. 空闲列表（Free List）**

如果内存不是连续的：

```text
堆内存

┌──────┬──────┬──────┬──────┬──────┐
│ 使用  │ 空闲 │ 使用  │ 空闲  │ 使用 │
└──────┴──────┴──────┴──────┴──────┘
```

JVM 就需要知道：

哪些位置还有空闲内存？

因此可以维护一张空闲列表，记录哪些内存块可供分配。

分配对象时：

```text
查看空闲列表
      ↓
寻找合适的内存块
      ↓
分配给新对象
      ↓
更新空闲列表
```

**两者区别：**

|**分配方式**|**适用情况**|**原理**|
|---|---|---|
|指针碰撞|空闲内存规整|移动分界指针|
|空闲列表|空闲内存不连续|从空闲块中寻找合适空间|

实际使用哪种方式，与 JVM 的内存管理方式和垃圾收集器有关。

### **3. 多线程同时创建对象怎么办？**

这里还有一个面试追问：

如果两个线程同时执行 `new User()`，会不会分配到同一块内存？

JVM 必须保证内存分配的线程安全。

常见解决方式有两种。

**第一种：CAS**

使用 CAS 等同步机制，确保多个线程并发更新内存分配位置时不会发生冲突。

**第二种：TLAB（Thread Local Allocation Buffer）⭐⭐⭐⭐⭐**

TLAB 可以理解成：

**JVM 预先从堆中划分一小块内存，供某个线程优先分配对象。**

例如：

```text
                  JVM 堆
                     │
       ┌─────────────┴─────────────┐
       │                           │
   Thread A 的 TLAB           Thread B 的 TLAB
       │                           │
       ├── User对象                 ├── Order对象
       └── Product对象              └── User对象
```

每个线程优先在自己的 TLAB 中分配对象，减少多个线程竞争同一个分配位置的情况。

注意：

**TLAB 虽然是线程私有的分配区域，但它仍然属于 JVM 堆，不属于虚拟机栈。**

这点很容易在面试中答错。

## **四、第三步：初始化零值**

内存分配完成后，JVM 会将对象实例字段对应的内存初始化为默认值。

例如：

```java
public class User {
    private int age = 18;
    private boolean active = true;
    private String name = "Eason";
}
```

此时先不要考虑代码里写的 `18`、`true` 和 `"Eason"`。

**在执行实例字段初始化代码之前，字段会先具有默认值。**

```text
User 对象

age    = 0
active = false
name   = null
```

因为 Java 对象的实例字段具有默认初始化机制。

常见默认值：

|**数据类型**|**默认值**|
|---|---|
|int|0|
|long|0 L|
|boolean|false|
|double|0.0|
|引用类型|null|

所以：

```java
private int age = 18;
```

并不是 JVM 分配完内存后，直接就把 `age` 设置为 18。

而是可以粗略理解成：

```text
内存分配
   ↓
age = 0
   ↓
后续执行实例初始化代码
   ↓
age = 18
```

---

## **五、第四步：设置对象头**

接下来 JVM 需要设置对象头（Object Header）。

你可以把对象头理解为：

**JVM 为管理对象而保存的一些运行时信息。**

在 HotSpot JVM 中，普通对象的对象头主要涉及：

### **1. Mark Word**

存储与对象运行状态相关的信息。

例如：

- 对象的哈希码（在适用情况下）
- GC 年龄
- 锁状态相关信息

这里正好联系到你之前学习的：

**synchronized 的锁机制。**

对象头中的 Mark Word 与对象锁的实现密切相关。

### **2. Klass Pointer（类型指针）**

用于关联对象的类型元数据。

例如：

```java
User user = new User();
```

JVM 需要知道：

这个对象属于哪个类？

类型指针就与此有关。

可以简单理解成：

```text
User对象
┌─────────────────────────┐
│ 对象头                  │
│ ├── Mark Word           │
│ └── Klass Pointer       │
├─────────────────────────┤
│ 实例数据                │
│ age                     │
│ name                    │
└─────────────────────────┘
```

对象在内存中通常还可能包含对齐填充。

---

## **六、第五步：执行构造方法 ⭐⭐⭐⭐⭐**

前面四步完成后，JVM 已经为对象准备好了内存和必要的运行时信息。

但是：

**此时对象的业务字段还不一定是程序员希望的最终值。**

例如：

```java
public class User {

    private int age = 18;
    private String name = "Eason";

    public User() {
        System.out.println("创建对象");
    }
}
```

对象刚完成零值初始化时：

```text
age  = 0
name = null
```

之后执行实例初始化逻辑：

```text
age  = 18
name = "Eason"
```

然后执行构造方法中的代码：

```java
System.out.println("创建对象");
```

需要注意，构造方法执行过程中还涉及父类构造方法的调用。

对于普通 Java 类，可以简化理解为：

```text
分配内存、初始化默认值
          ↓
执行父类构造相关初始化
          ↓
执行当前类实例字段初始化
          ↓
执行当前类实例初始化代码块
          ↓
执行当前类构造方法体
          ↓
对象初始化完成
```

最后：

```java
User user = new User();
```

将新对象的引用赋值给局部变量 `user`。

```text
虚拟机栈                         JVM 堆

test() 栈帧
┌─────────────┐
│ user 引用    │ ───────────────→ User 对象
└─────────────┘                  ├── age = 18
                                 └── name = "Eason"
```

## Q：说说 Java 对象的创建过程。

**第一步是类加载检查。** 当 JVM 遇到 new 指令时，会检查对应的类是否已经完成必要的加载、链接和初始化，如果没有，就先执行相应的类加载流程。

**第二步是分配内存。** JVM 根据对象所需的内存大小，在堆中分配空间，常见的分配方式有指针碰撞和空闲列表。为了保证并发分配的线程安全，可以使用 CAS 和 TLAB 等机制。

**第三步是初始化零值。** JVM 会将对象实例字段初始化为对应类型的默认值，例如 int 为 0，引用类型为 null。

**第四步是设置对象头。** 对象头包含 Mark Word 和类型指针等信息，用于支持对象的运行时管理。

**第五步是执行构造方法。** JVM 执行实例初始化和构造方法相关逻辑，将字段设置为程序中指定的值，最终完成对象初始化。

### **最后记住这张图**

```text
new User()
    │
    ▼
① 类加载检查
   类是否已经加载、链接、初始化？
    │
    ▼
② 分配内存
   指针碰撞 / 空闲列表
   CAS / TLAB
    │
    ▼
③ 初始化零值
   int → 0
   boolean → false
   引用类型 → null
    │
    ▼
④ 设置对象头
   Mark Word
   Klass Pointer
    │
    ▼
⑤ 执行构造方法
   父类初始化
   实例字段赋值
   构造方法体
    │
    ▼
对象创建完成
```

**一句话记忆：类加载检查 → 分配内存 → 初始化零值 → 设置对象头 → 执行构造方法。**

对于 Java 后端实习面试，建议重点掌握这五个步骤，并额外理解 **CAS、TLAB 和对象头**，这三个知识点很容易成为面试官的追问。
