**不一定！在 JVM 中，判断两个类是否是同一个类，不仅要看类名，还要看加载它们的类加载器。**

这是 Java 类加载机制中的一个高频面试题，和你刚刚学过的**双亲委派模型**密切相关。

## **一、JVM 如何判断两个类是否相同？⭐⭐⭐⭐⭐**

JVM 判断类身份主要依据两个条件：

1. **类的全限定名是否相同。**
2. **定义这个类的类加载器是否相同。**

可以记住这个公式：

**类的唯一身份 = 类的全限定名 + 定义它的类加载器**

例如：

```java
com.example.User
```

假设存在两个类加载器：

```text
                JVM
                 │
        ┌────────┴────────┐
        │                 │
   ClassLoader A     ClassLoader B
        │                 │
        ▼                 ▼
 com.example.User   com.example.User
        │                 │
        ▼                 ▼
      Class A           Class B
```

虽然两个类的全限定名完全相同，但因为它们由不同的类加载器定义，所以：

**JVM 会认为它们是两个不同的类。**

---

## **二、举个具体例子**

假设我们有：

```java
package com.example;

public class User {
    private String name;
}
```

现在通过两个不同的自定义类加载器分别加载这个类：

```java
Class<?> classA = loaderA.loadClass("com.example.User");

Class<?> classB = loaderB.loadClass("com.example.User");
```

假设 `loaderA` 和 `loaderB` 都独立定义了这个类，那么：

```java
System.out.println(classA == classB);
```

输出：

```text
false
```

为什么？

因为：

```text
classA：
com.example.User + ClassLoader A

classB：
com.example.User + ClassLoader B
```

虽然类名相同，但是类加载器不同。

**因此它们在 JVM 中属于不同的类型。**

注意：这里的前提是两个加载器确实分别定义了类。如果它们都遵循双亲委派，并最终委托给同一个父加载器，那么返回的仍可能是同一个 Class 对象。

---

## **三、这和双亲委派有什么关系？**

你刚刚学习过双亲委派：

类加载器收到请求时，优先委托父类加载器加载，父类加载器无法加载时，才自己加载。

例如：

```text
        Bootstrap ClassLoader
                  ↑
                  │
         Platform ClassLoader
                  ↑
                  │
       Application ClassLoader
             ↑          ↑
             │          │
       Custom A      Custom B
```

假设 Custom A 和 Custom B 都要加载：

```java
com.example.User
```

如果 Application ClassLoader 已经能够加载这个类：

```text
Custom A ──┐
           │
           ▼
    Application ClassLoader
           │
           ▼
     com.example.User
           ▲
           │
Custom B ──┘
```

那么两个自定义类加载器最终获得的是同一个类。

```java
classA == classB; // true
```

因此：

**双亲委派可以减少不同类加载器重复定义同名类的情况。**

但是，如果自定义类加载器采用特殊的加载策略，分别定义相同全限定名的类，就可能得到两个不同的类型。

---

## **四、实际项目中有什么应用？**

最典型的就是 **Tomcat 的类加载隔离机制**。

假设 Tomcat 部署了两个 Web 应用：

```text
Tomcat
│
├── 应用 A
│   ├── WebAppClassLoader A
│   └── com.example.User
│
└── 应用 B
    ├── WebAppClassLoader B
    └── com.example.User
```

即使两个应用都有：

```java
com.example.User
```

它们也可以由各自的 WebAppClassLoader 独立加载。

这样做的好处是：

- 不同 Web 应用可以使用不同版本的依赖。
- 避免应用之间发生类冲突。
- 实现不同 Web 应用之间的类隔离。

例如：

```text
应用 A → commons-lang3 版本 3.12

应用 B → commons-lang3 版本 3.14
```

Tomcat 可以通过类加载隔离，让两个应用使用各自的依赖版本。

这也是为什么在 Java 中：

**类名相同，不代表类型相同。**

---

## Q：两个相同类名的类，一定是同一个类吗？


不一定。在 JVM 中，一个类的唯一身份由类的全限定名和定义它的类加载器共同决定。

如果两个类的全限定名相同，而且由同一个类加载器定义，那么它们属于同一个类。

但是如果两个类由不同的类加载器分别定义，即使全限定名完全相同，JVM 也会认为它们是两个不同的类型。

例如 Tomcat 为不同 Web 应用提供独立的类加载器，即使两个应用中存在同名类，也可以实现类隔离。

另外，双亲委派机制可以减少这种重复定义的情况，因为子类加载器会优先委托父类加载器加载。

### **最后记住一个公式**

```text
Java 类的唯一身份
        =
    类的全限定名
        +
   定义它的类加载器
```


**类名相同不一定是同一个类，还要看是不是由同一个类加载器定义的。**

这里面试时最好强调**“定义类加载器”**，而不只是“发起加载请求的类加载器”，因为两个不同的加载器可能最终委托给同一个父加载器来定义类。
