JVM 采用分代收集，主要是因为 **不同对象的生命周期不同，如果对所有对象采用同一种垃圾回收算法，效率往往不高。**

先记住结论：

- **年轻代：主要采用复制算法（Copying）。**
- **老年代：传统分代收集器主要采用标记-清除（Mark-Sweep）或标记-整理（Mark-Compact）算法。**

不过，这是传统分代垃圾收集器的典型设计。现代 G 1、ZGC 等收集器的实现更加复杂，不能简单地将所有年轻代、老年代都对应到一种算法。

## **一、为什么 JVM 要采用分代收集？⭐⭐⭐⭐⭐**

分代收集的核心依据是**弱分代假说**：

绝大多数对象都是朝生夕死的，只有少量对象能够长期存活。

例如，在 Spring Boot 项目中：

```java
public UserDTO getUser(Long id) {
    User user = userMapper.selectById(id);
    return convertToDTO(user);
}
```

每次调用接口，都可能创建一些临时对象。

这些对象完成业务处理后，如果不再被引用，很快就可以被回收。

但另一些对象可能长期存在，例如：

```java
private static final Map<Long, User> CACHE = new HashMap<>();
```

这个静态集合及其持有的对象可能存活很长时间。

因此，JVM 可以根据对象生命周期的特点，将堆划分为不同区域：

```text
                  JVM 堆
┌────────────────────────────────────┐
│                                    │
│              年轻代                │
│                                    │
│  ┌────────┐ ┌───────┐ ┌───────┐   │
│  │ Eden   │ │  S0   │ │  S1   │   │
│  └────────┘ └───────┘ └───────┘   │
│                                    │
├────────────────────────────────────┤
│                                    │
│              老年代                │
│                                    │
│         长期存活的对象             │
│                                    │
└────────────────────────────────────┘
```

这样做有两个好处：

**① 年轻代对象死亡率高**

每次 GC 后，存活对象通常较少，因此适合使用复制算法。

**② 老年代对象存活率高**

如果仍然使用传统的半区复制算法，就需要频繁复制大量存活对象，成本较高。

因此，传统老年代收集器通常选择标记-清除或标记-整理算法。

---

## **二、年轻代：复制算法 ⭐⭐⭐⭐⭐**

### **1. 复制算法的工作原理**

年轻代通常划分为：

- Eden 区
- Survivor 0 区
- Survivor 1 区

新对象通常优先分配在 Eden 区。

当 Eden 空间不足时，可能触发 Young GC。

假设当前 Eden 区有 100 个对象，其中 90 个已经死亡，只有 10 个存活。

```text
GC 前：

Eden
┌─────────────────────────────┐
│ 存活对象 10%                 │
│ 死亡对象 90%                 │
└─────────────────────────────┘
```

执行 Young GC：

```text
Eden + From Survivor
          │
          ▼
     找到存活对象
          │
          ▼
复制到 To Survivor
          │
          ▼
回收原来的空间
```

例如：

```text
GC 前：

Eden         S0          S1
┌───────┐  ┌───────┐   ┌───────┐
│ A B C │  │  D E  │   │       │
│ F G H │  │       │   │       │
└───────┘  └───────┘   └───────┘


假设只有 A、C、D 存活


GC 后：

Eden         S0          S1
┌───────┐  ┌───────┐   ┌───────┐
│       │  │       │   │ A C D │
│       │  │       │   │       │
└───────┘  └───────┘   └───────┘
```

下一次 Young GC 时，两个 Survivor 区会交换角色。

注意：如果对象达到晋升条件，或者 Survivor 空间不足，部分对象可能进入老年代，而不是全部复制到另一个 Survivor 区。

### **2. 为什么年轻代适合复制算法？**

因为年轻代对象死亡率高。

假设：

- 年轻代有 1000 个对象。
- 其中 950 个对象已经死亡。
- 只有 50 个对象存活。

采用复制算法，只需要复制 50 个存活对象。

**复制成本主要与存活对象数量有关，而不是与死亡对象数量成正比。**

另外，复制后对象通常可以紧凑排列，避免产生大量内存碎片。

## **三、老年代：标记-清除和标记-整理算法**

老年代对象通常已经经历过多次 GC，存活概率相对较高。

### **1. 标记-清除算法（Mark-Sweep）**

分为两个阶段：

**第一步：标记存活对象。**

通过可达性分析，找到仍然存活的对象。

**第二步：清除死亡对象。**

释放不可达对象占用的空间。

```text
GC 前：

┌───┬───┬───┬───┬───┬───┐
│ A │ B │ C │ D │ E │ F │
└───┴───┴───┴───┴───┴───┘

假设 B、D、F 死亡


GC 后：

┌───┬───┬───┬───┬───┬───┐
│ A │   │ C │   │ E │   │
└───┴───┴───┴───┴───┴───┘
```

**优点：** 不需要移动全部存活对象。

**缺点：** 容易产生内存碎片。

例如，虽然总共有 300 MB 空闲内存，但这些空间不连续，可能无法分配一个需要 200 MB 连续空间的大对象。

经典的 CMS 收集器主要采用标记-清除算法。

### **2. 标记-整理算法（Mark-Compact）**

同样先标记存活对象。

但与标记-清除不同，它会将存活对象向内存的一端移动，再清理边界之外的空间。

```text
GC 前：

┌───┬───┬───┬───┬───┬───┐
│ A │ B │ C │ D │ E │ F │
└───┴───┴───┴───┴───┴───┘

假设 B、D、F 死亡


GC 后：

┌───┬───┬───┬───────────┐
│ A │ C │ E │   空闲    │
└───┴───┴───┴───────────┘
```

**优点：** 不容易产生内存碎片。

**缺点：** 需要移动存活对象，并更新相关引用，整理过程存在额外开销。

传统的 Serial Old 收集器主要采用标记-整理算法。

---

## **四、三种垃圾回收算法的区别**

|**对比**|**标记-清除**|**标记-复制**|**标记-整理**|
|---|---|---|---|
|核心思想|标记并清理死亡对象|将存活对象复制到其他区域|将存活对象移动到一端|
|是否移动对象|否|是|是|
|是否容易产生碎片|是|否|否|
|额外空间需求|较少|需要复制目标空间|较少|
|典型适用场景|传统老年代收集器|年轻代|传统老年代收集器|
|典型收集器|CMS|Serial、Parallel 的年轻代|Serial Old|

**为什么老年代通常不采用传统复制算法？**

因为老年代对象存活率高。

假设老年代有 1000 个对象，其中 900 个存活。

如果采用复制算法，就需要移动大量对象，而且还要预留足够的目标空间。

因此，传统分代收集器在老年代通常更倾向于标记-清除或标记-整理。

## **五、G 1 垃圾收集器也是这样吗？**

这里需要特别注意。

前面介绍的是传统分代垃圾收集器的典型情况。

**G 1 虽然也区分年轻代和老年代，但它不再使用传统的连续年轻代、老年代布局。**

G 1 将堆划分为多个 Region：

```text
G1 堆：

┌────┬────┬────┬────┐
│ E  │ O  │ S  │ E  │
├────┼────┼────┼────┤
│ O  │ E  │ O  │ S  │
├────┼────┼────┼────┤
│ E  │ O  │ H  │ E  │
└────┴────┴────┴────┘

E：Eden
S：Survivor
O：Old
H：Humongous
```

G 1 在回收选定 Region 时，通常通过 **Evacuation（对象转移）** 将存活对象复制到其他 Region。

因此，不能简单地认为：

G 1 年轻代使用复制算法，老年代一定使用标记-整理算法。

G 1 的正常回收过程包含并发标记和对象转移等机制，只有在某些特殊情况下才会退化到 Full GC。

## Q：

JVM 采用分代收集，主要是基于弱分代假说，也就是绝大多数对象生命周期很短，只有少量对象能够长期存活。

因此，JVM 将堆划分为年轻代和老年代，针对不同对象的存活特点采用不同的回收策略。

**年轻代通常采用复制算法。** 因为年轻代对象死亡率高，每次 GC 后只有少量对象存活，只需要将这些存活对象复制到 Survivor 区或者晋升到老年代，就可以回收大量空间，而且不会产生内存碎片。

**老年代在传统分代收集器中主要采用标记-清除或者标记-整理算法。** 因为老年代对象存活率较高，如果使用传统复制算法，需要移动大量对象，成本较高。

标记-清除的优点是不需要移动存活对象，但容易产生内存碎片；标记-整理能够解决碎片问题，但需要移动对象。

不过，具体使用什么算法还要看垃圾收集器，例如 G 1 使用 Region 进行内存管理，其正常回收过程主要涉及对象转移，不能完全套用传统分代收集器的分类。

**一句话总结：年轻代对象死得多，适合复制；老年代对象活得多，传统收集器适合标记-清除或标记-整理。**
