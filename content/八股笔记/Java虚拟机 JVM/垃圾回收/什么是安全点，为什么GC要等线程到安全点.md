
[[#Q：什么是安全点？为什么 GC 要等线程到达安全点？]]

Java 中的**安全点（Safepoint）**，是 JVM 能够安全地暂停 Java 线程，执行某些需要线程状态稳定的操作的位置。

它和垃圾回收（GC）密切相关，尤其是 **Stop The World（STW）**。

先记住一句话：

**安全点就是 JVM 能够准确识别线程中的对象引用，并安全地暂停线程的位置。GC 中某些需要 STW 的阶段，必须等待相关 Java 线程进入安全状态后才能执行。**

## **一、为什么 GC 需要安全点？**

我们之前学过，GC 通过**可达性分析算法**判断对象是否存活。

例如：

```java
public void test() {
    User user = new User();
    user.hello();
}
```

假设执行过程中：

```text
虚拟机栈                      堆
   │                          │
   │                          │
 user 引用 ─────────────────→ User对象
```

GC 需要知道：

**当前线程中，哪些变量保存了对象引用？这些引用指向哪些对象？**

但问题来了：

Java 程序在执行过程中，对象引用可能不断发生变化。

例如：

```java
User user = new User();

user = new User();

user = null;
```

如果 GC 在某个需要全局一致视图的阶段检查对象引用，而应用线程又同时修改引用关系，就可能导致分析结果不一致。

因此，JVM 在某些 GC 阶段需要暂停应用线程，让对象引用状态保持稳定。

这就是 STW。

不过还有一个问题：

**JVM 为什么不直接在任意一条指令处暂停线程呢？**

因为在任意位置暂停线程，JVM 不一定能方便、准确地判断哪些寄存器或栈槽保存着对象引用。

这就引出了安全点。

---

## **二、什么是安全点？⭐⭐⭐⭐⭐**

安全点是 JVM 在程序执行过程中设置的一些特殊位置。

当线程到达安全点时，JVM 能够获得准确的对象引用信息，并在需要时安全地暂停线程。

例如：

```text
Java 线程执行过程

指令1 → 指令2 → 指令3 → 指令4 → 指令5 → 指令6
                 ↑                         ↑
               安全点                    安全点
```

假设 JVM 发起一次需要 STW 的 GC：

```text
线程执行到指令1
      ↓
JVM 请求进入安全点
      ↓
线程继续执行
      ↓
到达指令3（安全点）
      ↓
线程暂停
      ↓
等待 GC
```

也就是说：

**JVM 不需要在每一条机器指令处都设置安全点，而是在特定位置设置安全点。**

这样既能支持 GC，又能减少运行时检查带来的额外开销。

### **安全点通常出现在哪里？**

常见位置包括：

- 方法调用相关的位置。
- 循环回边（例如循环跳转到下一轮的位置）。
- 某些可能阻塞或需要运行时协作的位置。

具体安全点的位置取决于 JVM 和 JIT 编译器的实现，并不是每一次方法调用或循环都必然对应一个独立安全点。

## **三、为什么 GC 要等线程到达安全点？⭐⭐⭐⭐⭐**

主要有两个原因。

### **原因一：保证 GC 能准确找到对象引用**

假设：

```java
public void test() {
    User user = new User();
    user.hello();
}
```

程序执行时，`user` 的引用可能存放在：

- 虚拟机栈中的某个位置。
- CPU 寄存器中。

那么 GC 怎么知道哪个位置保存着对象引用？

HotSpot JVM 使用一种称为 **OopMap** 的数据结构。

你可以简单理解为：

**OopMap 是 JVM 记录特定执行位置上，哪些寄存器或栈槽保存对象引用的信息。**

例如：

```text
线程执行到安全点
       ↓
查看 OopMap
       ↓
发现：

寄存器 R1 → User对象
栈槽 S2   → Order对象
       ↓
GC 根据这些引用寻找存活对象
```

这样 JVM 就不需要把所有寄存器和栈槽中的数值都猜测一遍。

**安全点的重要作用，就是让 JVM 能在已知的位置获取准确的引用信息。**

### **原因二：避免任意位置暂停带来的复杂性和开销**

假设一段程序有 10000 条机器指令。

如果 JVM 要支持在任意指令位置安全暂停，就可能需要为大量执行位置维护精确的对象引用信息。

这样会带来：

- 更多的元数据开销。
- 更复杂的编译器实现。
- 更高的运行时维护成本。

因此，JVM 选择在有限的安全点维护必要的信息。

```text
方案 A：每条指令都支持安全暂停

指令1  指令2  指令3  指令4  指令5
  ↑      ↑      ↑      ↑      ↑
 信息   信息   信息   信息   信息


方案 B：只在特定位置设置安全点

指令1 → 指令2 → 指令3 → 指令4 → 指令5
                  ↑
                安全点
```

显然，第二种方式通常更加高效。

## **四、GC 等待安全点的过程是什么？⭐⭐⭐⭐⭐**

假设 JVM 中有三个 Java 线程：

```text
Thread A
Thread B
Thread C
```

当 GC 需要执行一次全局 STW 操作时：

**第一步：JVM 发起安全点请求**

```text
              JVM
               │
        发起安全点请求
               │
       ┌───────┼───────┐
       ▼       ▼       ▼
    Thread A Thread B Thread C
```

**第二步：线程陆续进入安全状态**

```text
Thread A：执行 → 安全点 → 暂停

Thread B：执行 → 执行 → 安全点 → 暂停

Thread C：执行 → 执行 → 执行 → 安全点 → 暂停
```

对于正在运行 Java 代码的线程，通常需要执行到可以响应安全点请求的位置。

已经处于某些阻塞状态或执行 Native 代码的线程，则可能通过其他安全状态检查机制参与协调，不一定要先恢复执行 Java 代码。

**第三步：完成线程协调**

```text
Thread A：已暂停
Thread B：已暂停
Thread C：已暂停
             ↓
      满足 STW 条件
             ↓
       执行 GC 阶段
```

**第四步：恢复应用线程**

```text
GC 阶段结束
     ↓
Thread A 恢复
Thread B 恢复
Thread C 恢复
```

整个过程可以概括为：

**发起安全点请求 → 线程进入安全状态 → 执行 STW 操作 → 恢复线程。**

需要注意，现代垃圾收集器（例如 G 1、ZGC）能够并发完成部分 GC 工作，因此**不是每次 GC 都需要让所有应用线程从头到尾保持暂停**。

## **五、安全点和 STW 有什么区别？**

这两个概念非常容易混淆。

|**对比**|**安全点（Safepoint）**|**STW（Stop The World）**|
|---|---|---|
|本质|线程能够安全暂停的执行位置|暂停应用线程的一种状态|
|主要作用|提供安全暂停及准确引用信息的条件|为特定 JVM 操作提供稳定的执行环境|
|是否等于 GC|不是|不是|
|两者关系|是实现某些 STW 操作的重要机制|某些 STW 操作需要安全点协调|

可以用一个简单的比喻理解：

**安全点就像高速公路上的服务区，STW 就像要求所有车辆暂停行驶。**

如果管理人员需要统一检查车辆：

1. 发出暂停通知。
2. 车辆行驶到合适的停车位置。
3. 所有车辆进入安全状态。
4. 开始统一检查。
5. 检查完成后恢复行驶。

这里：

- **服务区对应安全点。**
- **车辆暂停对应 STW。**
- **统一检查对应需要暂停线程的 GC 操作。**

这个比喻是为了帮助理解，实际 JVM 中的线程协调比它更复杂。

## Q：什么是安全点？为什么 GC 要等线程到达安全点？

你可以这样回答：

安全点是 JVM 在程序执行过程中设置的一些特殊位置，在这些位置上，JVM 能够准确获取线程中的对象引用信息，并安全地暂停线程。

GC 需要安全点主要有两个原因。

第一，GC 需要通过可达性分析判断对象是否存活，而对象引用可能存放在栈或寄存器中。HotSpot 可以通过安全点对应的 OopMap 获取准确的引用信息。

第二，如果允许线程在任意指令位置暂停，就需要维护大量引用信息，会增加 JVM 的实现复杂度和运行开销，所以 JVM 通常只在特定位置设置安全点。

当 GC 需要执行 STW 阶段时，JVM 会发起安全点请求，等待相关 Java 线程进入安全状态，然后执行垃圾回收操作，完成后再恢复线程。

不过，现代垃圾收集器有很多并发回收阶段，并不是所有 GC 工作都必须等待全部应用线程暂停。

### **最后记住一句话**

**安全点解决的是“线程在哪里可以安全暂停”，STW 解决的是“什么时候需要暂停线程”。GC 等待安全点，是为了在可控的执行位置获取准确的对象引用信息，并安全地完成需要暂停线程的回收工作。**
