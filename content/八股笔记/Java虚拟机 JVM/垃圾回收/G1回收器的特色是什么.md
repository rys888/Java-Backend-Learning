
G 1（Garbage First）是 Java 中非常重要的垃圾收集器，也是 Java 后端面试的高频考点。

**G 1 最大的特色是：基于 Region 管理堆内存，优先回收收益较高的区域，通过对象复制减少内存碎片，并尽可能控制 GC 停顿时间。**

对于 Java 后端实习面试，我建议重点掌握以下 **5 个特点**。

## **一、基于 Region 管理堆内存 ⭐⭐⭐⭐⭐**

传统分代垃圾收集器通常将堆划分为连续的新生代和老年代：

```text
传统分代垃圾收集器

┌──────────────────────────────┐
│            Java 堆           │
├──────────────┬───────────────┤
│    新生代     │     老年代     │
│ Eden / S0/S1 │      Old      │
└──────────────┴───────────────┘
```

而 G 1 将整个堆划分为多个大小相同的 **Region（区域）**。

```text
               G1 堆内存

┌──────┬──────┬──────┬──────┐
│ Eden │ Old  │ Eden │ Old  │
├──────┼──────┼──────┼──────┤
│  S   │ Old  │ Eden │ Free │
├──────┼──────┼──────┼──────┤
│ Old  │ Free │  S   │ Old  │
└──────┴──────┴──────┴──────┘
```

每个 Region 可以承担不同的角色：

- **Eden Region**：存储新创建的对象。
- **Survivor Region**：存储经历 GC 后仍然存活的年轻代对象。
- **Old Region**：存储长期存活的对象。
- **Humongous Region**：存储特别大的对象。
- **Free Region**：尚未分配用途的空闲区域。

需要注意：

**G 1 并没有取消分代思想，而是让新生代和老年代不必在物理上连续。**

这样 JVM 就能更加灵活地调整不同代所占用的 Region 数量。

---

## **二、优先回收收益较高的 Region ⭐⭐⭐⭐⭐**

这是 G 1 名称的由来。

Garbage First 可以理解为：

**优先选择垃圾回收收益较高的区域。**

假设：

```text
Region A：垃圾占比 80%

Region B：垃圾占比 20%

Region C：垃圾占比 60%
```

如果只考虑垃圾比例，那么回收 Region A 显然更划算。

但是，实际的 G 1 并不是简单按照垃圾比例排序。

它还会考虑：

- Region 中存活对象的数量。
- 复制存活对象需要的时间。
- 预计能够回收多少内存。
- 当前设定的 GC 停顿时间目标。

例如：

```text
Region A
垃圾：80MB
存活：20MB

Region B
垃圾：30MB
存活：70MB
```

通常来说，Region A 的回收收益可能更高，因为需要复制的存活对象更少。

因此，G 1 会根据回收收益和预计成本选择回收集合（Collection Set，简称 CSet）。

**不过，G 1 的 Young GC 需要回收年轻代的相关 Region；这种收益选择机制主要体现在选择混合回收中的老年代 Region。**

---

## **三、能够减少内存碎片 ⭐⭐⭐⭐⭐**

你刚刚学习过 CMS 和 G 1 的区别。

CMS 主要使用**标记-清除算法**，容易产生内存碎片。

例如：

```text
CMS 回收前：

[A][垃圾][B][垃圾][C][垃圾]

CMS 回收后：

[A][空闲][B][空闲][C][空闲]
```

虽然回收了垃圾，但是空闲内存不连续。

而 G 1 的常规区域回收主要使用**复制算法**。

假设：

```text
Region A：

[A][垃圾][B][垃圾][C]
```

G 1 会将存活对象复制到其他 Region：

```text
Region B：

[A][B][C][          ]
```

然后释放原来的 Region A：

```text
Region A：

[                    ]
```

这样 Region A 就可以整体重新利用。

因此：

**G 1 通过复制和转移存活对象，能够有效减少内存碎片。**

但它也不是完全不存在内存碎片问题，例如特别大的对象可能带来空间利用率问题。

---

## **四、能够尽量控制 GC 停顿时间 ⭐⭐⭐⭐⭐**

这是 G 1 非常重要的特色。

我们之前学过：

**GC 在某些阶段需要 Stop The World（STW），暂停应用线程。**

假设一个 Java 后端服务正常响应时间是 20 ms。

如果某次 GC 造成 500 ms 的停顿：

```text
正常请求：

请求 → 业务处理 → 响应
         20ms


发生 GC：

请求 → STW → 业务处理 → 响应
        500ms    20ms
```

请求耗时就可能明显增加。

G 1 可以设置 GC 停顿时间目标：

```bash
-XX:MaxGCPauseMillis=200
```

表示希望将 GC 停顿控制在约 200 ms 的目标范围内。

G 1 会根据这个目标，动态调整回收策略。

例如：

```text
预计回收 Region A：30ms

预计回收 Region B：50ms

预计回收 Region C：100ms

预计回收 Region D：150ms
```

G 1 会综合考虑回收收益和预计停顿成本，决定本轮适合回收哪些 Region。

当然，实际回收还存在一些必须完成的工作，并不是任意 Region 都可以自由选择。

**注意：200 ms 是软目标，不代表 G 1 能保证每次 GC 都不超过 200 ms。**

---

## **五、支持并发标记和混合回收 ⭐⭐⭐⭐**

G 1 不仅可以回收新生代，还可以通过混合回收处理部分老年代 Region。

主要有三种需要了解的工作方式。

### **1. Young GC**

主要回收年轻代 Region。

```text
Eden + Survivor
        ↓
      Young GC
        ↓
回收垃圾、转移存活对象
```

通常需要 STW。

### **2. Concurrent Mark（并发标记）**

当堆内存占用达到一定条件时，G 1 可以启动并发标记周期。

```text
应用线程：████████████████████████

GC线程：      ██████████████
```

G 1 可以在应用继续执行的同时，分析堆中对象的存活情况。

但并发标记周期中的初始标记、重新标记等阶段仍然需要短暂 STW。

### **3. Mixed GC（混合回收）**

这是 G 1 非常有代表性的特点。

**Mixed GC 会回收年轻代 Region，以及经过筛选的部分老年代 Region。**

```text
              G1 堆

Eden Region ──────┐
                  │
Survivor Region ──┼──→ Mixed GC
                  │
部分 Old Region ──┘
```

为什么不一次性回收所有老年代 Region？

因为 G 1 希望控制单次回收的停顿时间。

所以它会根据回收收益和停顿目标，分批回收合适的老年代 Region。

这也是 G 1 与传统 Full GC 的重要区别。

---

## **六、G 1 的五个特色总结**

|**特色**|**核心作用**|
|---|---|
|**Region 分区管理**|灵活管理年轻代和老年代|
|**优先回收高收益区域**|提高垃圾回收效率|
|**复制算法**|减少内存碎片|
|**可预测停顿时间模型**|尽量控制 GC 停顿|
|**并发标记 + Mixed GC**|在减少长时间停顿的同时回收老年代垃圾|

### **G 1 就一定比其他垃圾收集器好吗？**

不一定。

G 1 需要维护 Region 之间的引用关系，并进行存活对象复制，因此会产生额外的 CPU 和内存开销。

如果业务更注重吞吐量，Parallel GC 可能是合适的选择。

如果业务对延迟要求极高，ZGC 可能更有优势。

所以选择垃圾收集器时，仍然需要结合应用的实际性能表现。

---

## **七、面试怎么回答？⭐⭐⭐⭐⭐**

如果面试官问：

**“G 1 垃圾收集器有什么特色？”**

你可以这样回答：

G 1 是一种兼顾吞吐量和停顿时间的垃圾收集器，主要有五个特点。

第一，**Region 分区管理**。G 1 将整个 Java 堆划分为多个大小相同的 Region，仍然保留分代思想，但是年轻代和老年代不需要连续分布。

第二，**优先回收高收益区域**。G 1 会根据 Region 的垃圾回收收益和预计回收成本，选择合适的区域进行回收。

第三，**减少内存碎片**。G 1 主要通过复制和转移存活对象来回收 Region，相比 CMS 的标记-清除算法，能够有效减少内存碎片。

第四，**控制 GC 停顿时间**。G 1 可以通过 `MaxGCPauseMillis` 设置停顿时间目标，并动态调整回收策略，但这个目标并不是绝对保证。

第五，**支持并发标记和混合回收**。G 1 可以并发分析对象存活情况，并通过 Mixed GC 回收年轻代和部分老年代 Region，避免每次都进行全堆回收。

### **最后记住一句口诀**

**G 1 五大特色：分区管理、收益优先、复制整理、停顿可控、混合回收。**

其中最重要的三个关键词是：

**Region、Garbage First、可预测停顿时间。**

把这三个概念讲清楚，再补充 G 1 通过复制减少内存碎片、通过 Mixed GC 回收部分老年代，就足以应对大部分 Java 后端实习面试中的 G 1 基础问题。
