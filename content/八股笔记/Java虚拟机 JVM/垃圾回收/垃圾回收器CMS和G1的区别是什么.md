
CMS 和 G 1 都是以**降低 GC 停顿时间**为重要目标的垃圾收集器，但它们最大的区别在于：

**CMS 主要使用标记-清除算法回收老年代，容易产生内存碎片；G 1 将堆划分为多个 Region，通过标记、复制和整理等方式回收垃圾，能够减少内存碎片，并尽量控制 GC 停顿时间。**

对于 Java 后端实习面试，这道题重点掌握 **回收范围、垃圾回收算法、内存碎片、STW 和回收效率**即可。

## **一、CMS 和 G 1 的核心区别 ⭐⭐⭐⭐⭐**

先看对比表：

|**对比维度**|**CMS**|**G 1**|
|---|---|---|
|全称|Concurrent Mark Sweep|Garbage First|
|回收范围|主要负责老年代|管理整个 Java 堆|
|内存布局|传统连续分代布局|将堆划分为多个 Region|
|核心回收算法|标记-清除|标记、复制、整理|
|内存碎片|容易产生碎片|通过对象转移减少碎片|
|STW|初始标记、重新标记等阶段需要|Young GC、Mixed GC 等阶段需要|
|停顿时间|以降低停顿为目标|可以设置停顿时间目标|
|并发回收|支持|支持|
|JDK 状态|JDK 14 已移除|JDK 9 起成为 HotSpot 默认 GC|

需要特别注意：**CMS 和 G 1 都不能完全避免 STW。**

---

## **二、CMS：标记-清除，容易产生内存碎片**

CMS 的主要目标是减少老年代垃圾回收造成的停顿。

它主要经历四个阶段。

### **1. 初始标记（Initial Mark）**

标记与 GC Roots 直接关联的对象。

**需要 STW，但通常比较快。**

### **2. 并发标记（Concurrent Mark）**

从 GC Roots 出发，遍历对象引用关系，标记存活对象。

**可以与应用线程并发执行。**

### **3. 重新标记（Remark）**

修正并发标记期间，由于应用线程继续运行而产生的标记变化。

**需要 STW。**

### **4. 并发清除（Concurrent Sweep）**

清理垃圾对象占用的内存。

**可以与应用线程并发执行。**

整体流程：

```text
                 CMS 回收流程

初始标记 → 并发标记 → 重新标记 → 并发清除
   │          │          │          │
  STW        并发       STW        并发
```

### **CMS 最大的问题：内存碎片**

假设老年代中存在以下对象：

```text
GC 前：

[A][垃圾][B][垃圾][C][垃圾]
```

CMS 使用标记-清除算法：

```text
GC 后：

[A][空闲][B][空闲][C][空闲]
```

虽然垃圾对象被回收了，但空闲内存并不连续。

假设：

```text
[空闲2MB][对象A][空闲2MB]
```

现在需要分配一个连续的 3 MB 对象。

虽然总空闲空间有 4 MB，但是没有连续的 3 MB 空间。

这可能导致分配失败，甚至需要触发 Full GC 进行整理。

另外，CMS 在并发回收期间，如果老年代空间不足，还可能发生 **Concurrent Mode Failure（并发模式失败）**，导致退化为停顿时间较长的回收方式。

**一句话：CMS 可以并发回收老年代，但标记-清除容易产生内存碎片。**

## **三、G 1：Region 分区管理，减少内存碎片 ⭐⭐⭐⭐⭐**

G 1 最大的特点是：

**不再要求新生代和老年代分别占据连续的大块内存，而是将堆划分为多个大小相同的 Region。**

例如：

```text
                  G1 堆内存

┌──────┬──────┬──────┬──────┐
│ Eden │ Old  │ Eden │ Old  │
├──────┼──────┼──────┼──────┤
│  S   │ Old  │ Eden │ Free │
├──────┼──────┼──────┼──────┤
│ Old  │ Free │  S   │ Old  │
└──────┴──────┴──────┴──────┘
```

其中：

- **Eden Region**：存储新创建的对象。
- **Survivor Region**：存储经历 GC 后仍然存活的年轻代对象。
- **Old Region**：存储长期存活的对象。
- **Free Region**：尚未使用的区域。

虽然 G 1 仍然采用分代思想，但这些 Region 可以分散在堆中。

### **1. G 1 如何回收垃圾？**

假设有三个 Region：

```text
Region A：垃圾占比 80%

Region B：垃圾占比 20%

Region C：垃圾占比 60%
```

G 1 会根据每个 Region 的回收收益、存活对象复制成本和停顿时间目标等因素，选择合适的 Region 进行回收。

这也是 Garbage First 名称的由来。

但要注意，G 1 并不是每次都简单选择垃圾最多的 Region；例如 Young GC 就主要针对年轻代 Region。

### **2. G 1 为什么不容易产生内存碎片？**

关键在于**对象复制和转移（Evacuation）**。

假设：

```text
Region A：

[A][垃圾][B][垃圾][C]
```

G 1 可以将存活对象复制到其他 Region：

```text
Region B：

[A][B][C][          ]
```

然后将原来的 Region A 整体释放：

```text
Region A：

[                    ]
```

这样就能获得完整的空闲 Region。

相比 CMS 的标记-清除算法，G 1 可以通过对象转移有效减少内存碎片。

不过，G 1 并不是绝对不会发生碎片或分配失败。

### **3. G 1 可以控制 GC 停顿时间**

例如：

```bash
-XX:MaxGCPauseMillis=200
```

表示希望 GC 停顿时间控制在 200 ms 左右。

G 1 会根据这个目标，动态调整年轻代大小、回收集合等。

**但是 200 ms 只是软目标，并不保证每次 GC 都在 200 ms 内完成。**

## **四、CMS 和 G 1 在 STW 方面有什么区别？**

这是面试官可能追问的重点。

你之前刚学过安全点和 STW，可以联系起来理解。

### **CMS**

```text
初始标记 → 并发标记 → 重新标记 → 并发清除
   │          │          │          │
  STW        并发       STW        并发
```

CMS 的部分标记、清除工作可以与应用线程同时进行。

但由于使用标记-清除算法，可能产生内存碎片。

### **G 1**

G 1 的回收过程更加复杂，包括：

- Young GC：回收年轻代 Region，通常需要 STW。
- Concurrent Mark：并发标记，部分阶段需要短暂 STW。
- Mixed GC：回收年轻代和部分老年代 Region，通常需要 STW。

因此：

**CMS 和 G 1 都有并发阶段，也都有 STW 阶段。**

两者最大的区别并不是谁有 STW、谁没有 STW，而是：

**CMS 通过并发标记和并发清除降低老年代回收停顿；G 1 通过 Region 管理、并发标记以及选择性回收和对象转移，在减少碎片的同时尽量满足停顿时间目标。**

## **五、为什么 G 1 逐渐取代 CMS？**

主要有三个原因。

**第一，CMS 容易产生内存碎片。**

CMS 使用标记-清除算法，回收后可能出现大量不连续的空闲空间。

G 1 通过复制和转移存活对象，能够有效减少碎片。

**第二，G 1 能够更灵活地控制停顿时间。**

CMS 的主要目标是尽量降低停顿。

而 G 1 可以根据停顿时间目标，动态选择回收范围。

**第三，G 1 能够统一管理整个堆。**

CMS 主要负责老年代，通常需要搭配年轻代收集器，例如 ParNew。

G 1 则可以统一管理年轻代和老年代，并支持 Young GC 和 Mixed GC。

因此，G 1 从 JDK 9 开始成为 HotSpot 的默认垃圾收集器，而 CMS 最终在 JDK 14 被移除。

不过，**G 1 并不意味着在所有场景下性能都优于 CMS**。垃圾收集器的实际表现仍然取决于应用负载、堆大小和 JVM 配置。

## **六、面试怎么回答？⭐⭐⭐⭐⭐**

如果面试官问：

**“CMS 和 G 1 垃圾收集器有什么区别？”**

你可以这样回答：

CMS 和 G 1 都是以降低 GC 停顿时间为重要目标的垃圾收集器，但它们在内存管理和回收算法上有较大区别。

首先，CMS 主要负责老年代回收，采用标记-清除算法，能够在并发标记和并发清除阶段与应用线程同时执行，但是容易产生内存碎片。

而 G 1 将整个 Java 堆划分为多个 Region，通过 Region 管理年轻代和老年代，并根据回收收益和停顿时间目标选择合适的区域进行回收。

其次，G 1 通过复制和转移存活对象来释放 Region，能够减少内存碎片，而 CMS 的标记-清除算法容易造成碎片化。

最后，G 1 可以通过 `MaxGCPauseMillis` 设置停顿时间目标，在吞吐量和停顿时间之间进行平衡。

因此，相比 CMS，G 1 在内存碎片控制和停顿时间管理方面具有优势，而且从 JDK 9 开始成为 HotSpot 默认垃圾收集器。

---

## **七、最后记住三个重点**

|**核心区别**|**CMS**|**G 1**|
|---|---|---|
|**回收范围**|主要负责老年代|管理整个堆|
|**回收算法**|标记-清除，容易产生碎片|复制、整理，减少碎片|
|**停顿控制**|尽量降低停顿|根据停顿目标选择回收区域|

**一句话记忆：CMS 是老年代并发标记清除，容易产生内存碎片；G 1 是基于 Region 的垃圾收集器，通过对象转移减少碎片，并尽量控制 GC 停顿时间。**

对于 Java 后端实习面试，重点理解这三个区别就足够应对大部分基础追问。
