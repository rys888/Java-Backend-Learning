[[#Q：Java 有哪些垃圾收集器？]]

Java 里常见的垃圾收集器主要有 **Serial、ParNew、Parallel、CMS、G1、ZGC 和 Shenandoah**。面试不用把每个收集器的底层实现都背下来，重点是知道它们各自有什么特点、适用于什么场景，以及彼此之间有什么区别。

## 一、Java 常见的垃圾收集器

先看一个整体分类：

```text
              Java 垃圾收集器
                     │
        ┌────────────┴────────────┐
        │                         │
     经典收集器                现代收集器
        │                         │
   ┌────┼────┐              ┌─────┼─────┐
   │    │    │              │     │     │
 Serial Parallel CMS         G1   ZGC  Shenandoah
   │
 ParNew（与 Serial 类似的年轻代并行收集器）
```

这个分类只是为了方便学习，不是 JVM 官方严格的划分方式。

### 1. Serial GC：串行垃圾收集器

**Serial 只有一个 GC 工作线程，回收期间要暂停所有应用线程。**

```text
应用线程：████████      ████████
GC线程：          ████
                  ↑
             Stop The World
```

这里的 **Stop The World（STW）**，就是垃圾回收期间暂停应用线程的执行。Serial 实现简单、GC 时要停顿，适合堆较小、CPU 资源有限的场景。

一句话：**Serial GC 是单线程垃圾回收器。**

### 2. ParNew GC：并行年轻代垃圾收集器

ParNew 可以理解成 Serial 年轻代收集器的多线程版本，用多个 GC 线程并行回收年轻代。

```text
应用线程：████████          ████████

GC线程1：        ████
GC线程2：        ████
GC线程3：        ████
```

它的特点是多个 GC 线程并行回收年轻代，回收期间仍然需要 STW，历史上经常和 CMS 配合使用。ParNew 属于比较老的收集器，在现代 JDK 里已经被移除了。

### 3. Parallel GC：并行垃圾收集器 ⭐⭐⭐⭐

Parallel GC 同样用多个线程执行垃圾回收，但它更注重**吞吐量**。什么是吞吐量？假设程序运行 100 秒，执行业务代码 95 秒、垃圾回收 5 秒，那么吞吐量就是 95 / (95 + 5) = 95%。Parallel GC 的目标就是让 CPU 尽可能多地执行用户代码，而不是拿去做 GC。

它的特点：多线程并行回收，**GC 期间存在 STW**，注重吞吐量，适合批处理、后台计算这类场景。回收工作全部在 STW 期间完成。

一句话：**Parallel GC 追求高吞吐量。**

### 4. CMS：并发标记清除收集器 ⭐⭐⭐⭐

CMS 全称 **Concurrent Mark Sweep**，即并发标记清除。它的主要目标是**尽可能减少垃圾回收造成的应用停顿**，部分工作可以和应用线程并发执行。

```text
应用线程：██████████████████████████

GC线程：     ██████████████
                 ↑
             并发执行
```

不过 CMS 并不是完全没有 STW，比如初始标记和重新标记阶段仍然需要暂停应用线程。它的主要缺点有三个：使用标记-清除算法，容易产生内存碎片；并发回收要占用一部分 CPU 资源；可能发生并发模式失败，反而导致更严重的停顿。

**CMS 已经在 JDK 14 中被移除**，现在主要作为历史知识了解。

一句话：**CMS 追求低停顿，但存在内存碎片问题。**

## 二、G1 GC：现代 Java 里的重点 ⭐⭐⭐⭐⭐

G1 全称 **Garbage First Garbage Collector**，从 **JDK 9 开始成为 HotSpot Server VM 的默认垃圾收集器**，面试里非常值得重点掌握。

### 1. G1 的核心特点

传统分代收集器通常把堆划分成连续的新生代和老年代，G1 不一样，它把堆拆成很多个大小相同的 Region。

```text
                G1 堆内存

┌──────┬──────┬──────┬──────┐
│ Eden │ Old  │ Eden │ Old  │
├──────┼──────┼──────┼──────┤
│  S   │ Old  │ Eden │ Free │
├──────┼──────┼──────┼──────┤
│ Old  │ Free │  S   │ Old  │
└──────┴──────┴──────┴──────┘
```

其中 Eden 存放新创建的对象，Survivor 存放经历 GC 后仍然存活的年轻代对象，Old 存放长期存活的对象，Free 是空闲 Region。**G1 仍然保留分代思想，只是不同代的 Region 不必连续排列。**

### 2. 为什么叫 Garbage First？

因为 G1 会估算不同 Region 的垃圾回收收益和回收成本，在满足停顿时间目标的前提下，优先选择回收收益较高的 Region。

比如 A、B、C 三个 Region 的垃圾占比分别是 80%、20%、60%，G1 不会只盯着垃圾比例最高的那个，而是把垃圾量、存活对象复制成本这些因素一起算进去，综合判断哪些 Region 值得回收。并不是简单地只看垃圾比例。

### 3. G1 的优点

可以并发执行部分垃圾回收工作，用 Region 管理堆内存，支持年轻代回收和混合回收，能根据停顿时间目标调整回收策略，还通过对象转移和整理减少内存碎片。

启用 G1 用 `-XX:+UseG1GC`。也可以设置停顿时间目标，比如 `-XX:MaxGCPauseMillis=200`，表示希望 GC 停顿控制在约 200 ms 的目标范围内。**注意：200 ms 是软目标，不是 JVM 保证的最大停顿时间。**

一句话：**G1 通过 Region 管理堆，兼顾吞吐量和可预测的停顿时间。**

## 三、ZGC：低延迟垃圾收集器 ⭐⭐⭐⭐

ZGC 的核心目标是**尽可能缩短垃圾回收导致的应用停顿**。它和 G1 最大的区别在设计侧重点：G1 更注重吞吐量与停顿时间之间的平衡，ZGC 则更注重低延迟。

ZGC 的停顿时间短，是因为它把大量垃圾回收工作设计成和应用线程并发执行。

```text
G1：

应用线程：████████    ████████    ████████
GC停顿：          ████        ████


ZGC：

应用线程：████████████████████████████
GC线程：     █████████████████
                 ↑
             大量工作并发执行
```

上图只是示意，ZGC 仍然有少量 STW 阶段，并不是完全没有停顿。它的特点是以低延迟为主要目标，大量回收工作和应用线程并发执行，能够处理较大的堆，适合对响应时间敏感的应用。

需要注意，ZGC 在不同 JDK 版本里经历了重要演进，比如后来引入的分代 ZGC，所以具体实现和参数会跟着 JDK 版本变化。

## 四、Shenandoah GC

Shenandoah 也是一种低延迟垃圾收集器，设计目标和 ZGC 相似：**尽量让垃圾回收工作和应用线程并发执行，减少 STW 停顿**。不过两者的底层实现机制并不相同。实习面试知道它是一种低延迟垃圾收集器就够了。

## 五、几种垃圾收集器对比 ⭐⭐⭐⭐⭐

| **垃圾收集器** | **主要特点** | **侧重点** |
|---|---|---|
| Serial | 单线程回收 | 简单、低资源开销 |
| ParNew | 多线程年轻代回收 | 并行回收，历史收集器 |
| Parallel | 多线程并行回收 | **高吞吐量** |
| CMS | 并发标记清除 | **低停顿**，已移除 |
| G1 | Region 管理、分代回收 | **吞吐量与停顿时间平衡** |
| ZGC | 大量回收工作并发执行 | **低延迟** |
| Shenandoah | 并发回收与对象转移 | **低延迟** |

这里有个非常容易混的知识点：并行和并发有什么区别？

**并行（Parallel）** 指多个 GC 线程一起执行垃圾回收，GC 期间应用线程可能全部暂停。

```text
应用线程：████████          ████████

GC线程1：        ██████
GC线程2：        ██████
```

**并发（Concurrent）** 指 GC 线程和应用线程在同一时间段内共同推进工作。

```text
应用线程：████████████████████████

GC线程：     ██████████████
```

**并行强调多个 GC 线程一起工作，并发强调 GC 和应用线程能够同时推进。** 两者并不矛盾，一个垃圾收集器可以同时使用并行和并发技术。

## Q：Java 有哪些垃圾收集器？

Java 常见的垃圾收集器包括 Serial、ParNew、Parallel、CMS、G1 和 ZGC 等。

Serial 是单线程垃圾收集器，实现比较简单；Parallel 使用多线程并行回收，主要追求高吞吐量，也就是多执行用户代码而不是做 GC。CMS 是一种以低停顿为目标（GC 期间没有 STW，而 Parallel 是有的）的并发垃圾收集器，但采用标记-清除算法容易产生内存碎片，而且已经在 JDK 14 中被移除。

G1 是比较重要的现代垃圾收集器，把堆划分为多个 Region，根据回收收益和停顿时间目标选择回收区域，**兼顾吞吐量和停顿时间**。ZGC 则更注重低延迟，通过让大量垃圾回收工作与应用线程并发执行，尽可能缩短 STW 停顿。

普通 Java 后端应用，优先了解 G1；如果业务对响应延迟要求非常严格，也可以考虑 ZGC，并结合实际压测结果选择。

**Serial 单线程，Parallel 重吞吐，CMS 降停顿，G1 求平衡，ZGC 低延迟。**
