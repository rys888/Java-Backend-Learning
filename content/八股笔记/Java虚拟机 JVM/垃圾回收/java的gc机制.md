如果面试官问你：**“Java 的 GC 机制你了解哪些？”**

这其实是一道比较综合的 JVM 面试题，考察的不仅仅是垃圾回收的定义，还包括**对象存活判断、垃圾回收算法、分代回收机制以及垃圾收集器**。

对于 Java 后端实习面试，我建议你从以下 **4 个方面**回答。

## **一、GC 如何判断对象是否需要回收？**

Java 主要通过**可达性分析算法**判断对象是否存活。

JVM 从一组称为 **GC Roots** 的根引用出发，沿着引用关系寻找对象。

```text
                 GC Roots
                    │
             ┌──────┴──────┐
             ▼             ▼
           对象 A         对象 B
             │
             ▼
           对象 C


           对象 D ←→ 对象 E
```

其中：

- A、B、C：能够从 GC Roots 到达，属于存活对象。
- D、E：无法从 GC Roots 到达，可以被垃圾回收。

常见的 GC Roots 包括虚拟机栈中的引用、类静态字段中的引用以及 JNI 引用等。

**核心理解：GC 主要回收的是无法从 GC Roots 到达的对象。**

## **二、GC 有哪些垃圾回收算法？⭐⭐⭐⭐⭐**

当 JVM 找到需要回收的对象后，还需要考虑如何回收它们。

主要有三种经典算法。

### **1. 标记-清除算法（Mark-Sweep）**

分为两个步骤：

1. 标记需要保留的存活对象。
2. 清除未被标记的垃圾对象。 
![[截屏2026-10-09 19.50.30.png|404]]
**优点：** 不需要移动存活对象。

**缺点：** 容易产生内存碎片。

假设：

```text
[空闲 2MB][对象][空闲 2MB]
```

虽然总共有 4 MB 空闲空间，但如果需要分配一个连续的 3 MB 对象，可能仍然无法成功。

### **2. 标记-复制算法（Mark-Copying）**

将可用内存划分为不同区域，把存活对象复制到另一块区域，再整体回收原来的区域。
![[截屏2026-10-09 19.52.02.png|325]]
**优点：**

- 不容易产生内存碎片。
- 当存活对象较少时，回收效率较高。

**缺点：**

- 需要额外的空间存放复制后的对象。
- 存活对象较多时，复制成本较高。

**典型应用：** 经典分代垃圾收集器中的新生代回收。

### **3. 标记-整理算法（Mark-Compact）**

同样先标记存活对象，但是不会直接清除垃圾，而是将存活对象向内存的一端移动。
![[截屏2026-10-09 19.53.17.png|302]]

**优点：** 不容易产生内存碎片，也不需要像复制算法那样预留完整的复制区域。

**缺点：** 移动存活对象需要一定的时间成本，还可能需要更新对象引用。

**典型应用：** 一些老年代垃圾收集器。

### **三种算法对比**

|**算法**|**核心操作**|**主要缺点**|
|---|---|---|
|标记-清除|标记存活对象，清除垃圾|内存碎片|
|标记-复制|将存活对象复制到其他区域|复制开销、额外空间|
|标记-整理|将存活对象移动到一端|对象移动开销|

**一句话记忆：清除有碎片，复制占空间，整理要移动。**

## **三、什么是分代垃圾回收机制？⭐⭐⭐⭐⭐**

这是 Java GC 中非常重要的思想。

JVM 发现，大多数 Java 对象的生命周期比较短，而少部分对象会长期存活。

因此，经典分代垃圾回收机制将堆划分为：

```text
                  Java 堆
                     │
          ┌──────────┴──────────┐
          │                     │
        新生代                 老年代
          │                     │
    ┌─────┼─────┐               │
    │     │     │               │
   Eden   S0    S1             Old
```

### **1. 新生代**

新创建的对象通常优先分配在 Eden 区。

例如：

```java
public void test() {
    for (int i = 0; i < 1000; i++) {
        User user = new User();
    }
}
```

这些临时对象生命周期通常比较短。

当 Eden 空间不足时，经典分代收集器通常会触发 **Minor GC（Young GC）**。

存活的对象可能被复制到 Survivor 区。

经过多次 GC 仍然存活的对象，可能晋升到老年代。

### **2. 老年代**

老年代主要用于存储存活时间较长的对象。

例如，长期被引用的缓存对象、单例对象等。

当老年代内存压力较大时，JVM 可能执行老年代回收，必要时进行 Full GC。

但要注意：**并不是所有垃圾收集器都采用固定的新生代、老年代结构。** 例如 G 1 使用 Region 管理堆，ZGC 的分代与回收方式也不同。

### **Minor GC 和 Full GC 的区别**

|**对比**|**Minor GC / Young GC**|**Full GC**|
|---|---|---|
|回收范围|年轻代|更大范围，通常涉及整个 Java 堆|
|触发场景|年轻代分配空间不足等|内存压力较大、收集器退化等|
|执行特点|通常比较频繁|通常成本更高|
|停顿时间|通常相对较短|可能产生较长停顿|

具体行为取决于使用的垃圾收集器。

## **四、Java 有哪些垃圾收集器？⭐⭐⭐⭐**

前面介绍的是垃圾回收算法，而垃圾收集器是这些算法和回收策略的具体实现。

常见垃圾收集器包括：

|**垃圾收集器**|**主要特点**|
|---|---|
|Serial GC|单线程执行垃圾回收，结构简单|
|Parallel GC|多线程并行回收，注重吞吐量|
|CMS|以降低停顿为目标的老年代并发收集器，已在 JDK 14 移除|
|G 1 GC|基于 Region 管理堆，兼顾吞吐量与可预测停顿|
|ZGC|以低延迟为目标，能够并发执行大量 GC 工作|

这里重点了解 **G 1 GC 和 ZGC** 即可。

### **G 1 GC**

G 1 不再简单地把整个堆划分为连续的新生代和老年代，而是划分为多个大小相同的 Region。

```text
              G1 堆内存

┌──────┬──────┬──────┬──────┐
│ Eden │ Old  │ Eden │ Old  │
├──────┼──────┼──────┼──────┤
│  S   │ Old  │ Eden │ Free │
├──────┼──────┼──────┼──────┤
│ Old  │ Free │  S   │ Old  │
└──────┴──────┴──────┴──────┘
```

G 1 会根据各 Region 的垃圾回收收益和停顿时间目标，选择合适的区域进行回收。

它的特点是：

- 支持并发标记。
- 可以混合回收年轻代和部分老年代 Region。
- 尝试满足用户设定的 GC 停顿时间目标。

### **ZGC**

ZGC 更强调低延迟。

它通过并发标记、并发转移等技术，让大量垃圾回收工作与应用线程同时执行，从而尽量缩短 Stop-The-World 停顿。

适用于对响应延迟要求较高的应用。

## **五、面试怎么回答？⭐⭐⭐⭐⭐**

如果面试官问：

**“Java 的 GC 机制你了解哪些？”**

你可以这样回答：

Java 的 GC 是 JVM 自动管理内存的一种机制，主要负责回收堆中不再存活的对象。

首先，在判断对象是否可以回收方面，JVM 主要使用可达性分析算法，从 GC Roots 出发遍历对象引用关系，无法到达的对象就可能被回收。

其次，在垃圾回收算法方面，主要有标记-清除、标记-复制和标记-整理三种。标记-清除容易产生内存碎片，标记-复制需要额外空间，而标记-整理需要移动存活对象。

然后，在经典分代回收机制中，堆可以划分为新生代和老年代。新生代主要存储生命周期较短的对象，通常使用复制算法；老年代主要存储长期存活的对象，可以采用标记-清除或标记-整理等算法。

最后，在垃圾收集器方面，我了解 Serial、Parallel、CMS、G 1 和 ZGC。其中 G 1 通过 Region 管理堆，兼顾吞吐量和停顿时间，而 ZGC 更注重低延迟。
