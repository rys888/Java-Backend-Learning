## 一、三个地方在存「用户是谁」

| 存什么 | 存哪 | Key / 位置 | TTL |
|---|---|---|---|
| 验证码 | Redis | `login:code:{手机号}` | 2 分钟 |
| 登录态 | Redis | `login:token:{token}`（Hash：id / nickName / icon / role） | 30 分钟，每次请求续期 |
| 本次请求的用户 | **ThreadLocal** | `UserHolder` | 请求结束清掉 |

`RedisConstants.java:4-8`

```java
public static final String LOGIN_CODE_KEY = "login:code:";
public static final Long   LOGIN_CODE_TTL = 2L;
public static final String LOGIN_USER_KEY = "login:token:";
public static final Long   LOGIN_USER_TTL = 30L;
```

`UserHolder.java` —— 就是对 `ThreadLocal<UserDTO>` 的 set / get / remove 三个静态方法。

## 二、登录：两个接口

### 2.1 发验证码 `POST /user/code?phone=xxx`

`UserController.java:26-30` → `UserServiceImpl.sendCode`

```java
// UserServiceImpl:40-53
if (RegexUtils.isPhoneInvalid(phone)) return Result.fail("手机号格式错误！");
String code = RandomUtil.randomNumbers(6);                                    // 6 位随机数字
stringRedisTemplate.opsForValue().set(LOGIN_CODE_KEY + phone, code, LOGIN_CODE_TTL, TimeUnit.MINUTES);
log.debug("发送短信验证码成功，验证码：{}", code);                              // 没有真发短信，只是打日志
return Result.ok();
```

三步：校验手机号格式 → 生成 6 位码 → 写进 Redis（`login:code:{手机号}`，2 分钟）。

### 2.2 登录 `POST /user/login`，body `{"phone":"...","code":"..."}`

`LoginFormDTO` 只有 `phone` 和 `code` 两个字段。

```java
// UserServiceImpl:59-97
String phone = loginForm.getPhone();
if (RegexUtils.isPhoneInvalid(phone)) return Result.fail("手机号格式错误！");

String cacheCode = stringRedisTemplate.opsForValue().get(LOGIN_CODE_KEY + phone);   // ① 取 Redis 里的码
if (cacheCode == null || !cacheCode.equals(loginForm.getCode())) {
    return Result.fail("验证码错误");                                                // 取不到/不相等 → 失败
}

User user = query().eq("phone", phone).one();                                       // ② 查 tb_user
if (user == null) user = createUserWithPhone(phone);                                // ③ 没有就自动注册

String token = UUID.randomUUID().toString(true);                                    // ④ 生成令牌
UserDTO userDTO = BeanUtil.copyProperties(user, UserDTO.class);
Map<String, Object> userMap = BeanUtil.beanToMap(userDTO, new HashMap<>(),
        CopyOptions.create().setIgnoreNullValue(true)
                .setFieldValueEditor((f, v) -> v.toString()));                      // ⑤ DTO → Map

String tokenKey = LOGIN_USER_KEY + token;
stringRedisTemplate.opsForHash().putAll(tokenKey, userMap);                         // ⑥ 存 Hash
stringRedisTemplate.expire(tokenKey, LOGIN_USER_TTL, TimeUnit.MINUTES);             // ⑦ 设 30 分钟

return Result.ok(token);                                                            // ⑧ 把 token 返回前端
```

几个要点：

- **token 是随机 UUID，不含任何用户信息**。用户信息在 Redis 那一侧。客户端只存一个字符串。
- **存的是 Hash 不是 String**。`BeanUtil.beanToMap` 把 `UserDTO` 摊平成 map，`setFieldValueEditor` 是把所有值转成 String（因为用的是 `StringRedisTemplate`，只能存字符串）。`setIgnoreNullValue(true)` 是值为 null 的字段不写进去。
- **`UserDTO` 只有 4 个字段**：`id / nickName / icon / role`。密码、手机号这些都不进缓存。
- 自动注册 `createUserWithPhone`（`:107-116`）：新建 `User`，`nickName = "user_" + 随机10位`，`role = UserRole.USER`，`save(user)` 插入。

前端拿到 token 后，之后每个请求都加请求头：`authorization: {token}`。

## 三、每个请求进来：三个拦截器

注册在 `MvcConfig.java:20-31`：

```java
registry.addInterceptor(new RefreshTokenInterceptor(stringRedisTemplate))
        .addPathPatterns("/**").order(0);
registry.addInterceptor(new LoginInterceptor())
        .excludePathPatterns("/user/code", "/user/login").order(1);
registry.addInterceptor(new RoleInterceptor())
        .addPathPatterns("/**").order(2);
```

**order 小的先执行。** 所以顺序是 0 → 1 → 2。

### order 0 `RefreshTokenInterceptor` —— 把 token 翻译成 UserDTO

`RefreshTokenInterceptor.java:26-47`

```java
String token = request.getHeader("authorization");
if (StrUtil.isBlank(token)) return true;                    // ① 没带 token → 直接放过

String key = LOGIN_USER_KEY + token;
Map<Object, Object> userMap = stringRedisTemplate.opsForHash().entries(key);  // ② 查 Redis
if (userMap.isEmpty()) return true;                         // ③ 查不到（过期/伪造）→ 也放过

UserDTO userDTO = BeanUtil.fillBeanWithMap(userMap, new UserDTO(), false);    // ④ Map → DTO
UserHolder.saveUser(userDTO);                               // ⑤ 存进 ThreadLocal
stringRedisTemplate.expire(key, LOGIN_USER_TTL, TimeUnit.MINUTES);            // ⑥ 续期 30 分钟
return true;
```

**这个拦截器不做任何拦截**——三种情况全部 `return true`。它只负责一件事：**如果 token 有效，就把用户放进 `UserHolder`**。

第 ⑥ 步就是「滑动过期」：只要用户 30 分钟内来过一次，登录态就一直续下去。

### order 1 `LoginInterceptor` —— 没登录就 401

`LoginInterceptor.java:11-21`

```java
if (UserHolder.getUser() == null) {
    response.setStatus(401);
    return false;              // 链子到此为止，后面的拦截器和 Controller 都不执行
}
return true;
```

它只读 ThreadLocal。**「有没有登录」完全由上一个拦截器有没有写进 ThreadLocal 决定。**

排除的路径 `/user/code` 和 `/user/login` 不需要登录，所以跳过。

### order 2 `RoleInterceptor` —— 角色不对就 403

`RoleInterceptor.java:15-43`

```java
if (!(handler instanceof HandlerMethod)) return true;                    // ① 不是 Controller 方法就放过

HandlerMethod handlerMethod = (HandlerMethod) handler;
RequireRole requireRole = handlerMethod.getMethodAnnotation(RequireRole.class);   // ② 读方法上的注解
if (requireRole == null) {
    requireRole = handlerMethod.getBeanType().getAnnotation(RequireRole.class);   // ③ 方法上没有就读类上的
}
if (requireRole == null) return true;                                    // ④ 两处都没有 → 放过

UserDTO user = UserHolder.getUser();
if (user == null) { response.setStatus(401); return false; }             // ⑤

for (UserRole role : requireRole.value()) {                              // ⑥ 逐个比对
    if (role == user.getRole()) return true;                             //    命中任意一个就放行
}
response.setStatus(403);                                                 // ⑦ 都不匹配
return false;
```

`@RequireRole` 定义（`RequireRole.java`）：

```java
@Target({ElementType.METHOD, ElementType.TYPE})
@Retention(RetentionPolicy.RUNTIME)
public @interface RequireRole { UserRole[] value(); }
```

`UserRole` 只有两个值：`USER`、`LAB_ADMIN`。

**实际用法**：全项目 18 处，**全部是方法级、全部是 `@RequireRole(UserRole.LAB_ADMIN)`**，没有一处用类级，也没有一处写 `USER`。

## 四、第二层：归属校验（在 Service 里）

`RoleInterceptor` 只能看角色。**「这个实验室是不是我的」要查库才知道**，所以在 Service 层。

`LaboratoryServiceImpl.java:25-34`

```java
public void assertManageable(Long laboratoryId) {
    UserDTO user = UserHolder.getUser();
    if (user == null) throw new ForbiddenException("无权管理该实验室");
    Laboratory laboratory = getById(laboratoryId);                                 // 查库
    if (laboratory == null || !user.getId().equals(laboratory.getAdminUserId())) { // 比 admin_user_id
        throw new ForbiddenException("无权管理该实验室");
    }
}
```

**注意这里没有检查角色**——它只比 `laboratory.admin_user_id` 和当前用户 id。

调用它的地方（都是先查出实体、拿到 `laboratoryId` 之后再调）：

```
EquipmentServiceImpl.java:66, 78, 103
ReservationServiceImpl.java:193

LaboratoryServiceImpl.java:50, 57
```

`ForbiddenException` 由 `WebExceptionAdvice.java:25-30` 处理，返回 **HTTP 403** + `Result.fail(消息)`。

## 五、登出与原位用户

`UserController.java`

```java
@PostMapping("/logout")                                    // :46-51
public Result logout(@RequestHeader(value = "authorization", required = false) String token) {
    userService.logout(token);      // 删 Redis 的 login:token:{token}
    UserHolder.removeUser();        // 清 ThreadLocal
    return Result.ok();
}

@GetMapping("/me")                                         // :53-58
public Result me() {
    return Result.ok(UserHolder.getUser());   // 直接读 ThreadLocal 返回
}
```

`UserServiceImpl.logout:101-105`：token 非空就 `stringRedisTemplate.delete(LOGIN_USER_KEY + token)`。**删除后这个 token 就作废了**——下次请求 `RefreshTokenInterceptor` 查到空 map，ThreadLocal 不写，`LoginInterceptor` 401。

## 六、ThreadLocal 什么时候清

在 `RefreshTokenInterceptor.afterCompletion:50-53`：

```java
@Override
public void afterCompletion(...) {
    UserHolder.removeUser();
}
```

`afterCompletion` 是**逆序**执行的（order 大的先执行），所以 `RefreshTokenInterceptor`（order 0）的清理**最后执行**——不管前面哪个拦截器返回了 false，它都会跑到。

**为什么必须清**：Tomcat 线程是复用的。假设不清，下一个请求带了个无效 token：

- `RefreshTokenInterceptor` 查 Redis 空 → `return true`，**没写 ThreadLocal**
- `LoginInterceptor` 读 `UserHolder.getUser()` → **读到上一个请求残留的用户**
- → 未登录的请求被当成已登录放行
