### 03 List、Set与Map的区别

**Q：** 平时会使用到的集合有哪些? [来源 02](https://juejin.cn/post/7370994785656668187)

**A：** List表示有序序列，通常允许重复元素，可按下标访问；Set主要表达元素唯一性；Map保存键值映射，键唯一而值可以重复，Map本身不继承Collection。具体顺序和空值规则取决于实现：HashSet不保证迭代顺序，TreeSet按排序规则组织元素。HashMap或HashSet中的自定义键要正确实现equals与hashCode，并避免修改参与判等的字段。选择时先看是否需要位置、去重或按键查询，再考虑并发和性能。

### 04 HashMap 的存储与查找原理

**Q：** HashMap [来源 02](https://juejin.cn/post/7370994785656668187)

**A：** HashMap 根据键的哈希值定位桶，再通过 equals 区分发生冲突的键。JDK 8 中桶采用链表或红黑树，链较长且数组容量足够时才树化，容量不足时优先扩容；元素数量超过容量与负载因子的乘积也会触发扩容。哈希分布均匀时查询平均接近 O(1)，但不能保证所有场景都为常数时间。它允许 null 键和值，不保证遍历顺序，也不适合并发修改。

### 05 接口与抽象类有什么区别

**Q：** 接口与抽象类的区别？ [来源 02](https://juejin.cn/post/7370994785656668187)

**A：** AI参考答案：接口主要定义能力契约，一个类可以实现多个接口；抽象类适合表达同一类型体系中的共享状态和部分实现，一个类只能直接继承一个类。抽象类可以有实例字段、构造器和不同可见性的方法；接口字段是常量，不能保存每个对象的实例状态。Java 8接口可有default和static方法，Java 9起还可有private方法。选择时优先根据类型关系与职责决定，不要仅为了代码复用建立不合理继承。

### 06 常见集合中哪些支持线程安全访问

**Q：** 常见的集合有哪些，哪些是线程安全的？ [来源 02](https://juejin.cn/post/7370994785656668187)

**A：** AI参考答案：常用ArrayList、HashMap、HashSet不提供并发修改安全保证。可按需求使用ConcurrentHashMap、CopyOnWriteArrayList或阻塞队列，也可用Collections的同步包装；Vector和Hashtable的方法虽有同步，复合操作仍可能产生竞争。并发Map的“先判断再写入”应使用putIfAbsent、compute等原子接口。CopyOnWrite适合读多写少，写入会复制数组；遍历同步包装集合通常仍需外部加同一把锁。

### 07 受检异常与运行时异常的区别

**Q：** 运行时异常和编译时异常 [来源 02](https://juejin.cn/post/7370994785656668187)

**A：** AI参考答案：所谓“编译时异常”通常指受检异常，并不是异常真的在编译阶段抛出。除RuntimeException、Error及其子类外，受检异常需要在编译时满足捕获或声明要求，例如IOException；运行时异常如NullPointerException不强制捕获或声明，但同样在运行中发生。异常类型应表达调用方能否合理恢复，不能为逃避处理一律包装为运行时异常。包装需保留cause，资源释放优先使用try-with-resources。

## Java 并发与 JVM

### 08 多个线程操作同一个变量可能发生什么

**Q：** Java 还学了什么？高级的？比如说 并发、多线程？比如说多个线程处理一个变量会发生什么？ [来源 01](https://www.cnblogs.com/thr-0103/p/18113538)

**A：** AI参考答案：多个线程操作同一变量不一定出错，要看是否存在并发写入及正确同步。像count++包含读、计算、写，交错执行可能丢失更新；即使单次读写原子，也可能有可见性和顺序问题。可用同一把锁保护完整操作，或用AtomicInteger等原子类更新单个状态；多个变量共同维护不变量时仍需整体同步。volatile主要提供可见性与有序性，不能让复合操作自动原子化。

### 09 后端如何选择并发控制方式

**Q：** 多线程中如何使用的锁 [来源 02](https://juejin.cn/post/7370994785656668187)

**A：** 先明确竞争的数据和作用范围。**单进程**内共享变量可用synchronized或ReentrantLock，**跨实例**共同修改数据库时，优先考虑原子条件更新、唯一约束或数据库行锁；确需协调**跨节点**任务时再评估分布式锁。选择时还要看事务边界、锁粒度、超时与死锁处理。加锁只能保护参与同一协议的访问，不能拿到锁就认为重复请求、远程调用失败和业务幂等都已解决。

### 10 什么是死锁以及如何减少死锁

**Q：** 什么是死锁，如何减少这种情况的发生？ [来源 02](https://juejin.cn/post/7370994785656668187)

**A：** AI参考答案：死锁是多个线程互相等待对方持有的资源，导致都无法继续。典型条件包括**互斥、持有并等待、不可抢占和循环等待**。工程中可统一多把锁的获取顺序、缩小持锁范围，避免持锁进行远程调用；必要时用带超时的tryLock并在失败后释放已持有资源。通过线程转储检查等待关系和持有者，确认实际环路。超时重试也需退避和次数限制，防止死锁变成活锁或持续重试。

### 11 Java创建和执行线程任务的方式

**Q：** 创建线程的方式 [来源 02](https://juejin.cn/post/7370994785656668187)

**A：** 可继承Thread重写run，或把Runnable交给Thread后调用start；需要返回值时可用Callable配合FutureTask或提交给ExecutorService。Runnable、Callable描述任务，本身不是操作系统线程；调用run只是当前线程普通方法调用，start才请求启动新线程。实际工程常使用受控线程池复用线程，并处理任务异常、超时和关闭流程，不能无界地为每个请求新建线程。

## Spring / Spring Boot / MyBatis

### 12 MyBatis与MyBatis-Plus的区别

**A：** MyBatis负责SQL映射与结果封装，复杂查询通常通过XML或注解显式编写；MyBatis-Plus是在其基础上的增强，提供通用CRUD、条件构造器和分页等能力，减少重复代码，但不会让SQL设计、索引和事务问题自动消失。简单单表操作可用通用Mapper，复杂业务仍可写自定义SQL。应按项目依赖版本说明API，不把starter版本直接当作MyBatis核心版本。

## Redis

### 15 Redis内存不足如何定位与处理

**Q：** Redis内存溢出是如何定位解决的？ [来源 02](https://juejin.cn/post/7370994785656668187)

**A：** AI参考答案：先区分达到maxmemory后的写入OOM报错与操作系统因内存不足终止进程。结合INFO memory、键数量和TTL分布，观察数据增长、大key、客户端缓冲及内存碎片；可用MEMORY USAGE抽样定位，避免在线上执行高开销全量操作。确认业务后清理无用数据、补齐过期时间或拆分大key，并评估容量和淘汰策略。持久化、复制还需额外内存，不能把maxmemory直接等同于进程RSS上限。


区分 Redis 内存溢出和 JVM 内存溢出
**如果 Redis 出现内存问题，我会首先通过 `INFO memory` 查看内存使用量、内存峰值、碎片情况和 maxmemory 配置。
然后通过 `redis-cli --bigkeys` 和 `MEMORY USAGE` 排查是否存在大 Key，并检查 TTL 设置和内存淘汰策略。
如果是大 Key 导致的，就考虑拆分或清理；如果是缓存不断增长，就设置合理的过期时间和淘汰策略；如果是容量不足，就考虑扩容或集群分片。
如果 Redis 进程直接被杀死，还需要检查操作系统 OOM 日志和容器内存限制。**

## RabbitMQ / 消息队列
