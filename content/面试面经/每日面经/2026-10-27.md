### 01 Java反射的原理与应用场景

**Q：** 反射了解吗，反射的场景 [来源 02](https://www.nowcoder.com/feed/main/detail/5083b0fbb75e480db6e8db2bbafc1195)

**A：** 反射是在运行时通过Class等对象获取类、字段、构造器和方法信息，并按权限规则创建实例或调用成员。常见场景包括依赖注入、对象映射、注解解析、测试框架和动态代理的调用分发，使框架不必为每种业务类写死处理逻辑。代价是额外运行开销、访问检查和对成员名称的运行时依赖，应缓存元数据并控制使用范围；反射不会自动让对象线程安全。Java 9后的模块封装也可能限制深反射，不能假定setAccessible永远可用。

### 02 JVM运行时内存区域

**Q：** java的堆和栈区别 [来源 02](https://www.nowcoder.com/feed/main/detail/5083b0fbb75e480db6e8db2bbafc1195)

**A：** 按JVM规范可说明程序计数器、虚拟机栈、本地方法栈、堆和方法区。计数器与栈随线程组织，堆和方法区通常在线程间共享；栈帧包含局部变量表、操作数栈等，堆主要存放对象和数组。方法区是规范概念，HotSpot在Java8后主要以元空间承载类元数据，不能把元空间当作堆内老年代。直接内存也不能简单列成规范规定的第六块运行时区域。

### 03 多线程是否更快及CPU与IO任务如何选线程数

**Q：** 多线程能提高速度 [来源 02](https://www.nowcoder.com/feed/main/detail/5083b0fbb75e480db6e8db2bbafc1195)

**Q：** IO密集型和计算密集型哪个需要多线程 [来源 02](https://www.nowcoder.com/feed/main/detail/5083b0fbb75e480db6e8db2bbafc1195)

**A：**
CPU 密集型和 IO 密集型任务都可以使用多线程，但是线程数量的选择不同。

对于 CPU 密集型任务，由于线程大部分时间都在进行计算，CPU 资源比较紧张，因此线程数通常设置在 CPU 核数附近。如果线程过多，反而会增加上下文切换和线程调度开销，降低性能。

对于 IO 密集型任务，线程经常需要等待数据库查询、网络请求或者文件读取等操作。在等待 IO 的过程中，CPU 可以执行其他线程的任务，因此可以适当增加线程数量，提高 CPU 利用率和系统吞吐量。

不过线程数量并不是越多越好，还需要考虑内存、数据库连接池以及下游服务的承载能力，最终通过压测确定合适的线程数。



## Spring / Spring Boot / MyBatis

### 04 MyBatis如何从Mapper方法执行SQL

**Q：** mybatis怎么实现的 [来源 02](https://www.nowcoder.com/feed/main/detail/5083b0fbb75e480db6e8db2bbafc1195)

**A：** 
MyBatis 是一个持久层框架，底层主要通过动态代理、反射和 JDBC 实现数据库操作。

首先，MyBatis 启动时会解析 Mapper XML 或注解中的 SQL，将 SQL 和映射信息封装为 `MappedStatement`。

当我们调用 Mapper 接口方法时，实际上调用的是 MyBatis 通过 JDK 动态代理生成的代理对象。代理对象会根据方法找到对应的 SQL，并交给 `SqlSession` 和 `Executor` 执行。

底层通过 JDBC 完成 SQL 参数绑定和数据库访问，最后利用反射等机制将查询结果映射成 Java 对象。

因此，MyBatis 的核心就是通过动态代理实现 Mapper 接口，通过 JDBC 执行 SQL，通过反射完成对象映射，从而简化数据库操作

### 05 DispatcherServlet的作用

**Q：** tomcat怎么路由请求到对应Controller啥的 [来源 02](https://www.nowcoder.com/feed/main/detail/5083b0fbb75e480db6e8db2bbafc1195)

**A：** DispatcherServlet是Spring MVC的前端控制器，负责把Servlet容器交给它的请求接入MVC处理链。它通过HandlerMapping找到处理器，再由HandlerAdapter调用Controller；返回结果按配置交给视图解析器或消息转换器，例如将对象转换为JSON。异常也可进入相应解析器。Filter通常在Servlet层包围请求，MVC拦截器则处于MVC处理流程内；不能把DispatcherServlet本身等同于监听端口的HTTP服务器。

### 06 如何用条件UPDATE防止库存扣成负数

**Q：** 简历写了“条件更新扣减库存”，这个条件更新的 SQL 怎么写？ [来源 01](https://www.nowcoder.com/feed/main/detail/0da5ca7b308e49d985dd22aa5fe3a9fc)
🌟🌟🌟，这个我的简历中也写了

**A：** 可用参数化SQL：UPDATE goods SET stock=stock-? WHERE id=? AND stock>=?，扣减数量必须为正数，两个数量参数一致。根据影响行数判断成功或库存不足，避免先普通查询再无条件扣减。InnoDB会对更新涉及的记录加锁，并发更新会按锁规则检查条件，因此库存不足的请求不能扣成负数；扣库存和写订单应置于同一数据库事务，业务异常须回滚。唯一业务号或唯一约束另行解决重复请求，不能把防超卖等同于幂等。

### 07 如何查询学生总分最高者并保留并列

**Q：** sql语句，一个学生表，记录学生姓名，科目，分数。找到总分最高分的那个 [来源 02](https://www.nowcoder.com/feed/main/detail/5083b0fbb75e480db6e8db2bbafc1195)

**Q：** 假如最高分有两个怎么解决 [来源 02](https://www.nowcoder.com/feed/main/detail/5083b0fbb75e480db6e8db2bbafc1195)

**A：** 先按学生分组计算SUM(score)，再取最高总分对应的全部学生。MySQL 8.0可先在派生表或CTE中聚合，再用DENSE_RANK() OVER(ORDER BY total DESC)排名，筛选排名为1；也可以把聚合结果与最大总分比较。不能只用ORDER BY总分DESC LIMIT 1，因为它只返回一行，可能漏掉并列者。原题仅给姓名、科目和分数；若现实中可能同名，应补充稳定学号分组，并明确重复科目、补考和NULL分数的计算规则。

```
SELECT
    name,
    SUM(score) AS total_score
FROM student_score
GROUP BY name
HAVING SUM(score) = (
    SELECT MAX(total)
    FROM (
        SELECT SUM(score) AS total
        FROM student_score
        GROUP BY name
    ) AS t
);
```


## Redis

### 08 Lua库存预扣与MySQL扣库存如何取舍

**Q：** 简历里写用 Lua 脚本实现秒杀，为什么不直接用 MySQL 扣库存？ [来源 01](https://www.nowcoder.com/feed/main/detail/0da5ca7b308e49d985dd22aa5fe3a9fc)

**Q：** 如果库存只有 1，两个用户同时请求你的 Lua 脚本，怎么保证只有一个人成功？ [来源 01](https://www.nowcoder.com/feed/main/detail/0da5ca7b308e49d985dd22aa5fe3a9fc)

**A：** Lua把库存检查和扣减放到Redis服务端一次执行，减少网络往返；同一节点上的脚本执行不被其他命令插入，库存为1时，先执行者扣成0，后执行者检查后失败。高并发场景可用它提前拦截无库存请求，减轻数据库压力，但MySQL条件更新本身也能防超卖。Redis预扣成功不等于订单落库成功，还需处理重复请求、异步落库失败补偿和对账；脚本运行报错也不代表自动回滚已执行的写操作。

## RabbitMQ / 消息队列

### 09 订单和本地消息表为何放在同一事务

**Q：** 订单变更同事务写入本地消息表，为什么要多建一张消息表？ [来源 01](https://www.nowcoder.com/feed/main/detail/0da5ca7b308e49d985dd22aa5fe3a9fc)

**A：** 本地消息表用于把订单变更与待发送事件一起写入同一数据库事务：提交时两者同时保存，回滚时都不生效，避免订单成功却没有可重试的消息记录。事务外由可靠投递任务读取消息，发送成功并确认后更新状态，失败按策略重试。它解决的是本地事务与消息投递之间的衔接，不是数据库和MQ天然组成一个原子事务；发送后更新状态前宕机可能导致重复投递，因此消费者还要按事件ID或业务唯一键幂等处理，并监控积压和最终失败。

## 计算机网络与操作系统

### 10 CPU调度的基本单位是什么

**Q：** cpu执行的最小单位 [来源 02](https://www.nowcoder.com/feed/main/detail/5083b0fbb75e480db6e8db2bbafc1195)

**A：** 在通常的现代通用操作系统面试语境中，**线程是CPU调度的基本单位**，进程主要作为资源分配与隔离的单位。一个进程可含多个线程，线程共享进程地址空间，但各自有执行上下文和栈，内核调度可运行线程到CPU上执行。若问题说的是CPU“执行”的最小单位，需要先澄清它问调度单位还是机器指令，不能混为一谈；Java虚拟线程又由JVM调度到载体线程上，内核并非直接调度每个虚拟线程。

### 11 RPC为何看起来像调用本地方法

**Q：** rpc原理，为什么能像调用本地一样调用远程服务 [来源 02](https://www.nowcoder.com/feed/main/detail/5083b0fbb75e480db6e8db2bbafc1195)

**A：** RPC框架通常用客户端代理提供与服务接口相似的方法调用入口：代理把服务名、方法、参数和请求ID编码序列化，通过网络发送；服务端解码后定位实现并执行，将结果或异常信息返回，客户端再关联请求并反序列化。因此相似的是使用方式，实际还多了网络延迟、超时、连接失败和版本兼容问题。超时不代表服务端一定没执行，写操作不能盲目重试，需要幂等设计；鉴权、限流与服务发现也应按场景配置。

### 12 Spring AI与RAG的问答链路

**Q：** 项目里的 Spring AI + RAG，用户提问之后，从收到问题到生成回答，完整经过哪些步骤？ [来源 01](https://www.nowcoder.com/feed/main/detail/0da5ca7b308e49d985dd22aa5fe3a9fc)
