## Java 基础与集合

### 01 try中return后finally是否执行

**Q：** Java的try-catch-finally，try里面有return finally还会执行吗？ [来源 01](https://www.nowcoder.com/feed/main/detail/cecac304535c4b3c99e6ff117908251e)

**A：** 通常会执行。try中的return先计算返回值，随后执行finally；若finally正常结束，才完成原来的返回。finally若也return或抛异常，会覆盖原本的返回或异常，因此应避免在finally里改变控制流。finally中修改局部基本类型变量通常不改变已计算的返回值，但修改返回对象的内容可能被调用方看到。进程被终止、JVM退出或代码一直未离开try等情况下，不能保证执行finally。

### 02 方法重载与重写的区别

**Q：** 重载和重写的区别 [来源 01](https://www.nowcoder.com/feed/main/detail/cecac304535c4b3c99e6ff117908251e)

**A：** 重载是在同一类或继承体系中使用相同方法名、不同参数列表，编译器根据声明类型和参数选择调用目标，不能只改变返回类型来重载。重写是子类对继承的实例方法提供兼容实现，调用时再按对象实际类型动态分派；返回类型需兼容，不能收紧访问权限或任意扩大受检异常范围。静态方法是隐藏而非实例方法重写，私有方法也不按普通重写规则参与动态分派。

### 03 HashMap 的存储与查找原理

**Q：** 必考的HashMap，以及是否线程安全，还有ConcurrentHashMap [来源 01](https://www.nowcoder.com/feed/main/detail/cecac304535c4b3c99e6ff117908251e)

**A：** HashMap 根据键的哈希值定位桶，再通过 equals 区分发生冲突的键。JDK 8 中桶采用链表或红黑树，链较长且数组容量足够时才树化，容量不足时优先扩容；元素数量超过容量与负载因子的乘积也会触发扩容。哈希分布均匀时查询平均接近 O(1)，但不能保证所有场景都为常数时间。它允许 null 键和值，不保证遍历顺序，也不适合并发修改。

## Java 并发与 JVM

### 04 ConcurrentHashMap如何保证并发安全

**Q：** 必考的HashMap，以及是否线程安全，还有ConcurrentHashMap [来源 01](https://www.nowcoder.com/feed/main/detail/cecac304535c4b3c99e6ff117908251e)

**A：** 以JDK 8为例，ConcurrentHashMap使用桶数组，冲突桶可为链表或树。空桶插入主要通过CAS竞争，非空桶更新会使用桶级同步，并配合可见性机制，使不同桶上的操作尽量并行；扩容时线程也可协助迁移。不能把JDK 7的Segment分段锁当成JDK 8实现。单次操作安全不代表先判断再写入的组合操作原子，应使用putIfAbsent、compute等合适接口，遍历和size也不能当成全表一致快照。

### 05 synchronized与ReentrantLock的区别

**Q：** synchronized和Lock的区别 [来源 01](https://www.nowcoder.com/feed/main/detail/cecac304535c4b3c99e6ff117908251e)

**A：** 两者都支持互斥和可重入。synchronized由JVM管理监视器，退出同步块或异常离开时自动释放，使用简单；ReentrantLock需要在成功加锁后用finally解锁，但支持可中断获取、限时尝试及可选公平策略，还能创建多个Condition。公平锁并不保证线程调度的绝对先后，性能也要结合竞争情况测试。普通临界区可优先用简单方式，确有取消、超时或多条件等待需求时再选择显式锁。

## 其他问题

### 06 斐波那契数有哪些计算方法

**Q：** 斐波那契数算法有哪些解法？ [来源 01](https://www.nowcoder.com/feed/main/detail/cecac304535c4b3c99e6ff117908251e)

**A：** 先约定数列起点，例如F(0)=0、F(1)=1。直接递归按F(n)=F(n-1)+F(n-2)计算，但重复子问题很多，时间呈指数增长；记忆化递归或动态规划可降到O(n)。只求某一项时用两个变量滚动迭代，时间O(n)、额外空间O(1)；更大n可用矩阵快速幂或快速倍增，按算术操作数计为O(log n)。通项公式涉及浮点误差，不宜直接用于大整数精确计算；数值超范围需使用大整数或按题意取模。

### 07 冒泡排序的实现与复杂度

**Q：** 冒泡排序怎么实现？有几层for 循环 [来源 01](https://www.nowcoder.com/feed/main/detail/cecac304535c4b3c99e6ff117908251e)

**A：** 常见实现用两层循环：外层控制轮数，最多n-1轮；内层比较尚未排好部分的相邻元素，逆序就交换，每轮把最大元素移到该部分末尾，所以下一轮比较范围缩小。可设置交换标志，某轮没有交换就提前结束。平均和最坏时间复杂度O(n²)，有提前终止时已排序输入最好为O(n)，额外空间O(1)。仅在前者严格大于后者时交换可保持稳定性，适合小规模数据或教学，较大数据通常采用更高效的排序。
