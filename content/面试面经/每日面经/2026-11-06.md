## Java 基础与集合

### 01 ArrayList与LinkedList的区别及场景

**Q：** 讲一讲ArrayList和LinkedList [来源 01](https://www.nowcoder.com/discuss/353154223065997312)

**A：** ArrayList基于可扩容数组，按下标访问为O(1)，尾部追加通常是摊销O(1)，中间插入删除需要移动元素。LinkedList基于双向链表，按下标定位仍为O(n)，只有已经定位节点或在两端操作时，链接调整才是O(1)，不能笼统说插入一定更快。一般列表优先ArrayList；需要双端操作可比较ArrayDeque等实现。两者都不自动保证并发安全，选择时还要考虑节点内存和缓存局部性。

### 02 ASM是什么及适用场景

**Q：** 了解asm吗？ [来源 01](https://www.nowcoder.com/discuss/353154223065997312)

**A：** AI参考答案：ASM是Java字节码分析与操作框架，可读取class结构、修改现有字节码或动态生成类，常用于插桩、代理生成、覆盖率统计和诊断工具。它处理的是类文件及指令层面，反射主要在运行时检查类型和调用已有成员，两者用途不同。使用时要保证栈、控制流与类文件格式合法，并确认工具支持目标JDK的class版本；普通业务开发通常优先使用成熟框架封装，避免直接修改字节码增加维护成本。

### 03 == 与 equals 的区别

**Q：** String str1=new String("abc"),String str2=new String("abc"); str1== str2返回什么[来源 01](https://www.nowcoder.com/discuss/353154223065997312)

**A：** == 对基本类型比较数值，对引用类型比较是否指向同一对象；equals 是对象的方法，默认实现也比较引用，但 String 等类重写后按内容判断。业务对象需要按关键字段判等时，应同时重写 equals 和 hashCode，保证相等对象具有相同哈希值，否则放入 HashMap、HashSet 可能出现查找或去重异常。比较字符串内容通常用 equals，并注意接收者为 null 时的空指针问题。

### 04 HashMap 的存储与查找原理

**Q：** 讲一下hashmap吧 [来源 01](https://www.nowcoder.com/discuss/353154223065997312)

**A：** HashMap 根据键的哈希值定位桶，再通过 equals 区分发生冲突的键。JDK 8 中桶采用链表或红黑树，链较长且数组容量足够时才树化，容量不足时优先扩容；元素数量超过容量与负载因子的乘积也会触发扩容。哈希分布均匀时查询平均接近 O(1)，但不能保证所有场景都为常数时间。它允许 null 键和值，不保证遍历顺序，也不适合并发修改。

### 05 HashMap是否允许null键与null值

**Q：** hashmap可以插入null值吗 [来源 01](https://www.nowcoder.com/discuss/353154223065997312)

**A：** AI参考答案：HashMap允许一个null键及多个null值；再次写入null键会更新同一映射。get返回null既可能表示没有该键，也可能表示该键对应的值为null，需要containsKey区分。允许空值与线程安全是不同问题；ConcurrentHashMap不允许null键和值，不能把HashMap的规则推广到所有Map。设计接口时应说明缺失值与空值各自的业务含义。

### 06 HashMap如何避免对null键调用hashCode

**Q：** 为什么呢？你不是说根据key的hashcode插入吗 [来源 01](https://www.nowcoder.com/discuss/353154223065997312)

**A：** AI参考答案：以OpenJDK 8的HashMap为例，计算键的散列值时先判断键是否为null，null直接取散列值0，因此不会调用null.hashCode，也不会因此抛空指针异常。它与其他散列值映射到同一桶的键仍要通过身份或equals区分，再次写入null键更新原映射。null值只是条目的值，不参与键的散列计算。允许null属于HashMap的契约，不能据此认为ConcurrentHashMap或所有Map实现也允许null。

### 07 HashMap并发修改有哪些风险

**Q：** 我们都知道hashmap是线程不安全的，那么为什么线程不安全呢？ [来源 01](https://www.nowcoder.com/discuss/353154223065997312)

**A：** AI参考答案：HashMap没有为并发修改提供同步保证，多线程put可能发生覆盖、丢更新或读取到不符合预期的结果，size和遍历也不能视为一致快照。JDK 7扩容的链表成环问题不能直接套到JDK 8，但8仍不是线程安全容器。共享可变映射应使用ConcurrentHashMap或统一外部锁，先查后改等复合业务也需原子API或完整加锁。

## Java 并发与 JVM

### 08 后端如何选择并发控制方式

**Q：** 你说你对锁有了解，说一说你最熟悉的两个锁 [来源 01](https://www.nowcoder.com/discuss/353154223065997312)

**A：** 先明确竞争的数据和作用范围。单进程内共享变量可用synchronized或ReentrantLock，跨实例共同修改数据库时，优先考虑原子条件更新、唯一约束或数据库行锁；确需协调跨节点任务时再评估分布式锁。选择时还要看事务边界、锁粒度、超时与死锁处理。加锁只能保护参与同一协议的访问，不能拿到锁就认为重复请求、远程调用失败和业务幂等都已解决。

### 09 synchronized与ReentrantLock的区别

**Q：** 说一下synchronied和ReentrantLock的区别 [来源 01](https://www.nowcoder.com/discuss/353154223065997312)

**A：** 两者都支持互斥和可重入。synchronized由JVM管理监视器，退出同步块或异常离开时自动释放，使用简单；ReentrantLock需要在成功加锁后用finally解锁，但支持可中断获取、限时尝试及可选公平策略，还能创建多个Condition。公平锁并不保证线程调度的绝对先后，性能也要结合竞争情况测试。普通临界区可优先用简单方式，确有取消、超时或多条件等待需求时再选择显式锁。

### 10 ThreadLocal如何保存每个线程的变量

**Q：** 讲一下ThreadLoacal吧 [来源 01](https://www.nowcoder.com/discuss/353154223065997312)

**A：** AI参考答案：以常见OpenJDK实现为例，Thread对象持有自己的ThreadLocalMap，键是ThreadLocal对象的弱引用，值是该线程保存的数据；get、set操作先找到当前线程，再访问它的映射。因此不是所有线程共用一张以线程为键的全局Map。弱键被回收后，值仍可能被存活线程保留，线程池任务应在finally中remove；它隔离变量绑定，不会自动复制对象或使共享对象线程安全。

### 11 ThreadLocal的场景与风险

**Q：** 它（ThreadLocal）有什么用，可以举一个例子吗？ [来源 01](https://www.nowcoder.com/discuss/353154223065997312)

**A：** ThreadLocal为每个线程保存独立变量，常用于请求上下文或事务资源绑定，不负责让同一对象的并发访问自动安全。线程池会复用线程，任务结束后若不remove，旧数据可能串到下个任务；ThreadLocalMap的弱键也不能替代清理，因为值仍可能被线程长期引用。应在finally中清理，异步任务需要显式传递必要上下文，不能假设换线程后原值仍然可见。

### 12 Exchanger的exchange如何交换线程数据

**Q：** 用过exchange（）吗 [来源 01](https://www.nowcoder.com/discuss/353154223065997312)

**A：** AI参考答案：原文只写exchange()，未给出所属类；若指并发工具Exchanger，它让两个线程在交换点配对，各自交出对象并获得对方对象，适合交换已填满和空闲缓冲区。没有配对线程时调用会等待，可选择超时版本，并处理超时与中断。它提供交换前后相应的内存可见性保证，但不是广播或持久化队列，也不保证交换后共享可变对象的后续访问自动安全；实际口述应先确认API，不能编造使用经历。

### 13 JVM运行时内存区域

**Q：** 说一说JVM内存模型吧 [来源 01](https://www.nowcoder.com/discuss/353154223065997312)

**A：** 按JVM规范可说明程序计数器、虚拟机栈、本地方法栈、堆和方法区。计数器与栈随线程组织，堆和方法区通常在线程间共享；栈帧包含局部变量表、操作数栈等，堆主要存放对象和数组。方法区是规范概念，HotSpot在Java8后主要以元空间承载类元数据，不能把元空间当作堆内老年代。直接内存也不能简单列成规范规定的第六块运行时区域。

### 14 线程之间如何同步与协调执行

**Q：** 知道如何让线程同步吗？ [来源 01](https://www.nowcoder.com/discuss/353154223065997312)

**A：** AI参考答案：先区分保护共享数据和协调执行时机。前者可用synchronized或Lock实现互斥与可见性；后者可用wait/notify、Condition、CountDownLatch或CyclicBarrier。wait必须持有对应监视器，并在while中检查条件，等待时释放该监视器，唤醒后需重新获取；Condition需配合同一把Lock。等待若干任务完成可选闭锁，多阶段汇合可选屏障，还应处理异常、超时和中断，避免某个任务失败导致其他线程永久等待。

### 15 CountDownLatch与CyclicBarrier的区别和例子

**Q：** 说一说countdownlatch，cyclicbarrer [来源 01](https://www.nowcoder.com/discuss/353154223065997312)

**Q：** 举个例子？ [来源 01](https://www.nowcoder.com/discuss/353154223065997312)

**A：** AI参考答案：CountDownLatch由指定计数开始，任务调用countDown递减，等待者在await处等到零，计数不能重置，适合主线程等待多个初始化任务结束。CyclicBarrier让固定数量的参与线程互相等待，每轮都到齐后继续，可重复使用并执行汇总动作，适合分阶段并行计算。例子是多个分片分别计算后在屏障汇合再进入下一轮。使用线程池时要保证参与者能获得执行线程，并处理超时、中断和屏障损坏，避免相互等待。

### 16 线程池提交任务流程与拒绝策略

**Q：** 你说你对多线程有所了解，那你说一下线程池的实现原理吧 [来源 01](https://www.nowcoder.com/discuss/353154223065997312)

**A：** 提交任务时，若工作线程少于核心数就尝试创建核心线程；否则尝试入队。入队成功后还会复查运行状态与工作线程情况；入队失败则尝试创建非核心线程，达到上限或无法接收时执行拒绝策略。Java内置Abort、CallerRuns、Discard和DiscardOldest。选择要结合业务是否允许丢任务，不能默认静默丢弃；关闭中的线程池也可能拒绝任务。
