## Java 基础与集合

### 01 HashMap 的存储与查找原理

**Q：** HashMap 底层结构和原理？ [来源 01](https://www.nowcoder.com/discuss/353157949398917120)

**A：** HashMap 根据键的哈希值定位桶，再通过 equals 区分发生冲突的键。JDK 8 中桶采用链表或红黑树，链较长且数组容量足够时才树化，容量不足时优先扩容；元素数量超过容量与负载因子的乘积也会触发扩容。哈希分布均匀时查询平均接近 O(1)，但不能保证所有场景都为常数时间。它允许 null 键和值，不保证遍历顺序，也不适合并发修改。

### 02 Java基本类型与包装类

**Q：** Java基础数据类型 [来源 02](https://www.nowcoder.com/discuss/353159627783217152)

**Q：** int和Integer区别？ [来源 03](https://www.nowcoder.com/discuss/353157644422684672)

**A：** Java有byte、short、int、long、float、double、char、boolean八种基本类型，对应包装类为Byte、Short、Integer、Long、Float、Double、Character、Boolean。包装类可用于泛型和允许null的对象场景，自动装箱拆箱提供便利，但拆箱null会抛空指针异常。比较包装数值应关注equals语义，不能依赖引用相等或缓存范围；金额通常用BigDecimal并明确精度与舍入。

### 03 final修饰变量、方法与类的含义

**Q：** final的理解 [来源 02](https://www.nowcoder.com/discuss/353159627783217152)

**A：** final修饰变量表示只能赋值一次；引用变量不能再指向其他对象，但对象内部状态仍可能变化，所以不等于不可变或线程安全。修饰方法表示不能被子类重写，修饰类表示不能被继承。成员final字段需在声明、初始化块或构造过程中完成赋值；局部变量需在使用前赋值。并发中final字段有专门的初始化可见性语义，但前提包括构造期间不让this逸出，仍不能代替对可变共享状态的同步。

### 04 List、Set与Map的区别

**Q：** list,set,map的理解 [来源 02](https://www.nowcoder.com/discuss/353159627783217152)

**A：** List表示有序序列，通常允许重复元素，可按下标访问；Set主要表达元素唯一性；Map保存键值映射，键唯一而值可以重复，Map本身不继承Collection。具体顺序和空值规则取决于实现：HashSet不保证迭代顺序，TreeSet按排序规则组织元素。HashMap或HashSet中的自定义键要正确实现equals与hashCode，并避免修改参与判等的字段。选择时先看是否需要位置、去重或按键查询，再考虑并发和性能。

### 05 面向对象的理解与价值

**Q：** 面向对象特征？ [来源 03](https://www.nowcoder.com/discuss/353157644422684672)

**A：** 面向对象把数据与操作数据的行为组织到对象中，通过封装隐藏实现细节，通过抽象和接口表达稳定契约，通过多态在调用方不依赖具体实现的情况下替换行为。它有助于控制复杂业务的职责与变化，但不是类越多越好；继承应满足合理的类型关系，复用行为也可优先组合。设计时围绕业务边界划分职责，避免所有逻辑集中在一个大类中。

### 06 ArrayList与LinkedList的区别及场景

**Q：** ArrayList、LinkedList底层？ [来源 03](https://www.nowcoder.com/discuss/353157644422684672)

**A：** ArrayList基于可扩容数组，按下标访问为O(1)，尾部追加通常是摊销O(1)，中间插入删除需要移动元素。LinkedList基于双向链表，按下标定位仍为O(n)，只有已经定位节点或在两端操作时，链接调整才是O(1)，不能笼统说插入一定更快。一般列表优先ArrayList；需要双端操作可比较ArrayDeque等实现。两者都不自动保证并发安全，选择时还要考虑节点内存和缓存局部性。

## Java 并发与 JVM

### 07 Java引用类型与垃圾回收

**Q：** Java 四种引用和区别？ [来源 01](https://www.nowcoder.com/discuss/353157949398917120)

**A：** 通常区分强引用、软引用、弱引用和虚引用。对象若仍通过有效的强引用链从GC Roots可达，就不能当作垃圾回收；软引用对象在内存压力下可能被清理，弱引用不会阻止其所指对象被回收。虚引用的get始终返回null，常配合引用队列进行回收后的资源管理通知。具体回收时机由收集器决定，不能承诺一次GC必定回收；弱键也不代表容器里相关的强引用值会自动及时释放。

### 08 类加载、链接与初始化

**Q：** Java 中 Class 文件的加载过程？ [来源 01](https://www.nowcoder.com/discuss/353157949398917120)

**A：** 通常按加载、链接和初始化说明，链接又包括验证、准备和解析。加载得到类的二进制表示；验证检查合法性；准备为类变量分配空间并设置初始值，解析把符号引用转换为直接引用；初始化再按规则执行类初始化逻辑。各阶段未必严格一次性完成，例如解析可延迟。类加载与对象实例化不同，静态字段赋值也不能都笼统说在加载阶段执行。

### 09 ThreadLocal的场景与风险

**Q：** ThreadLocal 的作用和实现原理？ [来源 01](https://www.nowcoder.com/discuss/353157949398917120)

**Q：** ThreadLocal 实现原理 作用 [来源 04](https://www.nowcoder.com/discuss/353156179603955712)

**A：** ThreadLocal为每个线程保存独立变量，常用于请求上下文或事务资源绑定，不负责让同一对象的并发访问自动安全。线程池会复用线程，任务结束后若不remove，旧数据可能串到下个任务；ThreadLocalMap的弱键也不能替代清理，因为值仍可能被线程长期引用。应在finally中清理，异步任务需要显式传递必要上下文，不能假设换线程后原值仍然可见。

## Spring / Spring Boot / MyBatis

### 10 Spring AOP的作用与实现

**Q：** 什么场景适合使用切面？ [来源 01](https://www.nowcoder.com/discuss/353157949398917120)

**A：** AOP把事务、日志或权限等横切逻辑从业务代码中分离，通过切点选择连接点并织入通知。Spring AOP通常基于JDK动态代理或CGLIB代理，在代理调用处增强方法，因此对象是否由容器管理、调用是否经过代理会影响增强生效。它不是修改所有类的任意代码位置，也不等同于完整的AspectJ编织；项目中的声明式事务可作为有代码依据的典型应用。

## MySQL

### 11 数据库乐观锁与悲观锁如何选择

**Q：** 乐观锁与悲观锁？使用场景？乐观锁如何实现？ [来源 03](https://www.nowcoder.com/discuss/353157644422684672)

**Q：** Mysql 乐观锁 悲观锁 [来源 04](https://www.nowcoder.com/discuss/353156179603955712)

**A：** 悲观锁先取得数据库锁再处理竞争，例如在InnoDB事务中使用SELECT ... FOR UPDATE读取需要修改的记录；锁范围受索引、条件与隔离级别影响，事务应尽量短。乐观锁通常通过版本号条件更新，更新时同时校验旧版本并递增版本，根据影响行数判断冲突，再按业务决定重试或返回失败。低冲突场景可减少等待，高冲突时重试成本可能较高。两者都需要正确事务边界，不能用普通先查后改代替并发控制。

### 12 MySQL的B+树索引为什么快

**Q：** Mysql的B+树结构 [来源 04](https://www.nowcoder.com/discuss/353156179603955712)

**A：** InnoDB常用B+树组织索引，节点按页存储、分支多，树通常较矮，查找只需访问较少层级的页；内部节点主要保存导航信息，叶子节点有序并支持相邻遍历，适合等值与范围查询。聚簇索引的叶子保存行数据，二级索引叶子通常保存主键，取非覆盖列可能需要回表。查询快还依赖选择性、缓存命中和执行计划，不能仅凭建了B+树就认定不会扫描大量记录。

## Redis

### 13 如何保证缓存与数据库的一致性

**Q：** redis缓存与数据库的一致性问题？ [来源 03](https://www.nowcoder.com/discuss/353157644422684672)

**A：** 常见 Cache-Aside 方案以数据库为准：读取先查缓存，未命中再查库并回填；写入先提交数据库事务，再删除缓存，后续读取重建。删除失败需要可靠重试或消息补偿，并以 TTL 限制陈旧时间。并发读写仍可能出现旧值回填，所以它通常提供最终一致性，不能直接保证强一致；更高要求可结合版本校验、串行化更新，或对关键读取直接访问数据库，再根据延迟和业务容忍度选择方案。
