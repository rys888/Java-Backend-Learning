## 模块地图与调用链

采云台：`backend/cai-yun-tai` 中 common 放上下文/常量/工具，pojo 放DTO/实体/VO，server 放Controller/Service/Mapper与XML；sql保存建表迁移，front为静态前端。物理表仍有dish/setmeal等课程遗留名，Java业务使用Goods/Combo；不把遗留注释当成仍实现微信支付、地理配送或实时推送。

研约通：`src/main/java/com/yanyuetong` 按controller、service、mq、mapper、utils、config分层；resources保存Lua、SQL及Mapper，frontend为独立Vue应用。主业务是实验室/设备/预约批次/预约与核验/请求账本/死信治理；不是原课程点评业务。

### C-ORDER · 申领提交与本地事务

**项目**：采云台。

**调用链**：`OrderController.submit → OrderServiceImpl.submitOrder → BudgetServiceImpl.deduct → BudgetMapper.deduct → OrderMapper.insert → OrderDetailMapper.insertBatch → ShoppingCartMapper.deleteByUserId`

**已实现**：申领金额按数据库申领车单价×数量求和；预扣部门当月预算，写主单/明细并清空车，submitOrder 带 @Transactional。申领车首次添加时价格来自物资/组合包数据库记录。

**边界/建议**：提交时读的是申领车快照，不是再次查询所有物资的实时价格。事务仅覆盖同一数据库资源，Redis 序列与防重键不会随事务回滚。不能描述成跨 Redis/MySQL 的原子事务。

### Y-PUBLISH · 消息发送结果分类

**项目**：研约通。

**调用链**：`submit → publishReservationMessage → RabbitTemplate.convertAndSend → CorrelationData.future → request CAS / rollback`

**已实现**：最多等待5秒确认，检查confirm ACK/NACK与return；确定未送达尝试Lua回滚名额；异常/超时等不确定结果标UNKNOWN，不立即回滚。ACK后重试更新PUBLISHED，已被消费者推进终态时不会回退。

### Y-PERSIST · 消费者事务、幂等与数据库兜底

**项目**：研约通。

**调用链**：`ReservationMessageConsumer.onReservationMessage → persistWithLock → ReservationPersistenceServiceImpl.persist → batch条件扣减 + insert → request CONFIRMED → basicAck`

**已实现**：消费者使用用户维度Redisson锁，等待2秒、租期10秒；独立Service的 @Transactional 中判断同ID归属及占用预约，条件扣MySQL剩余名额，再插入预约。成功/业务重复ACK，冲突/异常NACK且不重入原队列。

**边界/建议**：显式10秒lease不能宣称由watchdog无限续期；数据库提交与ACK之间可故障，因此依赖幂等。CONFIRMED更新失败可留下非终态，由对账收口。锁超时进死信而非无限重试。

### Y-ROLLBACK · 取消跃迁与名额补偿

**项目**：研约通。

**调用链**：`ReservationServiceImpl.cancel → ReservationLifecycleServiceImpl.cancel → RESERVED条件UPDATE与MySQL名额回补 → rollback.lua → quota_released`

## 如何选择项目结合

| 题目领域 | 优先项目 | 直接依据 |
| --- | --- | --- |
| SQL条件更新、本地事务、预算 | 采云台 | C-ORDER、C-BUDGET |
| 短窗口防重 vs 业务幂等 | 采云台作边界；研约通作分层比较 | C-IDEMPOTENCE、Y-PERSIST |
| Lua、Redis并发准入 | 研约通 | Y-ADMISSION |
| RabbitMQ、确认/ACK/死信、异步一致性 | 研约通 | Y-PUBLISH、Y-PERSIST、Y-DLQ |
| 缓存空值、互斥重建、解锁 | 研约通；采云台可作轻量对比 | Y-CACHE、C-CACHE |
| JWT、AOP与ThreadLocal | 采云台 | C-AUTH |
| 会话续期、资源归属权限 | 研约通 | Y-AUTH |

没有直接代码关系的HashMap、GC调优、网络协议等问题不硬加项目案例；原理可以解释，不能伪造项目压测、线上QPS、事故或性能收益。

## 已识别的表述纠偏

- 采云台预算返还的金额条件不是订单级并发幂等；C-LIFECYCLE中的风险是静态推断，未复现。
- 研约通缓存逻辑过期是备选；实际queryEquipmentById走互斥锁。
- 研约通实际缓存TTL是正向随机抖动；不是README表格中的±5分钟。
- 研约通当前reconcile不自动重投；自动扫描补偿与管理员DLQ重放应分开描述。
- 消费者10秒显式租期与对账不显式lease的锁调用不同，不混讲watchdog。
- RedisIdWorker的日计数键没有在nextId里设置TTL，不是Snowflake。
- 有confirm、手动ACK和DLQ不等于任意故障都不丢消息，尤其DLQ台账失败存在丢弃路径。

## 版本更新与重新核实

机器索引为同目录 `项目知识索引.json`：保存项目SHA、Git文件对象清单、证据文件SHA256、符号/行号及问答依赖。`scripts/check_project_versions.py` 仅比较远端Git版本、生成变更报告，不生成或认证AI答案，也不自动把新SHA标成已核对。

每次正式采集前应检查版本；业务Java/Lua/SQL/依赖/配置有变动时，至少将该项目全部答案视为待复核，先读直接变更，再检查调用方、失败补偿、DDL和测试。新增未索引文件同样不能忽略。只有实际重新核实后才更新索引SHA、证据行号和项目答案；异常或无访问权限时保留旧索引并标陈旧，不伪造更新成功。

周期复核使用独立Codex云端任务，从2026-10-25起每周日早间约07:00检查（Asia/Shanghai，灵活窗口）；创建/启用状态与实际运行结果另行记录。正式每日采集尚未启用，因此当前不声称每天都已检查。GitHub Actions仍只负责同步，不用它冒充AI重审。
